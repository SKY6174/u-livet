# 2026 출석부 실제 운영 등록 준비표

확인일: 2026-09-21 KST · 대상: 운영계획서 16개 전체

출석부 기능과 Preview·Production DB 반영은 완료됐다. 이 준비표는 계획서와 현재 DB의 차이를 정리한 자료이며 실제 강사 배정·수강 확정·일정 등록 기록이 아니다. 계획서의 정원과 인력명을 실제 등록자·계정으로 전환하지 않는다.

## 실제 등록에 필요한 자료

| 자료 | 필요한 내용 | 처리 방법 |
| --- | --- | --- |
| 최종 시간표 | 과정/기수, 수업명, 한국시간 시작·종료, 휴게 구간, 보강 여부 | 실제 교육 구간별 회차를 등록. 종료−시작 시간이 출결 분모가 되므로 점심·휴게시간은 수업 구간에서 제외 |
| 담당 강사 연결 | 과정/기수와 승인된 강사 계정 식별 정보, 배정 유효기간 | 기존 승인 계정을 확인하고 해당 과정에 배정. 계획서 인명만으로 계정 생성·권한 부여하지 않음 |
| 수강 확정 명단 | 과정/기수, 본인 계정 식별 정보, 수강 확정·취소 여부 | 기존 신청·선발 절차와 대조하여 ACTIVE 등록자만 출석부에 표시. 정원 숫자로 가상 명단 생성하지 않음 |
| 개설 조건 | 최종 교육기간·모집기간·선발방식·비용·신청/수료 정책 | 기존 [과정 개설 준비표](production-course-opening.md)에 따라 확정. 임의 출석률·합격점수를 설정하지 않음 |

계정 식별과 명단 대조에는 내부 자료를 사용하며 실제 개인 명단·이메일·연락처를 저장소에 커밋하지 않는다. 등록 템플릿이나 계획 정원은 실제 수강 확정 근거가 아니다.

## 연결 순서와 확인 기준

1. 실제 개설 기수를 정하고 기존 보관 과정과 중복 여부를 확인한다.
2. 최종 개설 조건으로 과정 초안을 등록하고 기존 신청·수료 정책을 연결한다. 모집기간 미정이면 모집 공개를 보류한다.
3. 승인된 강사를 배정하고 실제 선발 결과에 따라 수강 확정 명단을 연결한다.
4. 담당 강사가 **강사 공간 → 담당 과정 → 출석부 → 수업/보강 일정 추가**에서 확정 시간표를 등록한다. 출석부 생성 시 출결은 미입력 상태여야 한다.
5. 일정·인원·강사 권한을 대조한다. 수업 종료 후 실제 확인 근거로 출결을 기록하고, 수강생의 **나의 학습 → 나의 출석 확인**에서 본인 기록이 일치하는지 확인한다.

현재 실제 입력을 기다리는 자료는 **최종 수업 시간표와 수강 확정 명단 및 담당 강사 계정 연결 정보**다. 운영 DB에 시험 명단·임의 일정·가상 출석을 추가하지 않았다.

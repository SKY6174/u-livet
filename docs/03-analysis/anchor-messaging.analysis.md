# 안내문자 예약·동의 관리 설계 대비 점검

2026-09-19 · anchor-messaging · 범위: 업체 미연결 예약 관리 + 로컬 가상 처리

## 판정

이번 단위의 인수 항목 14/14 충족(100%). 이는 전체 플랫폼이나 실제 SMS 서비스 완성도가 아니다. 계획상 유보한 업체 API·휴대전화 인증 연계·실제 발송·자동 스케줄러·공급자 callback/재처리는 포함하지 않는다.

| 항목 | 구현·검증 근거 |
|---|---|
| 기관/역할 권한 | 현재 COURSE_MANAGER 검사, 타인·타기관 RPC 거부 |
| 승인 문안 | 고정 종류/대상/문안/버전, enabled 외 변경 차단 |
| SMS 목적 정책 | 별도 SMS 정책 지정 테이블, 다른 채널 정책 거부 |
| 인증 연락처 | 비공개 opaque 참조/마스킹, 신규 UUID 버전, 만료·해제 검사 |
| 선택 동의 | 원문 확인, 동의/철회 이력, 학습 조건에서 독립 |
| 관련 기관만 표시 | 가입·신청 동의 또는 본인 설정/연락처 기록 범위 |
| 대상 미리보기 | 네 가지 대상 조건·제외 사유·최대 5명 표본 |
| 고정 대상 예약 | 스냅샷 밖 신규 대상 추가 없음, 변경 연락처 제외 |
| 예약 유효성 | 15분 미리보기·현재 이후 30일 이내, 중복 키 검증 |
| 실제 발송 차단 | DISABLED/TEST만 허용, 기본 BLOCKED_CONFIG, 비용 미확정 |
| 취소·반복 요청 | 취소/예약 멱등, 취소 후 claim 불가 |
| 처리 경쟁 | 기관 잠금, 중복 claim 차단, lease 만료 UNKNOWN |
| 최종 재검사 | 동의/정책/계정/연락처/등록관계/예약자 권한·문안 재검사 |
| 화면·회귀 | 역할별 브라우저 흐름, 390px 가로 넘침 없음, 166개 DB/Auth 검사 |

## 발견·수정

- 예약/처리 함수의 PL/pgSQL 지역 변수와 컬럼 이름 충돌을 명시적 블록 라벨로 수정했다.
- 일반 MARKETING 정책을 SMS 수신동의로 간주하는 여지를 없애기 위해 승인된 SMS 정책 목록을 추가했다.
- 개인 설정의 기관 목록을 본인 관련 범위로 제한했다.
- 정책 만료 후 제외 수를 검증할 때 원래 미동의자도 집계되는 점을 테스트 기대값에 반영했다(동작 수정 아님).

## 브라우저 증거

관리자 로그인 → 기수/홍보 문안 선택 → 미리보기 생성 → 확인 후 예약 → 연결 대기 표시. 수강생이 동의 철회 → 관리자 재조회에서 1명이 CONSENT_WITHDRAWN, 전체 3명 제외로 변경. 관리자가 취소 → 취소 이력. 수강생은 원문 확인 후 다시 선택 동의 가능. 수강생/관리자 화면 모두 390px viewport에서 scrollWidth=390, 오류 오버레이 없음.

최초 개발 서버 전환 직후 브라우저 오류 수집기에 URL 없는 SyntaxError 1건이 남았다. 인라인 스크립트 구문검사, 서버 로그, 새 브라우저 세션에서 홈/로그인/관리자 화면을 다시 확인했고 재현되지 않았다. 최종 새 관리자 세션과 학습자 세션은 오류 목록이 비어 있었다. 앱 원인으로 단정하지 않았다.

## 잔여 운영 범위

실제 발송 업체/발신번호/요금/위탁·보유기간·광고 문안/야간 제한 검토, 인증 모듈의 연락처 등록, 기관 승인 설정 관리 UI, 운영 worker 및 callback/결과 대사·재시도는 후속이다. 현재 TEST 결과는 실제 전달확인이 아니다. 보안검사 통과를 보안인증이나 운영 승인으로 간주하지 않는다.

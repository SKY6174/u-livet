## 점검 중 보완

- 공유 검증은 비활성 상태뿐 아니라 인증 계정 연결 해제도 차단하도록 보완하고 실제 RPC로 검사했다.
- 정의 승인·철회와 발급은 기수 잠금 획득 후 현재 위임을 다시 확인한다.
- 공유 링크는 반환 당시 revision이 현재 화면의 revision과 같을 때만 표시해 다른 탭 변경 후 이전 링크가 남는 것을 막는다.
- PL/pgSQL 매개변수와 열 이름 충돌을 명시적 함수명으로 한정했다. TypeScript의 프로젝트 컴파일 대상에 맞게 Map 순회를 변경했다.

## 재현 결과

전체 reset 후 18개 migration을 재생했고 core 33 → learning 33 → certificates 24 → finance 37 → messaging 39 → annual 37 → badges 34, 합계 **237개**가 통과했다. 새 배지 검사는 수료 확정 가상 자료를 직접 준비해 배지 경계를 검사하며, 실제 학사 계산 흐름은 앞선 learning 검사에서 검증한다. 이것을 단일 브라우저의 전체 과정 운영 검사로 주장하지 않는다.

브라우저는 실제 로컬 Auth로 별도 발급자 승인 → 수강생 배지함 → 원본 다운로드 → 공유 안내 선택·동의 → 익명 검증 → JSON 일치 확인 → 공유 철회 → 기존 코드 조회 차단을 확인했다. URL fragment가 주소에서 제거되고 전체 이름이 공개 화면에 나타나지 않는다. 다운로드 응답의 인증·범위·캐시와 잘못된 JSON 400/1KB 초과 413/미존재 코드 NOT_FOUND도 확인했다. 링크 교체·동시 발급·정정·만료·취소는 DB/Auth 검사로 확인했다.

lint·production build 성공, DB security advisor warn 이상 없음. 근거는 `docs/04-report/features/evidence/badges-*`에 저장했다. 최종 문서 변경 후 `git diff --check`도 확인한다.

## 경계

실제 발급권·보유기간·배지 기준·공유 문안은 승인됐다고 간주하지 않는다. 외부 사업자 선택에 대한 추가 답변이 없어 안내한 홈페이지 내부 발급 구조로 구현했다. 표준 서명·외부 지갑 API·일괄 발급·복합 배지·이미지 업로드는 범위 밖이다. 운영 데이터 이관·대용량 부하·보유기간별 파기·관리자 MFA·백업과 배포 검증은 후속이다.

# anchor-migration-retry 설계 대조

2026-09-19 · 설계: `docs/02-design/features/anchor-migration-retry.design.md`.

이번 한정 범위의 설계 항목 10개 중 10개 확인. 수동 설계 대조 100%이며 플랫폼 전체 완성도·운영 보안 인수율이 아니다. bkit 분석 도구는 템플릿과 절차만 제공했으며 아래 결과는 실제 코드/실행 결과를 대조해 작성했다.

| 항목 | 근거 | 결과 |
|---|---|---|
| 실제 실패 근거 | branch action 로그의 009 / 42710 | 확인 |
| 제한된 SQL 변경 | 009 +6줄, 010 +9줄; 원본과 정확한 DROP 추가만 허용하는 검사 | 통과 |
| 원본 오류 재현 | 009·010 각각 최초 성공 후 재실행 실패 | 통과 |
| 실패 rollback | 단일 transaction 실패 후 schema/행 지문 동일 | 통과 |
| 최초 및 반복 적용 | 001~008 기반 수정본 처음·반복 실행 | 통과 |
| 부분 적용 상태 수렴 | 절반의 정책 누락 + 남은 정책 조건 변경 후 원본 정의로 복원 | 통과 |
| 무관한 정책 보존 | 별도 restrictive 정책 존재/조건 유지 | 통과 |
| 데이터·접근 정의 보존 | public 전체 행 지문 및 정책/역할/함수/뷰/인덱스/컬럼/권한/RLS snapshot | 통과 |
| 로컬 격리 및 정리 | Unix Docker endpoint 고정, 무작위 임시 DB 생성/삭제, 기존 DB reset 없음 | 확인 |
| 운영/인증 후속 문서 | 실제 설정 요약·재시도 절차·결정안·미발송 문의 초안 | 작성 |

검증: `npm run test:migration-retry` 10개 통과, `npm run test:release` 합성 입력 111개 통과, Node 구문 검사 및 `git diff --check` 통과. 앱 UI나 인증 동작 코드는 이번에 변경하지 않았다.

누락된 범위 내 항목 없음. 원격 정의 전체 대조, 전체 migration 실행, 별도 Preview의 native Auth/메일/CAPTCHA/MFA 행동 검증은 후속 운영 인수 범위다. 원격에 정책 이름이 존재한다는 관측만으로 원격 실제 정의 일치 또는 안전성을 주장하지 않는다. 이력만 보정하거나 실패를 숨기지 않는다.

# 운영 환경 수료 판정 검증 기수 점검

> 2026-09-25 | 설계: [anchor-completion-live-test.design.md](../02-design/features/anchor-completion-live-test.design.md)

## 설계 일치율: 100%

1. 운영 DB에 `[검증용]` 조직과 두 기수를 분리 생성했다. 두 기수 모두 `DRAFT`이고 실제 두 과정은 수정되지 않았다.
2. 기수별 합성 수강생 6명, 종료 수업 1회, 출결 5건, 환불 신청서 표시 1건을 저장했다. 연락처·계정·결제·실제 환불은 만들지 않았다.
3. 90% 승인 대기, 85% 미산출, 70% 기준 미달, 50% 철회·환불 신청서, 100% 수료 확정, 출결 누락 사례가 화면에 표시됐다.
4. 운영 관리자 권한은 검증 조직의 관리·수료 승인 역할 두 개로만 추가됐다. 실제 사업단 조직 역할은 그대로다.
5. 로컬 DB에서 생성·중복 방지·정확한 제거 스크립트를 실행했다.
6. 운영 UI에서 기수별 85% 학습자 후보를 산출했고, 별도 작성자가 산출한 90% 학습자를 승인했다. 확정 수료율이 각각 16.7%에서 33.3%로 갱신됐다. 직접 산출한 판정의 자기 승인은 비활성화됐다.
7. 운영 DB 재조회에서 기수별 수강생 6명·판정 5건·승인 2건·환불 신청서 1건을 확인했다. 원 과정의 등록·판정·승인·환불은 모두 0건이다.

검증 데이터는 사용자의 화면 검토를 위해 남겨 둔다. 검토 종료 후 `scripts/cleanup-completion-live-test.sql`을 사용해 격리 조직과 합성 기록을 제거한다.

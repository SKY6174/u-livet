전체 플랫폼의 기능 충족률을 의미하지 않는다. 이번 설계 범위만 대조했으며 백분율 점수를 임의 산정하지 않았다.

## 검증 근거

- 전체 14개 마이그레이션을 전용 로컬 DB에 처음부터 재생 성공.
- 기본 흐름 33개 + 출결·시험·수료 33개 + 증명 발급 24개 = 자동 검사 90개 통과.
- 추가 실제 HTTP 검사 4개: 길이 헤더 없는 1KB 초과 본문 거부, 잘못된 JSON 거부, 유효 토큰 응답/보안 헤더, 비로그인 다운로드 거부.
- ESLint 경고 0, Next 프로덕션 빌드 성공(타입 검사 포함), 로컬 Supabase 보안 점검 문제 0, 운영 의존성 npm audit 취약점 0.
- 증명 승인 브라우저에서 실제 PDF 생성·다운로드 성공. 익명 검증에서 현재 상태와 마스킹 이름 확인. 토큰 fragment 제거, 쿼리 없음, 파일 비교 성공. 브라우저 오류 없음.
- 390px 모바일 화면 가로 넘침 없음. 재시작 후 홈 화면도 의미 있는 콘텐츠·메뉴가 표시되고 오류 오버레이 없음.
- 두 종류 PDF를 Poppler로 렌더링해 한글/줄바꿈/레이아웃을 육안 확인. 텍스트 추출과 macOS Vision QR 디코딩 확인. 경력시간은 예정 120분이 아닌 승인된 실제 30분, 정정 후 45분으로 검증.

자동 검사 로그는 `../04-report/features/evidence/certificates-*.txt`, 화면은 `../04-report/features/assets/certificate-*.png`에 보관한다. PDF 검증 산출물은 저장소 루트 `output/pdf/test-*.pdf`이며 공식 증명이 아니다.

## 발견하고 수정한 사항

1. SQL 제한 분기 문법과 변수 이름 충돌을 수정하고 전체 마이그레이션을 다시 재생했다.
2. NULL 조건으로 직인·생략 근거 검사를 통과할 수 없도록 명시적 coalesce 검사로 보강했다.
3. 생성 도중 위임 만료/권한 철회와 근거 변경을 완료 트랜잭션에서 다시 확인한다. 오래된 worker nonce는 거부한다.
4. 한글 폰트 부분 임베드에서 일부 글자가 보이지 않는 현상을 전체 임베드로 수정하고 두 PDF를 다시 렌더링했다. 글꼴을 Next 파일 추적 대상에도 포함했다.
5. 검증 API가 길이 헤더 없는 큰 본문을 끝까지 읽지 않도록 스트림 바이트 한도를 적용했다.
6. 공통 middleware가 검증·다운로드 API의 no-referrer를 덮어쓰던 문제를 실제 HTTP 검사로 찾아 수정했다.

## 남은 경계

D05 실제 기관 명의·직인 사용 근거·위임·공식 서식은 미확정이다. 운영 DB 반영/배포, 관리자 MFA, 보유·파기 자동화, 전자서명, 외부 기관 연계는 완료 범위에 포함하지 않는다. 현재 고정 v1 레이아웃과 비공개 DB의 최대 2MB 원본 저장을 사용한다. 대량 발급·부하/장애 복구·다중 지역 운영은 추가 검증이 필요하다.

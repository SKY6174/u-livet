# Issue 170: 과정 리스트 관리 메뉴 검증

2026-10-13 · 설계: `docs/02-design/features/issue-170-list-menu.design.md`

## 수정 전 재현

실제 OperationsDashboard를 두 합성 과정으로 렌더링하고 production CSS를 사용했다. 1440px에서 목록 영역 너비는 1214px, 표 너비는 1426px이었다. 관리 링크 9개 모두 일부가 영역 밖에 있거나 완전히 가려졌다. 이슈 첨부 화면의 버튼 잘림을 재현했다.

## 수정 후 검증

| 화면 폭 | 목록 영역 | 관리 열 | 좌우 스크롤 검사 | 링크/문구 클리핑 |
| --- | --- | --- | --- | --- |
| 360px | 318px | 240px | 0↔1082px | 0 / 0 |
| 768px | 702px | 320px | 0↔698px | 0 / 0 |
| 1440px | 1214px | 320px | 0↔186px | 0 / 0 |

각 폭에서 관리 머리글과 셀 너비가 같고 모든 9개 링크가 목록 영역 안에 있었다. 본문 가로 넘침은 없었다. 작은 화면에서만 과정 이름이 관리 셀 안에 표시됐다. 마지막 데스크톱 검사는 scrollLeft=0을 별도로 확인했다.

실제 컴포넌트 SSR 6개 회귀 검사: 카드 HTML이 수정 전과 동일, 카드/리스트 메뉴 목적지 동일, 연결 과정 6개 메뉴, 개설 전 과정 3개 메뉴, 조회 사용자에게는 수강생 화면만 표시, 보고서/원문 여부에 따른 조건부 메뉴 유지. TypeScript·lint·production build·매뉴얼·diff 검사 통과.

## 설계 대조

고정 머리글/셀, 반응형 너비와 전체 버튼, 불투명 배경과 경계선, 모바일 과정 문맥, 기존 권한/링크/카드 보존: 5/5 충족(100%). DB와 조회/권한 코드는 변경하지 않았다.

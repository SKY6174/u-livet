# 네이버 로그인 검수 테스트 설계 대조

확인일: 2026-09-22. 설계: `docs/02-design/features/anchor-naver-login-test.design.md`.

설계 항목 10개 중 10개 구현·확인(100%). 실제 개인 계정 비밀번호 입력·동의 이후 과정은 검증 범위에 포함하지 않는다.

| 설계 항목 | 확인 결과 |
| --- | --- |
| 기존 디자인의 네이버 버튼 활성화 | 운영 수강생 버튼 활성화 및 네이버 U-LIFE 인증 화면 도달 |
| 기존 제공자 비밀값 유지 | Client ID 변경 없음, Secret 갱신 요청 없음 |
| 중첩 응답 변환 | 모의 실제 응답 형식에서 `sub`·`email`만 선택 |
| 인증·오류 검증 | 33개 검사 및 운영 미인증/무효 토큰 401 |
| 토큰·추가 프로필 미노출 | 고정 upstream, 리다이렉트 금지, no-store, 일반화된 오류, 응답 허용 목록 |
| 이메일 확인 | false 유지, 인증 필요 오류를 취소와 구분, 운영 자동 확인 비활성 유지 |
| 기존 회원/가입/QR/역할 흐름 | 기존 회귀 검사 통과, 운영 사업단·교내 네이버 버튼 없음 |
| 새 개인정보 안내 | 운영 `/privacy`·이메일 가입 화면 v5 노출, 동의는 미선택 |
| 이전 문안·동의 보존 | 최신 v4의 연락처 유지, 과거 문안 불변, 동의 7건 지문 일치 |
| 빌드·푸시·운영 확인 | lint·빌드·TypeScript 통과, main 배포 READY 및 `/api/version` 일치 |

Supabase 보호 필드인 `email_verified`는 attribute mapping으로 지정할 수 없어 표준 응답 필드로만 전달한다. 이는 false를 유지하려는 설계 목적과 일치한다.

보안 advisor는 RLS 활성·정책 없음 INFO 75건이며 WARN/ERROR는 없었다. 이번 작업은 기존 정책 테이블의 데이터 추가만 수행했고 DDL·RLS 권한은 변경하지 않았다. 기존 서버 함수 중심 접근 구조의 안내 항목이다. 참고: https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy

검수 제출을 위한 다음 단계는 등록된 네이버 테스터가 직접 인증·제공 동의·필요시 이메일 확인·U-LIFE 가입 완료·QR 입실 확인을 수행하며 캡처하는 것이다. 테스트 데이터와 실제 이용자 동의는 대신 생성하지 않았다.

## 후속 가입 연결 보완 검증

- 실제 이용자의 시도로 초기 설계가 다루지 못한 미확인 연락처 이메일/빈 Auth 이메일 상태를 확인했다. 초기 표의 100%는 당시 인가 화면까지의 범위이며 실제 가입 완료 성공을 뜻하지 않는다.
- 추가 설계 8개 항목(네이버만 이메일 선택 설정, 가입 대기 세션, 이메일 직접 입력·실제 발송 확인, OTP 사용자 일치·세션 보존, DB 우회 차단, 기존 회원 분기, 대상·QR 복귀 보존, v6 문안)을 구현했다.
- 신규 회귀 검사 27건, 기존 어댑터·카카오·로그인 대상·자동 분기 검사가 통과했다. lint/TypeScript/Next.js 빌드 통과.
- DB 합성 계정 트랜잭션에서 이메일 미확인·위조 metadata·동의 누락을 차단하고, 확인 후 가입과 반복 제출의 멱등성 및 역할 미부여를 확인했다. 전부 rollback했다.
- 실제 가입 페이지를 렌더링한 로컬 브라우저 검증에서 이메일 확인 전에는 인증 입력, 확인 후에는 이름·휴대폰·미선택 동의 화면을 확인했다.
- 운영 코드 `a6148713820ab042ea61a9661c5591511145d78a`의 배포 `dpl_911gnkx329bQNACAPrbMYEZiGeXd` READY 및 버전 일치. 새 네이버 인증 요청의 저장된 flow state에서 `email_optional=true`를 확인했다. 원래 ID/Secret 및 전역 이메일 자동 확인 설정은 유지했다.
- 운영 오류 재시도 화면에서 수강생 로그인 버튼이 바로 표시되고 네이버 인증 화면에 연결된다. 운영 개인정보 페이지는 v6다. 실제 개인 계정의 인증번호 확인·최종 개인정보 동의는 이용자가 진행해야 하며 대신 완료 처리하지 않았다.
- 보안 advisor는 이전과 같은 INFO 75건, WARN/ERROR 0건이다.

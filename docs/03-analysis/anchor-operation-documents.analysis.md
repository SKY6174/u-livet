## 검증 증거

### 2026-09-22 과정명·영역 선택 및 PDF 1.7 보완

추가 설계 항목 3개 중 3개 확인(100%). 과정명은 `life_operation_list`가 반환하는 접근 가능 과정으로 제한하고, 다른 과정을 선택하면 같은 종류의 문서로 이동한다. 미저장 변경이 있을 때는 이동을 멈춘다. 영역은 공식 아카데미 목록에서 선택하며 기존 비표준 저장값도 선택 항목에 유지한다. 계획서와 결과보고서는 동일한 `OperationPrintControls`와 PDF 1.7 생성기를 사용하고, 종이 인쇄 버튼을 파일 다운로드와 구별했다.

이번 변경에서 `npm run build`, `npx tsc --noEmit`, `git diff --check`를 통과했다. 설치된 jsPDF 생성 결과를 PDF 검사 도구로 읽어 PDF version 1.7과 A4 용지를 확인했다.

- `node scripts/verify-operation-documents.mjs`: 로컬 실제 Auth/PostgREST 합성 계정으로 권한·예산 변조·충돌·상태 전이·불변 제출본·비정상 이미지·계획 예산 승계 모두 통과. SUBMISSION_IMMUTABLE 로그는 의도한 거부를 검증한 결과.
- `node scripts/verify-role-navigation.mjs`: 19개 통과.
- `node scripts/verify-pdf-17.mjs`: 6개 통과.
- 신규 코드 ESLint, Next 프로덕션 빌드(타입·린트 포함), `git diff --check` 통과.
- 실제 모바일 브라우저에서 강사 본문 수정 → 임시저장 → 새로고침 후 동일 내용 확인. 예산 입력 비활성 확인.
- 실제 관리자 브라우저에서 결과보고서 최종 제출 및 저장본 PDF 다운로드 확인.
- API 익명 요청 401, 외부 Origin 요청 403 확인.
- 운영·검증 Supabase에 두 마이그레이션 적용. 운영 DB security advisor WARN/ERROR 없음.

## 범위와 운영 방식

- 원본의 작성 예시·메모·작성안내 페이지는 완성본에서 제외하고 원본 양식 링크로 제공한다. 내용이 길거나 일정이 많으면 페이지가 늘어난다.
- 임시저장은 명시적인 저장 버튼 방식이다. 저장하지 않은 변경은 화면에 표시하고 창 종료 시 알린다.
- 새로운 책임강사 권한은 담당자가 실제 과정 배정에서 선택한다. 이름만으로 기존 계정을 자동 연결하지 않는다.
- 최종본은 DB 제출 스냅샷이며 이후 원자료가 바뀌어도 유지된다. 외부 기관으로 메일 전송하는 기능은 포함하지 않는다.

## 2026-09-22 결과보고서 예산 선행·책임강사 서명 전환

이번 추가 설계의 확인 가능한 6개 항목(예산 선행, 예산 확정 후 강사 작성, 예산 잠금, 책임강사 본인 서명·제출, 서명 무효화·재개, 서명 포함 출력) 중 6개를 로컬 RPC와 저장본 화면으로 확인했다(100%). 계획서의 기존 검토·담당자 제출 흐름도 회귀 검사했다.

- 합성 관리자·책임강사 계정으로 순서 위반, 예산 변경, 대리 서명·제출, 무서명 제출을 거부하는 것을 확인했다.
- 서명 후 본문 변경은 거부되고, 담당자가 재개하면 현 문서 서명은 지워지며 이전 서명 제출본은 그대로 남는다.
- Next 프로덕션 빌드와 ESLint를 통과했고, 로컬 관리자·강사 페이지가 새 단계 문구를 렌더링하며 서명 제출본 출력에 이미지가 포함되는 것을 확인했다.
- Preview와 운영 Supabase에는 신규 마이그레이션 한 개만 적용했다. 기존 REVIEW 결과보고서만 DRAFT로 되돌려 담당자의 예산 확정을 다시 받으며, SUBMITTED 제출본은 수정하지 않는다.

## 2026-09-24 기관·사업연도·아카데미 목록 분류

추가 설계 7개 항목(기관 필터, 사업연도 필터, 기존 아카데미 유지, 권한 범위의 등록 과정 포함, 앵커 2026년 원문 범위 유지, 선택 범위별 집계, 산학협력단 아카데미 추정 금지)을 구현·대조했다(7/7, 100%). 2026년 기본 선택과 전체 연도 선택을 제공하며 카드·표에 기관과 사업연도를 표시한다.

로컬 DB에서 새 목록 함수 적용과 실제 인증 관리자·강사 RPC 시험을 통과했다. 앵커사업단 2026년 및 산학협력단 2025년 스마트테크 합성 과정을 사용해 반환 분류와 타 기관 미배정 강사 접근 제한을 검증했다. 기존 운영 문서 회귀 시험, ESLint, Next 프로덕션 빌드도 통과했다. 운영 DB의 현재 등록 과정은 앵커사업단 2026년뿐이며 산학협력단 등록 과정은 없다.

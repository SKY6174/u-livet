# DB 연결·응답 최적화 검증

2026-10-08 · db-connectivity-performance · 설계 일치 6/6 (100%)

## 구현 대조

기관·연도 범위의 예산 RPC에 현재 책임강사 이름만 추가했고, 권한 검사와 기존 JSON 키를 유지했다. 관리자 과정 화면에서 전체 운영문서 목록 호출을 제거했으며, 기존 초기 지정 안내도 보존했다. DB 변경을 앱보다 먼저 적용하도록 배포 순서를 정했다.

## 연결·성능 근거

- 운영 및 스테이징 DB 연결 성공. 관측 순간 연결 수는 각각 12/60, 7/60이고 무효 인덱스는 0개다. 미검증 제약 1개는 두 환경 모두 Supabase `realtime.messages`의 관리형 제약이다.
- 운영 사이트 `/api/health`, `/`, `/courses`, `/auth/login` 각 5회 모두 정상. 첫 요청 제외 응답 중앙값은 375/356.5/413.5/248.5ms. 이는 변경 전 공개 경로 기준선이다.
- 운영 누적 `pg_stat_statements`에서 제거 대상 `life_operation_list()`는 256회 평균 400.55ms, 총 102,539.8ms였다. 한 화면에서 이 RPC 1회를 제거했다. 누적 평균은 관리자 화면 자체의 개선 시간을 뜻하지 않는다.
- 운영 2026년 안내 16건 모두 개설 과정에 연결되어 있다. 새 SQL의 `offering_id` 조인은 고유 인덱스를 사용한다.

## 검증

- 로컬 격리 DB에서 MFA 관리자, 타 기관 관리자 fixture를 사용해 새 책임강사 이름 반환, 기존 16개 결과, 타 기관 차단을 확인하고 트랜잭션을 롤백했다. 오래된 로컬 fixture에는 최신 열과 연결 테이블을 트랜잭션 안에서 보강했다.
- DB 응답 10개, 지연 11개, 공개 성능 16개, 예산 비교 14개 통과. 오래된 테스트의 현재 화면 스텁도 갱신했다.
- lint와 Next.js 프로덕션 빌드, `git diff --check` 통과.
- 운영 DB 마이그레이션 dry-run 결과 이번 파일 1개만 적용 대상이다.

로그인 후 관리자 페이지의 실측 전후 지연은 테스트 계정 세션 없이 확보할 수 없어, RPC 제거에 따른 기대 효과와 구분해 보고한다.

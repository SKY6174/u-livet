# 과정 카드 편집·배경 이미지 검증

2026-10-01 · 설계 대비 구현 9/9 항목

- 공개 16개 과정의 카드·리스트에 사업단 역할별 수정 링크를 제공하고, 별도 편집 화면에서 안내 필드를 수정한다.
- 과정별 이미지 주소 입력·파일 업로드·미리보기·제거와 기본 카드 대체 표시를 구현했다.
- 운영 배포 검증에서 최초 권한 범위가 좁다는 점을 발견해 보완했다. DB 저장 함수와 이미지 업로드 정책은 해당 기관의 활성 사업단 역할, 수동 등록된 사업단 구성원, 지정 운영자를 허용한다. 강사 전용·수강생·익명 계정은 제외하며, 입력 형식과 예상 revision을 검사하고 감사 이벤트를 기록한다. 직접 UPDATE 권한은 추가하지 않았다.
- 운영 DB 마이그레이션 후 16개 전부 게시 상태를 유지하며 `anon`은 저장 함수 실행권이 없는 것을 확인했다.
- lint, TypeScript 검사, Next.js 빌드는 통과했다. 로컬 Docker 데몬이 없어서 `test:core`의 로컬 Supabase 검증은 실행되지 않았다.
- 실계정으로 파일 업로드와 저장을 수행하는 최종 사용자 흐름은 배포 후 사업단 계정에서 확인할 항목이다.
- 운영 도메인에서 공개 과정 16개와 수정 권한 없는 방문자의 버튼 비표시를 확인했다.
- 운영 최고 관리자 계정에서 16개 수정 링크와 편집 화면을 확인했고, 파크골프 과정의 동일 값 저장이 성공해 revision이 1에서 2로 증가했다. 공개 내용은 바뀌지 않았다.
- 업로드 정책의 상관 하위 질의에서 `name`이 파일 경로가 아닌 과정명으로 해석되는 문제를 발견했다. `storage.objects.name`으로 명시하고 경로를 정확히 3개 구간으로 제한하는 마이그레이션을 적용했으며, DB 정책 정의가 `objects.name`을 참조하는지 재확인했다.
- PR Preview의 첫 빌드는 Supabase 연동이 이 PR 브랜치에만 넣은 DB 비밀값과 publishable 변수가 검토 전용 환경의 허용 목록을 위반해 차단됐다. 해당 브랜치 범위의 자동 주입 변수만 제거하고 보호 검사를 유지했다.
- 사업단 전체 권한 보완 PR에서도 Supabase Preview가 브랜치 전용 비밀 환경변수를 다시 주입해 검토용 빌드가 차단됐다. 해당 브랜치의 자동 주입 변수만 제거하고 Preview 보호 규칙은 유지했다.

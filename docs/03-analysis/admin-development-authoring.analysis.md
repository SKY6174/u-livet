# 관리자 과정 등록·수정 검증

2026-10-08 · [설계](../02-design/features/admin-development-authoring.design.md)

## 설계와 구현 비교

| 설계 항목 | 구현 및 검증 |
| --- | --- |
| 관리자 신규 개발·개편 초안 작성 | 관리자 화면에 작성 양식을 열고 NEW/REVISION 대상 관계를 서버에서 검증함 |
| 운영 과정의 신규 등록 및 수정 진입 | 관리자 화면과 운영 목록에서 실제 등록 화면 및 과정별 편집 화면으로 연결함 |
| 본인 초안만 관리자 목록에 표시 | 목록 RPC에서 본인 미제출 초안과 제출본만 조회하도록 제한함 |
| 기관별 관리자 작성 권한 | `id_proposer`에서 활성 사용자와 해당 기관 `COURSE_MANAGER` 역할을 확인함 |
| 다른 기관 과정의 운영 목록·예산 분리 | 조회를 가이드 `org_id`로 제한하고 다른 기관 가이드의 예산 저장을 거부함 |
| 등록 버튼 표기 | 주요 등록 진입과 접힌 등록 양식 제목을 `+ 과정 등록`으로 통일함 |
| 불필요한 개발 현황 안내 | 요청된 회색 안내 문단을 삭제함 |

## 확인 결과

- ESLint, TypeScript 검사, Next.js production build 통과.
- 로컬 PostgreSQL에서 신규 migration을 롤백 전용 트랜잭션으로 실행하여 관리자 본인 초안 조회, 타인 초안 비공개, 앵커 16개/산학 0개 기관별 조회, 교차 기관 예산 저장 거부를 확인함.
- 기존 로컬 DB의 migration 기록에 이 브랜치에 없는 버전이 있어 전체 `supabase migration up --local`은 실행하지 않음. 운영 DB dry-run은 신규 migration 하나만 적용 대상으로 확인함.
- 남은 확인: PR 검사, 운영 DB migration 적용, 병합 후 Vercel 배포와 운영 도메인 확인.

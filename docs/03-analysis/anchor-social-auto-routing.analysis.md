# 간편 로그인 자동 분기 검증

2026-09-21 · 기능 요구사항 7/7 확인.

| 요구사항 | 근거 |
|---|---|
| 선택 화면 제거, 미가입자는 즉시 가입 양식 | 실제 서버 컴포넌트 렌더링 및 브라우저 fixture |
| 기존 회원은 원래 목적지로 이동 | 실제 callback/상태 라우터 회귀 검사 |
| 카카오·Google·네이버 모두 동일 경로 | 제공자별 callback 9개 상태 및 DB fixture |
| 연결된 기존 이메일 가입도 완료로 인정 | 가입·접근 함수 모두 EMAIL 허용; 세 제공자 DB 검사 |
| 새로운 계정은 가입 완료 전 identity 없음 | 같은 이름/전화번호의 별도 Auth 계정 DB 검사 |
| 동의·역할·MFA·정지·세션 보호 유지 | 기존 SQL 검사와 신규 EMAIL 경로 회귀 |
| 가입 기록을 덮어쓰지 않음 | 가입 완료 재호출에도 EMAIL 출처/동의 수 유지 |

## 실행 결과
- JS: 자동 분기 79 + 카카오 가입 40 + 로그인 대상 46 = 165개 통과.
- SQL: 기존 가입/로그인 대상 및 세 제공자 자동 분기 총 114개 통과, 최종 ROLLBACK 확인.
- lint, 타입 검사 포함 Next.js production build, git diff 공백 검사 통과.
- 로컬 실제 컴포넌트 fixture에서 선택 화면 없이 이름·휴대폰·미선택 동의가 표시됨을 확인.
- 기존 로컬 DB는 일부 클라우드 인증 마이그레이션이 없어 관련 선행 마이그레이션만 트랜잭션 안에서 적용하고 함께 롤백했다. 기존 테스트의 ‘이메일 회원도 재가입’ 기대값은 새 요구사항에 맞게 수정했다.
- Preview 보안 advisor: 기존 RLS 무정책 INFO 72개(직접 테이블 접근 차단 설계), 경고/오류 없음. [공식 설명](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

## 한계
실제 회원 계정으로 세 제공자의 신규/기존 가입 전체 흐름을 각각 수행한 결과는 아니다. 인증 제공자 연결은 Supabase Auth를 신뢰하며 다른 이메일·다른 Auth 계정을 이름이나 전화번호로 병합하지 않는다. 네이버의 실제 사용 가능 여부는 기존 제공자 활성화·연결 설정을 따른다.

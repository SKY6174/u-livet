# 과정 통합 관리 검증

2026-09-20 · anchor-course-workspace

설계의 7개 요구 묶음(목록 검색·필터, 공통 과정 메뉴, 운영 집계·다음 행동, 6종 보완/출력, 저장 반영, 보관 과정 구분, 기관/MFA 경계)을 구현했다.

- 새 Supabase RPC는 목록을 한 번의 요청으로 조회하고 파일 본문·계좌·개인별 명단을 반환하지 않는다.
- 로컬 합성 DB 검증 7개 묶음 통과: 보고서/정산/강의실적 집계, 익명·AAL1·강사·학습자·타기관 경계, 미래/휴강 제외, 결석 0분과 미입력 구분, 변경된 수료 근거와 무효 정책 제외, 수정/첨부 변경 반영, 보관 원본과 개인별 기록 구분.
- 기존 보고서 저장/출결 담당/승인/파일/충돌 검사, workspace 조회 8건, 개설 준비 9건, 등록 사전 채움 7건 회귀 통과. 사전 채움 테스트는 새 집계 데이터 경로와 접기 영역에 맞게 갱신했다.
- 전체 Next.js build, 타입 및 lint 통과. React 검토에서 SSR 데이터 조회와 작은 검색 클라이언트를 분리하고, 상태 필터·현재 메뉴·입력 라벨·빈 상태를 확인했다.
- 브라우저에서 검색 → 과정 개요 → 보고서 → 강사료 보완 항목 자동 펼침을 확인했다. 390px에서 가로 넘침이 없다.
- 모바일의 저장 버튼이 공통 고정 헤더에 가리는 문제를 수정하고 재빌드했다. 실제 브라우저 수정·저장 시 revision 3→4 및 저장 완료 표시를 확인했다. 출력에 변경한 담당 교수 값이 반영된다.
- `20260919150459_anchor_course_workspace.sql` 한 개만 두 원격 dry-run에 표시됐고 Preview→운영 순으로 적용했다. 신규 public 함수는 invoker, private 함수만 definer이고 빈 search_path를 사용한다. anon/service_role 실행은 차단했다.
- 로컬·Preview·운영 보안 Advisor WARN/ERROR 없음. 운영의 기존 보관 과정/보고서/원본 PDF 각 3건을 유지했다. 실제 계정 대신 합성 로컬 계정으로 브라우저 검증했다.

준비 상태는 행정적 제출 승인으로 취급하지 않는다. 지급 대상 없음은 자동 완료하지 않으며, 자료 미등록을 그대로 보여준다. 이후 단계는 Git 통합 및 운영 배포 확인이다.

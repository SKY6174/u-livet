# 가입 안내·동의 화면 설계 대조

2026-09-19 · [설계](../02-design/features/anchor-consent-readability.design.md)

## 구현 항목

| 항목 | 확인 |
|---|---|
| 승인 문안 미준비 시 입력 없음 | early return으로 form/input을 렌더링하지 않음 |
| 인증 메일 미준비 시 입력 없음 | 같은 준비 안내로 전환, 해당 이유 표시 |
| 검토용 모드 가입 입력 없음 | 기존 REVIEW_MESSAGE 표시 |
| 다음 행동 제공 | 공개 과정 및 기존 계정 로그인 링크 |
| 승인 문안 가독성 | section 기본 노출, 제목 18px·본문 16px·줄간격 28px |
| 자발적 동의 선택 | 체크박스 미선택, required 및 기존 policy ID 유지 |
| 기존 로그인·서버 보호 유지 | 로그인 렌더링 확인, 서버·Auth·DB 설정 변경 없음 |

기능 설계 7개 중 7개 대응(100%). 공개 가입이나 기관 문안 승인 완료를 뜻하지 않는다.

## 검증

컴포넌트를 TS에서 메모리 변환하고 주변 의존성을 대체해 다섯 상태의 HTML을 확인했다. 정책 없음, 정책 있음, 메일 미준비, 검토용 모드, 기존 로그인 모두 통과했다. 합성 문안의 script 문자열이 실행 가능한 HTML로 삽입되지 않고 escape되며, 필수 동의가 미리 선택되지 않음을 확인했다. 이 검사는 실제 가입이나 메일 발송 검사가 아니다.

변경 파일 ESLint와 정리된 별도 디렉터리의 Next.js production build·타입 검사를 통과했다. 저위험 표시 변경이므로 구현을 반복하는 영구 테스트는 추가하지 않았다.

배포 후 실제 미준비 화면·로그인·상태·동일 버전은 `ops/evidence/signup-opening/consent-readability-release.json`에 별도로 기록한다. 실제 기관 문안이 등록되기 전 승인 문안 화면의 사용자 인수 검증은 합성 렌더링 확인 범위다.

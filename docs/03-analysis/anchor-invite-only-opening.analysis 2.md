# 초대 우선 계정 개방 검증

2026-09-19 · 대상 구현 e08b1db · 설계: `docs/02-design/features/anchor-invite-only-opening.design.md`

## 설계 대조

- 공개 가입은 server-only `AUTH_SIGNUP_ENABLED`가 정확히 `true`일 때만 허용한다. 미설정·빈 값·대소문자·공백·숫자 값은 닫힌다.
- 가입 액션은 입력 검사나 외부 호출 전에 서버 설정으로 거부한다. 클라이언트가 같은 이름의 필드를 보내도 개방되지 않는다.
- 승인 문안이 존재해도 닫힌 가입 화면에는 입력 폼이 없다. 개방 시에는 기존 문안·동의·메일 준비 검사가 유지된다.
- 로그인·복구·초대 수락은 공개 가입 설정에 의존하지 않는다. 새로운 초대 발송 API나 역할 자동 승격을 추가하지 않았다.
- 환경 예제와 운영 절차에 기본 닫힘, native Auth와 앱 설정의 개방·긴급 중단 순서를 기록했다.
- 운영/Preview 공통 Vercel 환경에 false를 저장했다. Supabase native 가입 차단도 유지한다.
- 사용자 확인 사항을 반영한 비공개 문안은 버전과 SHA-256으로 식별한다. 본인 동의·최종 승인·실제 메일 발송을 수행한 것으로 기록하지 않았다.

구현 범위에서 설계와의 미해결 차이는 발견되지 않았다. 계정 생성과 실제 초대는 기술 검증의 완료와 구분한다.

## 실행 증거

- `node scripts/verify-signup-gate.mjs`: 13개 통과. 닫힘 시 외부 호출 0회, 임의 역할 입력 무시, 기존 필수 조건을 확인했다.
- 실제 AuthForm을 사용하는 격리 렌더 검사 3개 통과: 승인 문안 + 닫힘, 개방 + 문안, 닫힌 가입과 로그인 독립성.
- 변경 파일 ESLint 및 깨끗한 추적 파일 복사본의 Next.js 15.5.25 운영 빌드·타입 검사 통과.
- 해당 운영 빌드를 로컬에서 실행해 가입 GET과 실제 Next Server Action POST를 검사했다. 폼 없음, 조작된 개방 필드로 요청해도 서버 거부를 확인했다. 원격 자격증명과 실제 수신자는 사용하지 않았다.
- Preview e08b1db 배포 READY. `/api/version`의 커밋 일치, `/api/health` healthy, 가입 준비 안내와 폼 부재, 로그인 폼과 초대 수락 경로 응답을 확인했다.

최종 양 환경 배포의 커밋·상태·HTTP 결과와 DB의 읽기 전용 확인은 Git에서 제외한 `ops/evidence/signup-opening/invite-only-release.json`에 보관한다. 배포 완료 여부는 그 기록으로 판정한다.

## 한계

실제 사용자 메일 전달·비밀번호 설정·인증 앱 연결·SYSTEM_ADMIN 부여는 아직 수행하지 않았다. 최종 문안 승인과 본인 동의 및 초대 발송 요청 이후에 진행한다. 공급자 공개 문서 확인은 기관의 법적 적합성 검토를 대신하지 않는다.

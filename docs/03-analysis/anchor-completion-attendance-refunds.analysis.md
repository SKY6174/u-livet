# 과정별 출석 수료기준·수료율·중도 환불 표시 검증

> 2026-09-25 | [설계](../02-design/features/anchor-completion-attendance-refunds.design.md)

## 설계 일치율: 100% (8/8)

| 설계 항목 | 구현 및 확인 |
| --- | --- |
| 운영계획서 과정별 80~100% 필드 | 필드·기본값·입력 범위·안내·PDF 미리보기 구현 |
| 기존 문서 호환 | 기존 본문 DB 이관, 클라이언트 정규화, 과거 제출 스냅샷 80% 대체 |
| 사업단 최종 제출값 적용 | 최신 제출 스냅샷을 수료 판정 기준에 반영 |
| 새 계획서 제출 시 기존 판정 무효화 | 제출 트리거가 academic_revision 증가 |
| 승인 정책·과제·시험 유지 | 기존 정책 검증·항목별 판단을 보존하고 출석률 하한 추가 |
| 출석부 자동 수료율 | 종료·기록 완료 회차의 출석률, 출석 충족 인원/전체 등록자 표시 |
| 확정 수료율 | 최신 승인·활성 등록 인원/전체 등록자 표시 |
| 중도 환불자 별도 표시 | 금융 환불과 신청서 상태를 별도 배지·집계로 표시 |

## 검증 결과

- `npm run lint`, `npx tsc --noEmit`, `npm run build`, `npm run test:operation-prefill`, `git diff --check` 통과.
- 새 migration을 로컬 DB 트랜잭션에서 실행 후 롤백. 기존 운영 문서 54건의 유효성, 79% 거부·80% 허용, 전 과정 80% 하한 확인.
- 로컬 등록 데이터로 수료 보드와 판정 RPC를 트랜잭션에서 실행하고 롤백. READY 판정의 출석률이 적용 기준보다 낮지 않음을 확인.
- 기존 계획서 제출본을 90% 기준으로 재제출하는 트랜잭션 검증에서 기준 반영 및 academic_revision 증가 확인 후 롤백.

## 남은 운영 조건

- 배포 DB migration 적용 및 실제 담당자 계정으로 운영계획서 저장·최종 제출, 수료 화면 확인은 배포 단계에서 진행한다.

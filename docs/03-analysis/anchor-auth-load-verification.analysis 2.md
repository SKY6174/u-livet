## 발견 및 수정

초기 학습자 `/admin` 응답은 404였지만 본문에 과정 등록 폼 문구가 포함됐다. 레이아웃 외에 페이지 진입부에도 역할 검사를 추가했다. 수정 후 `/admin`, `/instructor` 모두 404이며 업무 화면 문구가 없다. 시험에서 실제 타인의 업무 데이터 접근을 확인한 것은 아니다.

인증 화면은 전체 life_catalog를 읽은 뒤 코드에서 자기 과정을 찾고 있었다. 로컬 pg_stat_statements에서 해당 전체 조회 20회 평균 4,246ms를 관찰했다. 화면에 필요한 과정 범위와 7개 필드로 제한해 읽고, 신청/배정이 없을 때는 과정 조회를 생략했다. 신청/배정 목록 뒤의 과정 읽기는 종속 관계이므로 순차 실행한다. 운영자의 과정/사업연도 읽기는 병렬을 유지한다.

## 비교 측정

같은 로컬 DB와 Node 26.8.1, Next 15.5.25 프로덕션 빌드에서 순차 비교했다. 기준은 18e43f3 작업 트리에 역할 검사만 추가한 상태이며, 개선본은 이번 조회 범위 수정까지 포함한다. 각 조합 1회 예열 후 24회 측정했다. 이전/이후의 216개 역할별 요청과 각각 24개 사용자 혼합 요청에서 오류는 모두 0건이다.

단위 ms. p50은 중앙값, p95는 24개 표본의 nearest-rank 값이다.

| 역할 | 동시 요청 | 기존 p50 | 개선 p50 | 개선 p95 | p50 감소 |
|---|---:|---:|---:|---:|---:|
| 학습자 | 1 | 4,129 | 365 | 455 | 91.2% |
| 학습자 | 4 | 4,468 | 441 | 477 | 90.1% |
| 학습자 | 8 | 7,375 | 566 | 632 | 92.3% |
| 강사 | 1 | 5,320 | 1,609 | 1,805 | 69.8% |
| 강사 | 4 | 5,727 | 1,680 | 1,707 | 70.7% |
| 강사 | 8 | 8,185 | 2,443 | 2,500 | 70.2% |
| 운영자 | 1 | 781 | 244 | 270 | 68.8% |
| 운영자 | 4 | 878 | 276 | 297 | 68.6% |
| 운영자 | 8 | 1,210 | 379 | 444 | 68.7% |

개선본 native password login 중앙값은 학습자 90ms, 강사 82ms, 운영자 85ms(각 3회). 실제 Server Action은 각각 481/297/220ms(각 1회, 반환된 쿠키의 사용자 확인 포함). 시험 계정 세 명 모두 기존 MFA가 있어 보안 화면으로 이동했다. MFA 값에는 시험 도구 초기화가 포함되므로 사용자 MFA 체감 시간으로 해석하지 않는다.

## 검증과 한계

- `npm run test:db-performance`: 13개 통과.
- `npm run test:auth-load`: 개선본 전체 통과, 로그인 세션/임시 빌드 정리 확인.
- lint, TypeScript 검사, 독립된 Next 프로덕션 빌드 통과.
- agent-browser로 로컬 로그인 화면의 입력·버튼·화면 렌더링 확인.
- 원본 집계: ignored `ops/evidence/auth-load-baseline.json`, `ops/evidence/auth-load-result.json`.

운영 DB는 점검 시 과정·신청·수강 0건이었다. 로컬에서는 학습자에게 보이는 과정 64개, DB 전체 신청 157개·강사 배정 21개를 확인했다. 사용자별 관련 과정 수는 다르다. 동시 요청 8개는 8명의 독립 사용자가 아니다. 브라우저 리소스 로딩·렌더링 시간을 제외한 로컬 HTTP 측정이며, 장시간 부하·운영 SLA·최대 수용량을 판정하지 않는다. 강사 화면에는 1.61초(단일 요청)의 지연이 남아 있으므로 실제 운영 데이터가 준비되면 실행계획과 관련 RLS 비용을 추가 측정한다.

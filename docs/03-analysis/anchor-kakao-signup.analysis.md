# 카카오 가입 설계 대비 점검

2026-09-19 · anchor-kakao-signup

| 설계 항목 | 구현·검증 |
|---|---|
| 친절한 카카오 버튼·가입 안내 | 로그인/회원가입 화면, 390px/데스크톱 확인 |
| PKCE callback·안전한 복귀 | SSR code 교환, 고정 origin, 외부/인증 순환 URL 거부 |
| 미완료 사용자의 학습·업무 접근 거부 | Auth만 생성, DB identity 미발급, 자기 계정 완료 RPC |
| 이름·번호·동의 필수 | UI/server/DB 검증, 현재 설정 문안 강제 |
| 전화번호 미인증 | private 저장, null 제약, 외부 인증 연결 없음 |
| 수강생 권한만 | metadata 권한 무시, role assignment 없음 |
| 기존 업무 계정 보호 | 이메일/password/TOTP 유지, 강사 포함 업무 OAuth 거부 |
| 이메일 자동 연결 | 같은 person 보존, 카카오 정보/동의 확인 전 차단 |
| 동의 증빙 | 기존 문안 보존, 사용자 승인 v2 별도 등록 |
| 회귀 | 앱 37건 + 가입 13건 + MFA 23건 + 비밀번호/설정 28건, DB 34건 통과 |
| Supabase 배포 | Preview DB 합성 트랜잭션 모두 통과·ROLLBACK, 양 환경 마이그레이션과 문안 적용 |
| 공개 회원가입 개방 | 양 환경 READY·alias·API revision 확인, native disable_signup=false·휴대폰 provider=false 확인 |

실제 개인 카카오 계정의 로그인·동의·가입 전체 왕복은 사용자 인증이 필요하므로 자동으로 대신하지 않는다. 브라우저로 인증 시작과 서버/DB의 가입 완료 경계를 각각 검증했다. 사용자 동의 없이 실제 회원이나 인증 완료 상태를 만들지 않았다.

추가 본인확인 서비스, 네이버/Google provider와 폐쇄 자동 정리 기능은 이번 승인 범위 밖이다.

운영·스테이징에서 카카오 계정 로그인 화면까지 확인했다. 스테이징의 KOE004는 사용자가 해당 앱의 로그인 설정을 ON으로 변경해 해소되었다. 불필요한 프로필 사진·닉네임 scope는 요청하지 않고 account_email만 요청한다. 설계의 12개 구현 항목 중 12개를 반영했으며, 개인 계정의 동의·가입 완료 왕복은 별도 사용자 확인 범위다.

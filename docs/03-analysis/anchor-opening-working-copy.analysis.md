# 개설 준비 임시저장 설계 대비 검증

2026-09-21 · anchor-opening-working-copy

| 설계 항목 | 구현·검증 결과 |
| --- | --- |
| 16개 계획서의 미정 입력 보관 | 기존 6개 기본값 + 저장본 13개 문자열. 날짜·선택값 빈 값 저장/복원 확인 |
| 개인·조직·계획서 격리 | 세션 person_id와 COURSE_MANAGER 검사, 직접 테이블 접근 전면 차단. 로컬 실제 JWT로 다른 작성자·강사·학생·익명·다른 조직·권한 회수 검증 |
| 입력 검증 | 앱/DB 양쪽 길이·정원·UUID·실재 날짜·선택값 검사. 빈 문자열 허용, 실제 등록은 기존 필수값 유지 |
| 동시 편집 | 작성자 행 잠금 + expected_revision. 동시 두 저장 중 하나만 성공, stale 갱신 차단 |
| 추가 인증 | 기존 최근 MFA 쓰기 트리거 적용. 로컬 합성 계정의 MFA 시각을 만료시켜 저장 실패와 기존 버전 유지 확인 |
| 입력 보존 | 수동 dispatch로 임시저장 성공/실패 후 입력 유지. 실제 등록 성공은 버튼 잠금. 폼 key에 revision을 포함하지 않아 서버 재검증으로 성공 상태가 재설정되지 않도록 함 |
| 읽기 실패 | 로드 실패를 빈 저장본으로 취급하지 않고 편집 양식을 숨김 |
| DB 왕복 | 선택한 계획서에 한해 단일 조회 RPC를 기존 조회와 병렬 실행. 저장은 단일 원자 RPC. 공유 캐시 없음 |
| 운영 데이터 보존 | Preview/Production에 빈 임시저장 테이블과 RPC만 추가. 기존 3개 보관 기수와 실제 모집·수료·보고 자료 불변 |

검증: 애플리케이션 경계 8, 로컬 실제 DB 7, 계획서 불러오기 회귀 7, 역할별 메뉴 18, 출석 준비 12 = 총 52개 통과. Next.js production build 통과.

브라우저: 실제 폼 컴포넌트 + 로컬 모의 서버 액션으로 미정 임시저장, 새로고침 복원, 연결 실패 후 편집 보존, 재시도, 실제 등록 필수값/완료 잠금, P01/P02 분리 확인. 390px 모바일에서 가로 넘침 없음. 브라우저 저장은 모의 저장소이며 실제 DB 보존·권한은 별도 로컬 JWT 검증으로 확인했다. 운영 계정으로 테스트용 자료를 작성하지 않았다.

설계 대비 미해결 누락 없음. 실제 일정·강사 배정·수강생 등록은 확정 자료 수령 후 진행하는 별도 운영 작업이다.

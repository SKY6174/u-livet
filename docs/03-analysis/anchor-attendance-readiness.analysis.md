# 관리자 출석부 준비 상태 검증

2026-09-21 · anchor-attendance-readiness

## 설계 대조

| 설계 항목 | 확인 결과 |
| --- | --- |
| 기존 집계 재사용 | 관리 개요의 `getManagedCourse` 1회 호출 그대로 사용. 새 DB 조회·개인정보·권한·migration 없음 |
| 준비 상태 | 배정 강사·ACTIVE 수강생·정상 수업 일정의 8가지 유무 조합 검사 통과 |
| 원본 집계 분리 | 원본 모집 15명·7회가 있어도 실제 전산 0명·0회면 등록 필요 표시 |
| 다음 작업 | 초안/보관/신청 우선순위 유지. 강사·명단·일정 누락을 결과보고서보다 먼저 안내 |
| 수업·수료 구분 | 종료 회차 미입력 우선. 남은 정상 회차가 있으면 기간이 지났어도 수료 검토로 바로 안내하지 않음 |
| 담당 업무 연결 | 관리자 링크는 관리 설정·신청 앵커만 사용. 일정은 강사 입력 업무로 설명하며 권한 없는 강사 경로로 연결하지 않음 |
| 보관 과정 | 원본 첨부 확인 안내. 등록을 요구하지 않으며 실제 전산 출결이 있다면 기존 집계/출력 유지 |
| 실패 상태 | workspace 조회 실패 시 오류 화면 유지. 조회 실패를 0건으로 바꾸지 않음 |
| 교육시간 | 강사 일정 양식에 점심·휴게시간 제외 및 교육 구간별 등록 안내 추가. 계산·저장 규칙 유지 |

미충족 필수 설계 항목 없음. 실제 시간표·계정 연결·명단 확정은 별도 운영 입력이며 이번 UI 보완으로 생성하지 않았다.

## 실행 검증

- `node scripts/verify-attendance-readiness.mjs`: 12개 통과. 순수 상태 계산, 우선순위, 실제 컴포넌트 렌더링, 기존 스냅샷 호출 수, 오류 화면 검증.
- `node scripts/verify-attendance-ui.mjs`: 9개 통과.
- `node scripts/verify-role-navigation.mjs`: 18개 통과.
- `node scripts/verify-workspace-queries.mjs`: 8개 통과.
- 총 47개 통과. `npm run build`의 타입/lint/빌드 및 `git diff --check` 통과.
- 실제 관리 개요·헤더·준비 카드·보고서 상태 컴포넌트를 합성 데이터로 브라우저에 렌더링해 준비 전, 일정만 미등록, 보관 과정을 확인했다. 웹 배치와 390px 모바일(문서폭/스크롤폭 모두 390px), 앵커 이동, 등록 필요 표시, 원본 첨부 링크를 확인했다.
- 브라우저 검증은 합성 데이터이며 실사용자 인증·배정 변경·출석 입력은 수행하지 않았다. 운영 자료를 바꾸지 않아 DB 쓰기 회귀나 대량 성능 측정을 재실행하지 않았다.

## 점검 중 수정

- 초기 SQL 권한 범위 선택의 LIKE 밑줄이 와일드카드로 작동해 기존 identity 함수까지 포함되는 것을 실제 인증 검사에서 발견했다. 정확한 `id_` 문자열 접두사 비교로 수정했다. 전체 DB를 다시 구성한 뒤 기존 인증을 포함한270개 검사를 통과했다.
- 심사자가 과거 제출 당시 정책 원문을 확인할 수 있도록 현재 유효 목록과 별도로 버전별 문안을 조회한다. 과정 공개 시 임의의 다른 수료 정책으로 바꾸지 못하는 검사도 추가했다.
- 저장 성공 후 폼이 새 revision으로 교체되어 알림이 사라지는 동작을 확인했다. 현재 저장된 변경번호가 지속 표시되도록 보완하고 브라우저에서 변경번호 증가를 확인했다.
- 후속 개편 카드의 root 구분을 ‘최초 제안’으로 명시하여 승인 버전의 개발/개편 집계와 혼동하지 않게 했다.

## 검증 증거

새33개 + 기존237개 = **270개 통과**. core33, learning33, certificates24, finance37, messaging39, annual37, badges34, instructor-development33. 원격 대신 전용 로컬 `uc-life-core`를 확인하고 가상 계정·기관·정책만 사용했다. 새 스크립트는 반복 시 새로운 검증 기관을 만들며 이전 자료를 임의 삭제하지 않는다.

전체19개 migration 재생 성공. 로컬 DB security advisor warn 이상 없음. lint와 production build 통과. 브라우저 후 UI 문구·저장 표시 변경에 대해 lint/build를 다시 확인했다. 증거는 `docs/04-report/features/evidence/instructor-*`, `development-*`에 저장했다.

브라우저에서는 준비된 초안의 실제 편집·저장 → 이력 제출 → 다른 담당자 승인 → 본인 공개 동의 → 공개 과정의 최소 소개 → 철회 후 소개 숨김, 과정 초안 편집·저장 → 제출 → 별도 승인 → 기수 초안 → 승인 정책으로 모집 공개까지 검증했다. 새 초안 생성·보완/재신청·반려·동시 승인·정정 버전은 DB/Auth 검사로 확인했으며 모두 브라우저로 수행했다고 주장하지 않는다. 비로그인 이력/심사/개발 상세 URL은307 로그인 이동, 응답에 비공개 증빙 없음.

모바일390px 이력 상세·공개 소개·과정 편집의 문서 폭이390px와 일치했다. 최종 역할별 세 브라우저에 페이지 오류 없음. 초기 브라우저 세션에서 출처 URL 없는 SyntaxError가 기록되어 새 세션으로 다시 확인했으며 이후 재현되지 않았다. 해당 원인을 애플리케이션 오류로 확정하지 않는다. 최종 dev 재시작 직후 스타일 미적용도 새 탐색 후 정상 표시·콘솔 무오류로 재확인했다(`instructor-final-home.png`).

## 이번 범위 밖

실제 심사 기준 등록·원격 적용·배포는 하지 않았다. 증빙파일 보관/검사, 외부 자격기관 진위조회, 위촉·전자계약·지급·세무, 기관별 이력 승인 정지 화면, 위원회 다단계 심의, 대규모 목록/부하·전체 검색, 보유기간별 파기는 후속이다. 이력 승인과 국가 자격 진위확인·앵커사업단 강의실적 증명을 혼동하지 않도록 표시했다. 기존 환불/감면 미확정과 운영 MFA·백업 준비 조건도 유지한다.

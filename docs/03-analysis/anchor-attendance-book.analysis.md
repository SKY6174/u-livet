| 요구사항 | 구현·검증 결과 |
| --- | --- |
| 강사 출석부 생성 | ACTIVE 수강 명단과 회차로 자동 구성. 수업/보강 등록, 전체 표, 회차별 선택 기록, A4 가로 인쇄 화면 제공. 열람·생성으로 출석 인정하지 않음. |

미충족 필수 요구사항 없음. 브라우저 검증 중 발견한 저장 실패 후 네이티브 폼 초기화와 fieldset 첫 legend의 체크박스 비활성화 예외를 수정했다. 별도 기관 수료 판정 기준은 변경하지 않았다.

## 자동 검증

- `node scripts/verify-attendance-db.mjs`: 로컬 실제 Supabase JWT/DB 9항목. 권한, 본인 조회, 원자성, 입력 경계, revision 경합, 감사 이력, 철회, 보강, 대량 조회 및 성능 비교.
- `node scripts/verify-attendance-ui.mjs`: 9항목. 집계, 출력 분할, 데이터 로더, 실패 구분, 서버 액션 입력/오류, 초안 선택, 기존 평가 조회.
- 역할 메뉴 18, MFA 메뉴 44, DB 성능 16, workspace 조회 8, 실제 로컬 학습/평가 33항목. 합계 137항목 통과.
- `npm run build`: 빌드·타입·lint 통과. `git diff --check` 통과.
- 실제 브라우저에서 합성 데이터와 실제 UI 컴포넌트로 실패 시 선택·입력 유지, 재시도 성공/표 갱신, 예정 회차 저장 금지, 모바일 개인 화면과 인쇄 배치를 확인했다. 호스팅 실계정으로 출석을 입력한 검증은 아니다.

## 측정 조건과 결과

로컬 합성 과정 40명·39회차·출결 1,402건. 동일 담당 강사 JWT로 이전 방식과 신규 방식 각 9회 교차 측정, 첫 요청 제외 8회 중앙값/p95. 이전 방식은 동일한 전체 자료를 얻도록 1,000건 제한을 페이지 처리했다. 연결·인증을 포함한 API 응답시간이며 화면 전체 로딩시간이 아니다.

| 항목 | 이전 조회 | 신규 출석부 RPC |
| --- | ---: | ---: |
| API 요청 | 6회 | 1회 |
| 첫 요청 | 3,583ms | 22ms |
| 반복 중앙값 | 3,591.5ms | 22.5ms |
| p95 | 3,633ms | 26ms |
| JSON 전송량 | 511,812B | 321,840B |

전송량 약 37.1% 감소. 역할 검사를 한 번 수행하는 범위 제한 RPC, 필요한 필드만 반환하는 JSON 집계, 화면의 Map 인덱스로 반복 검색을 줄였다. 사용자 간 공유 캐시는 사용하지 않는다. 이 결과를 실운영 속도 개선율로 해석하지 않는다.

배포 전 Production 읽기 점검: `/api/health` 9회 모두 200, 첫 1,106ms·반복 중앙값 179ms·p95 389ms. `/courses` 9회 모두 200, 첫 512ms·반복 중앙값 144ms·p95 363ms. 공개 과정 목록은 이번 출석부 최적화의 비교 대상이 아니다.

## 호스팅 DB 반영

- Preview → Production 순서로 `20260920171500_anchor_attendance_book.sql` 적용과 migration history 기록을 같은 트랜잭션으로 완료.
- 양쪽 5개 함수의 고정 search_path, private definer/public invoker, authenticated 실행 권한 확인. anon/service_role 실행 권한 없음.
- 양쪽 공개 RPC 3개씩 익명 HTTP 요청: 401 / PostgreSQL 42501로 차단 확인.
- 반영 전후 양쪽 과정 3개, 수업 0, 출결 0, ACTIVE 등록 0 유지. 실제 사용자 권한과 교육 데이터는 변경하지 않음.
- Preview 첫 적용 요청은 migration history를 SQL 문자열로 포장하는 과정에서 구문 오류로 전체 거부되었다. 함수와 history가 생성되지 않았음을 확인하고 포장 로직을 수정해 성공했다. migration 원본 SQL은 변경하지 않았다.

운영 DB에 수업·등록자가 없는 관계로 실제 수업 규모의 운영 지연과 실계정 화면 확인은 개강 데이터 등록 후 확인할 수 있다. 로컬 시험 결과와 운영 연결 확인을 구분해 기록한다.

# 수강생 학습 허브 설계 대비 검증

2026-09-21 · anchor-student-learning · 설계 항목 14/14 구현

## 일치 항목
1. `${name}님의 학습` 제목과 네이비·민트 대시보드.
2. 실제 신청·현재 수업·공식 수료·참여할 조사 요약. 조회 실패는 `—`/안내.
3. 강사·장소·기간·다음 회차 시간 및 강의실 진입.
4. 회차별 학습내용과 공식 출석, 공개 학습자료와 읽음 상태.
5. 종료 회차만 출석률 계산, 미입력/결석/휴강/미래 상태 구분.
6. 승인된 이수 정책 원문과 출석·과제·시험 기준.
7. 기존 수강신청·취소·납부·환불 동작 연결.
8. 수료 기록·증명서·디지털배지 연결, 활성 등록 과정 다시 보기.
9. 만족도 조사 할 일과 기존 응답 화면 연결.
10. 본인 장학금의 금액·분류·지급일만 투영, 계좌/타인/보고서 원문 제외.
11. 같은 분야 우선 추천과 신청한 과정 제외, 모집 여부는 상세로 연결.
12. 희망 과목·학습 목적·시간 제출, 영구 저장·조회·중복/한도 검증.
13. 사업단 기관 범위의 제안 검토·답변과 수강생 결과 조회.
14. 역할별 계정 화면 유지, 모바일 1열·키보드 기본 요소·연락처/보안 연결.

## 검사 결과
- `node scripts/verify-student-learning.mjs`: 5개 시나리오 통과 (출석, 추천, 일정, 서버 액션, 화면의 빈/오류/수강 상태).
- `node scripts/verify-student-learning-db.mjs`: 6개 시나리오 통과 (본인 투영, 익명/보고서 차단, 제안의 기관/개인 격리, 쓰기 차단/검토 권한, 입력/한도/중복, 수강 취소 접근 제한).
- `npm run lint`, TypeScript, `node scripts/dev-local.mjs --build`: 통과.
- 로컬 Supabase security advisors: 문제 없음.
- agent-browser: 실제 로컬 인증 세션의 1440px 및 390px 화면, 오류 오버레이/가로 넘침 없음. 과정 상세 펼치기에서 회차/80% 출석기준/과제60점 확인. 빈 계정 제안 폼 제출 → 입력 초기화 → 1건 내역 → 새로고침 유지 확인. 콘솔 오류 없음.

## 설계 보완
- 소속기관 조회는 직원 디렉터리 helper 대신 기존 동의·신청·유효 역할만 사용하는 전용 helper로 구현했다. 로컬에서 과거 회원관리 migration 미적용 상태에도 동작하며 본인 범위만 반환한다.
- 수료 판정이 아직 없는 상태에서는 stale 플래그만으로 재검토라고 표시하지 않도록 수정했다.
- 고정 헤더 아래 섹션 제목이 보이도록 anchor scroll margin 적용.
- 로컬 migration history 불일치로 `db pull`이 중단되어 CLI `migration new`로 파일을 만들고 실제 로컬 적용 SQL을 기록했다. 기존 이력은 변경하지 않았다. Preview/Production dry-run은 이번 migration 1개만 적용 대상으로 확인했다.

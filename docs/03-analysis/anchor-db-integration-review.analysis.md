## 개선 근거와 범위

스테이징 DB에서 authenticated 역할 및 임시 MFA 세션으로 같은 기관을 교차 6회 조회했다. 인증 fixture는 트랜잭션 전체 ROLLBACK했다. 첫 회를 제외한 5회 중앙값이며, HTTP 왕복 시간은 포함하지 않는다.

| 기관 목록을 얻는 방법 | DB 시간 중앙값 | JSON 크기 |
| --- | ---: | ---: |
| 전체 강사 옵션·정책 RPC | 42.311ms | 13,928B |
| 관리 가능한 기관 id/name만 조회 | 0.103ms | 194B |

기관 선택용 전송량은 약 98.6% 감소한다. 소량 실제 데이터에서 측정한 특정 조회이므로 전체 화면의 99% 속도 개선이나 동시 사용자 처리량으로 해석하지 않는다. 심사 상세는 정책 본문을 계속 읽고, 대장 조회와 병렬 실행한다. 추가 인덱스나 RLS·인증·데이터 변경은 하지 않았다.

authenticated 역할의 EXPLAIN ANALYZE에서도 기존 인덱스를 이용하는 Bitmap Heap Scan으로 기관 2행을 읽었으며, planning 0.544ms / execution 0.160ms / shared buffer hits 5였다.

기존 공개 응답 기준(5회, 첫 회 제외): 운영 health 중앙값 588.5ms, 교육과정 242ms, 로그인 144ms. 이번 변경은 이 공개 화면의 성능을 개선했다고 주장하지 않는다. 홈페이지의 정상 307 로그인 이동을 점검 도구가 실패로 분류하던 문제를 따로 수정했다.

## 회귀 검증

- 기존 DB 조회 검사 16개, 업무 범위 검사 8개.
- 신규 강사 조회 검사 8개: 실제 Supabase builder의 범위/projection/중복 제거, 무권한·잘못된 ID·오류 처리, 불필요한 정책 조회 제거, 심사 상세 병렬 조회/실패 처리, 서류 목록 범위.
- 점검 도구: redirect 단위 검사 10개와 임시 로컬 HTTP 서버의 정상/외부 이동/health 실패/잘못된 JSON 시나리오 4개.
- 실제 로컬 Supabase 강사 Pool 검사 18개: 기관 격리, 등록·수정·중복 방지, 엑셀 원자성, 서류 접근, 수당 계산·증빙·완료 불변·취소 합계, 비인증 차단.
- 총 64개 통과. lint, diff whitespace 검사 및 격리 Next.js 프로덕션 빌드(타입 검사 포함) 통과. 운영 실사용자 계정이나 업무 자료는 변경하지 않았다.

## 설계 대조

기관 범위 유지, 경량 projection, 빈 권한 요청 생략, 오류 구분, 상세 정책 유지, 병렬 조회, 안전한 redirect 판정, 비밀정보 미출력의 8개 항목을 구현·검증했다. 식별된 미해결 차이는 없다.

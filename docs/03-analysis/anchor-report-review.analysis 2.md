# 결과보고서 관리자 검토 - 검증

2026-09-19 · anchor-report-review · 설계 항목 7/7 확인

- 운영 DB에서 사용자 지정 관리자와 연결된 활성 COURSE_MANAGER 1건, SYSTEM_ADMIN, 이메일 인증·TOTP 등록을 확인했다. 기존 시범 역할을 재사용한다.
- 과정이 없어도 `/admin/reports/preview`로 진입한다. 관리자 첫 화면과 공통 메뉴에 링크가 있다.
- 격리 빌드를 로컬 DB에 연결해 가상 운영자는 200, 강사는 404, 익명 사용자는 로그인 307 이동을 확인했다. 실제 사용자의 세션을 만들거나 MFA를 우회하지 않았다.
- 여섯 document 값은 결과보고서 5쪽, 나머지 각 1쪽으로 응답한다. 잘못된 값은 404다. 브라우저에서 양식 선택 링크를 확인했다.
- 실제 ReportDocuments 컴포넌트를 재사용한다. 10개 용지에 모두 검토용 과정명과 제출 불가 표기가 있으며 계좌 공개 링크가 없다.
- 운영 DB 사후 계수: 과정 0개, 보고서 0개, 지정 관리자의 시범 운영 역할 1개. 예시 데이터는 저장되지 않았다.
- 린트·전체 Next.js 빌드·타입 검사 통과. 데스크톱·390px 모바일 화면 검토; 모바일 전체 페이지 폭은 390px. 출력 문서는 별도 가로 스크롤 영역으로 표시한다.

브라우저 PDF 내보내기로 10쪽과 문서 텍스트를 확인했다. agent-browser PDF 기본 용지는 Letter이며 실제 브라우저 인쇄의 기존 A4 named-page CSS는 변경하지 않았다. 개인정보·계좌·서명 자료를 검토 데이터로 복사하지 않았다.

공유 작업 중 생성된 원격 커밋에 포함된 `.next-course-reports` 산출물 5개는 추적에서 제거하고 `.next-*/`를 제외했다. 로컬 캐시는 유지한다. 기존 제출용 PrintToolbar는 과정 복귀·계좌 가리기 기능을 그대로 제공한다.

# 출결·성적·수료 운영 읽기 검증

설계 6항목을 구현과 비교했다. ID 분류 predicate, private/security_invoker view 9개, 읽기 함수 13개 및 기존 권한에 AND되는 restrictive SELECT 정책 4개를 확인했다. 원본 UPDATE/DELETE 및 판정/승인/채점/QR/시험/발급 근거 함수 변경은 없다.

운영 감사: 출결 10건·판정 10건·승인 4건이 모두 기존 검증 과정 2개에 속한다. 등록 12건도 검증 범위다. 제출·성적·응시·QR·구형 출결/성적 및 연간 확정 성과 보고서는 0건이다. 원본을 취소/삭제하거나 정상 과정의 과거 확정 보고서를 다시 쓰지 않는다.

로컬 단일 transaction 후 ROLLBACK 검증 통과:
- 정상/검증 과정·계정, 이름 변경 후 ID 분류 유지. 출석 인정시간 48분과 정정 revision 유지, 정상 출석률 90%, 휴강·미입력 구분.
- 수료 명단 3명에서 정상 승인/미승인 최신 판정·철회/오래된 이력 유지. 모니터링의 활성 2명, 수료 1명, 검토 대기 1명, 예상 출결 4건/기록 3건/누락 1건 일치.
- 연간 등록 분모 3명·수료 분자 1명·33.33%, 정상 과제 점수와 피드백·시험 만료 상태 유지. 시험 종료 전 본인 점수 비공개와 정답 비공개 유지.
- 강사/기관·본인·타 기관 및 익명 접근 경계, 직접 테이블 RLS(성적·승인 자식 포함), private view/정답 원장 직접 접근 차단.
- 출결·등록·제출·점수·시험·정답·QR·판정·승인·보고 원본 hash 불변. 기존 학사 입력 변경 시 revision 증가와 마감 해제가 유지되어, fixture는 입력 완료 뒤 마감·판정 근거를 생성했다.

출시 검증: 운영 원본 84개 항목과 변경 범위 밖 함수 612개 hash baseline 확보. Preview 전체 migration/검사, 운영 SQL 원자적 적용 및 ledger, 실제 화면·배포 SHA·health·보안 advisor 전후 대조를 진행한다.

## 정상 과거 조회 보완

부모 회차/미공개 과제를 볼 수 없는 정상 철회자의 본인 출결·제출·성적을 유지하는 회귀 사례를 추가했다. 최초 restrictive 정책은 해당 정상 이력을 숨기는 문제를 재현했고, 후속 migration의 boolean reference helper 2개로 해결했다. 최종 로컬 전체 검증 통과. 부모 자료 권한과 원본 이력 hash는 그대로 유지된다. 두 migration은 운영에서 하나의 transaction으로 적용한다.

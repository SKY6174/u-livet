# 구성원 엑셀 등록·관리 설계

2026-09-24 · anchor-member-excel-workflow

## 파일과 화면
- `/admin/accounts`의 현재 분류 옆에 `엑셀 서식`, `엑셀 업로드`, `엑셀 다운로드`를 둔다. 업로드는 신규 등록 운영자 또는 SYSTEM_ADMIN만 사용한다.
- 사업단·강사·수강생마다 기존 편집 필드와 같은 열로 한 시트 서식을 만든다. 기존 내보내기 행은 `구성원 ID`와 `수정 버전`을 포함한다. ID가 빈 행은 신규 등록, ID가 있는 행은 기존 구성원 수정이다. 기존 행의 이메일은 조회용으로만 사용한다.
- 브라우저에서 `.xlsx` 2MB·100행 제한, 열 이름/순서, 자료형, 중복 ID·이메일, 그룹별 값 검증 후 미리보기한다. `등록 확정` 전에는 저장하지 않는다. 원본은 서버나 스토리지에 보관하지 않는다.
- 다운로드는 현재 그룹·검색어에 해당하는 전체 목록을 최대 1,000명까지 포함한다. 전화번호 등 개인정보가 들어 있으므로 기존 명부 조회 권한을 그대로 적용한다. 수강·강의 이력은 편집 서식에 넣지 않는다.

## 서버·DB
- 서버 액션에서 `newMemberInput`/`memberInput`으로 각 행을 다시 검증한다. 신규 행은 지정 `member_entry_orgs`, 수정 행은 `SYSTEM_ADMIN`을 요구한다. 수정 대상 ID·버전과 이메일 변경 여부를 확인한다.
- `life_member_import(group, org, rows)`는 private definer에 위임한다. private 함수는 1~100행을 같은 트랜잭션에서 처리하고 각 행마다 기존 `life_private.create_member` 또는 `life_private.save_member`를 호출한다. 두 함수의 조직/MFA/중복/버전 검증·감사를 유지한다. 한 행 실패 시 파일 전체가 롤백된다.
- `life_member_export(group, query)`는 기존 명부의 인증·조직 범위 `member_scope_for(false)`를 재사용해 해당 그룹·검색어의 최대 1,000명만 반환한다. 개인정보 필드 외의 인증 비밀·서류는 포함하지 않는다.
- 새 public wrapper는 invoker, private 함수는 고정 빈 search_path로 만들고 함수 실행 권한을 명시적으로 제한한다. 새 테이블이나 직접 테이블 접근 권한은 추가하지 않는다.

## 검증·반영
- 파서·서식·서버 경계 검증, 신규/수정·혼합 파일, 중복·잘못된 값·권한·MFA·revision 실패 시 원자적 롤백, 다운로드 범위·한도 확인.
- 로컬 DB에서 트랜잭션 격리 검증 후 Preview DB/웹 앱, Production DB/웹 앱 순으로 적용한다.

# 모집 공개 정책 준비 · 설계

2026-10-07 · [계획](../../01-plan/features/recruitment-policy-management.plan.md)

## 데이터·권한

기존 `life_policy_versions`의 `ENROLLMENT`, `COMPLETION`, `DRAFT`, `APPROVED` 및 승인 후 불변 트리거를 사용한다. 조직의 활성 `COURSE_MANAGER`만 초안을 작성·수정하고 승인할 수 있다. 초안 등록 RPC는 종류·제목·버전·본문 길이를 검사하고 감사기록을 남긴다. 초안 수정 RPC는 제출 당시 본문과 현재 본문이 일치하는지 확인한다. 승인 RPC도 제출 당시 본문을 확인하고 행을 잠근 뒤 `approved_by/approved_at`을 기록한다. 프런트에서 직접 테이블에 쓰기 권한을 부여하지 않는다.

정책 승인 자체가 법률 검토를 대체하지 않으므로, 승인 폼에 기관 내부 결재·검토 완료 확인을 명시한다. 초안에 오류가 있으면 새 버전을 등록한다. 유효일은 승인 시각부터 시작하며 승인 버전은 수정하지 않는다. 이미 승인된 `[검증용]` 항목은 선택 화면에서 경고 표시만 하고 자동 폐기하지 않는다.

## 화면·흐름

1. `/admin/policies?org=<id>`에서 담당 조직을 선택하고 정책별 구성 항목을 확인한다. 정책 종류별 초안을 입력한다. 본문 예시에는 기간·대상·기준을 추정해 넣지 않는다.
2. 작성자가 초안 본문을 확인한 뒤 기관 검토가 완료된 경우에만 승인한다. 승인된 버전만 모집 공개 선택지에 나타난다.
3. 과정 관리의 모집 공개 영역에 준비 경로와 두 정책의 요약 기준을 표시한다. 검증용 항목은 운영에 쓰지 말라고 안내한다.
4. 공개 과정 소개에도 모집·수집이용 안내를 보여준다. 신청 화면의 동의와 수료 화면은 선택된 승인 버전을 계속 보존·표시한다. 계산용 수료 임계값은 기존 `life_completion_rules` 별도 승인 흐름을 안내한다.

## 검증

- 관리자 페이지는 조직의 COURSE_MANAGER 역할만 접근 가능하다.
- 서버 액션과 DB RPC가 모두 길이·종류·조직 권한을 검사한다.
- 승인 전 초안은 `getPolicies()`에 포함되지 않는다. 승인 후에는 공개 선택지에 보인다.
- `npm run lint`, `npx tsc --noEmit`, `npm run build` 및 DB 마이그레이션/권한 점검을 수행한다.

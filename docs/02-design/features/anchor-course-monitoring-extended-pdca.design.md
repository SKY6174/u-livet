# 2026~2027 과정별 연간 PDCA 확장 설계

> 2026-09-25 | 계획: `docs/01-plan/features/anchor-course-monitoring-extended-pdca.plan.md`

## 데이터와 호환

- 기존 `life_course_monitoring_plans`에 과정준비·운영계획서 제출·수강생모집의 목표일/완료일 6개와 `next_year_decision`을 추가한다. 결정 값은 `UNDECIDED`, `CONTINUE`, `REVISE`, `STOP`으로 제한한다.
- 기존 `plan_due_on`/`plan_done_on` 값은 수강생모집 목표/완료일로 옮겨 보존한다. 이후 저장에서는 기존 P 열도 모집 날짜와 동기화한다.
- 새 `life_save_monitoring_plan_v2` RPC는 기존의 조직·역할·최근 MFA·revision 검사를 기존 저장 함수에 위임한다. 앞서 새 세부 날짜의 범위(2026-01-01~2027-02-28), 순서(준비→계획서→모집→운영→평가→차년도 반영), 완료일의 미래 금지, A 완료 시 차년도 결정과 반영 내용을 검사한다. 같은 트랜잭션에서 세부 필드를 저장하고 수정 후 행을 반환한다.
- 직접 테이블 접근은 기존처럼 차단한다. 익명 RPC 실행은 허용하지 않는다.

## 화면과 판정

- 현황 카드 5개(표시 과정·신청 대기·수강 확정·출결 미입력·수료 검토 대기)는 신호등 카드 바로 아래, 연간 PDCA 흐름과 일정표 위에 배치한다. 운영 현황 필터가 바뀌면 이 카드의 기존 집계도 함께 바뀌도록 같은 상태를 공유한다.
- 과정 운영 현황 목록의 메타정보는 기관명을 첫 줄에, `2026(2차년도)∙라이프케어`처럼 사업연도·차년도·분야를 둘째 줄에 표시한다. 분야의 끝에 붙은 `아카데미`는 화면 표기에서만 제거한다.

- 고정된 14개 월 키 `2026-01`부터 `2027-02`를 표·필터에서 공유한다. 각 헤더는 연도를 포함해 ’26.1월과 ’27.1월을 구별한다.
- 표 위에 P 3개 업무 → D 과정운영 → C 과정별 성과평가 → A 차년도 운영 반영 흐름을 표시한다. 월 셀에는 겹치는 목표 마커를 모두 출력한다. D 공개 안내 기간과 확정 계획, 실제 운영 기간은 서로 구별한다.
- 상세 편집에서 P 3개 업무·D·C·A의 목표/완료 날짜와 차년도 결정·반영 내용을 입력한다. A가 완료되기 전에는 결정을 미정으로 둘 수 있다. 근거 없는 과거 P/C/A 날짜는 생성하지 않는다.
- 신호등은 P 3개 목표, D 시작/종료, C/A 목표 누락을 `계획전`으로 판정한다. 명시 애로가 최우선이며 각 완료 지연과 지난 목표 미완료는 `지연`으로 판정한다. 기존 D 실제 운영 비교는 유지한다.

## 단계별 실제 완성도

- 일정 목표와 실제 완성도를 분리한다. 신호등은 일정 준수 여부, P·D·C·A 백분율은 실제 증빙으로 계산한다. 각 과정 행과 상세 화면에 네 단계의 수치와 근거를 표시한다.
- P: 담당자가 최종 제출한 운영계획서(`plan_status=SUBMITTED`)를 승인 완료로 보아 50%; 모집 완료일 기록 또는 과정 상태 `CLOSED`/`ARCHIVED`를 모집 종료 근거로 보아, 계획서 승인과 모집 종료가 모두 충족되면 100%. 그 외 0%. 계획서 초안/검토 중은 승인으로 세지 않는다.
- D: 전체 예정 회차 대비 실시간 출석부 입력을 반영한다. 등록 수강생 × 전체 예정 회차를 분모로, 기록된 출결 건수를 분자로 하여 0~100%로 제한하고 소수점은 버려 기록 누락 시 100%가 되지 않게 한다. 예정 회차나 수강생이 없으면 0%와 근거 없음 안내를 표시한다. 기존 과정 현황 RPC의 출결·회차 집계를 재사용한다.
- C: 책임교수가 결과보고서를 검토 요청(`result_status=REVIEW`)하거나 최종 제출(`SUBMITTED`)하면 75%. 평가회 예정 횟수는 1회 또는 2회로 설정하고, 그 횟수만큼 평가회 수행일을 기록하면 100%. 결과보고서 없이 회의일만 입력된 경우에는 100%로 올리지 않는다. 수행일은 미래 날짜를 허용하지 않는다.
- A: 사업단 주관 성과평가 수행일 또는 자체평가회 수행일이 있으면 100%, 없으면 0%. 기존 차년도 계속·개편·중단 결정 및 반영 내용은 별도 기록한다. A 백분율은 평가회 수행 기준이므로 차년도 반영 완료일과 동일시하지 않는다.
- 신호등의 지난 목표 미완료 판정은 기록된 수행일과 실제 증빙을 함께 본다. 계획서 최종 제출·모집 종료, C 평가회 충족, A 평가회 수행이 있으면 수동 완료일이 비어도 미완료로 보지 않는다. 다만 기록된 수행일이 목표보다 늦으면 지연을 유지한다. D 종료 목표일 이후 미운영 회차·출석부 미입력은 D 지연, 결과보고서와 평가회 미완료는 C 목표일 이후 지연으로 판단한다. A 평가가 끝나도 차년도 운영 판단·반영 내용이 A 목표일까지 없으면 지연으로 알린다.
- 신규 평가회 수행일(최대 2회), 평가회 목표 횟수, 사업단 평가 수행일은 기존 모니터링 계획 행에 보관한다. 기존 저장 RPC의 권한/MFA/revision/audit 경계를 유지한 v2 확장으로 저장한다. DB도 1~2회, 날짜 범위·미래 금지, 2회차 순서를 검증한다.

## 검증

- 14개 월의 순서·연도 경계·두 1월 구분, 한 셀의 여러 마커, 과정 16개 렌더링과 월 필터를 확인한다.
- P 세부 기한별 지연/미계획 및 차년도 결정 조건을 확인한다.
- 새 migration을 로컬 DB에서 적용하고 저장 RPC의 날짜 순서·역할·수정 충돌을 확인한다.
- lint, TypeScript, build 및 기존 모니터링 회귀를 통과한다.

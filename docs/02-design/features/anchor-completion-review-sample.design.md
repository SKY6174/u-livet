# 수료 검토 예시 데이터 표시 설계

> Feature: anchor-completion-review-sample | 2026-09-25
> Plan: [계획](../../01-plan/features/anchor-completion-review-sample.plan.md)

## 데이터 흐름

`/completion/[id]`의 기존 과정·조직 역할 검사를 통과한 뒤 `?sample=1` 요청에서만 메모리의 `CompletionRow[]` 예시를 사용한다. 기본 요청은 기존 DB 보드를 그대로 사용한다. 수강등록자가 없을 때 예시 링크를 노출한다. 예시 화면에는 명확한 배너와 원래 화면 링크를 표시한다.

## 데이터 구성

- 등록 활성·출석률 90%·수료 확정
- 등록 활성·출석률 85%·승인 대기
- 등록 활성·출석률 70%·기준 미달
- 등록 철회·중도 환불 신청서 처리와 금융 지급 완료
- 등록 활성·출석 미완료·미산출
- 등록 활성·기존 판정이 자료 변경으로 재산출 필요

각 행에는 기존 `CompletionRow` 구조의 출석률, 기준, 판정 근거, 회차, 과제, 시험, 환불 상태를 채운다. 기존 UI 컴포넌트를 재사용하되 예시 모드에서 모든 상태 변경 폼의 버튼을 비활성화한다. 예시 데이터는 외부 API로 보내지 않으며 DB에 저장하지 않는다.

## 검증

정적 예시 데이터의 상태 다양성과 링크·배너·비활성 동작을 확인하고 lint, TypeScript, 빌드를 통과한다. 실제 등록자가 0명인 화면으로 복귀하면 원래 빈 상태가 유지되어야 한다.

# 강사 출석부·개인 출석 확인 설계

2026-09-21 · 기존 anchor-learning-evaluation 설계의 공식 출결·정정·수료 근거 계약을 유지한다.

## DB 계약
- 추가 테이블 없이 life_class_sessions, life_enrollments, life_attendance를 재사용한다. 출석부 명단은 ACTIVE 등록자이며 생성/열람으로 출석을 인정하지 않는다.
- `life_teaching_attendance(f)`는 유효 배정 INSTRUCTOR만, `life_my_attendance(f)`는 본인 ACTIVE 등록만 허용한다. 공통 private definer 함수는 이 조건을 먼저 검사한다. 과정 기본정보, 서버 현재 시각, 회차, 필요한 명단/출결 필드만 JSON으로 반환한다. 학생 입력 person ID는 받지 않는다.
- 하나의 읽기 RPC로 기존 과정·배정·명단·회차·출결 조회 왕복을 줄인다. JSON 집계로 PostgREST 기본 1,000행 제한에 따른 출석부 누락을 피한다. 명단에는 이메일·연락처가 포함되지 않는다.
- `life_record_attendance_batch(s, records)`는 회차를 잠그고 1~200개의 고유 person ID·0~1440분·사유·expected_revision 입력을 검증한다. 기존 record_attendance를 재사용하여 권한/종료/ACTIVE 등록/자기기록 금지/정정 충돌/감사·학사 revision을 보존한다. 중간 오류 시 전체 rollback. 변경된 행만 저장한다.
- 공개 함수는 security invoker, 구현은 private, search_path 고정, 실행 권한은 authenticated에만 부여한다. 기존 native MFA와 최근 인증 쓰기 트리거를 유지한다.

## 강사 화면
- `/instructor/offerings/[id]/attendance`: 담당 과정 명단·전체 회차 표, 수업/보강 일정 추가, 선택 회차별 기록 입력. 휴강/예정/미입력/출석/일부 출석/결석 구분.
- 각 수강생의 입력은 기본 미입력. 명시적으로 선택한 행만 일괄 저장하며 전체 출석 버튼은 입력 초안만 채운다. 사유는 저장 시 필수이며 기존 기록을 덮어쓰는 일괄 기본값은 사용하지 않는다.
- revision 변경이나 저장 실패 시 입력을 유지하고 재조회 방법을 안내한다. 성공 후 서버 데이터 새로고침. 수업이 끝나기 전과 취소 회차는 입력 불가.
- `/instructor/offerings/[id]/attendance/print`: 같은 권한·DB를 읽어 회차 6개/명단 20명 단위 인쇄 출석부 생성. 이름, 회차별 인정분, 서명용 빈칸, 집계 포함. PDF 저장은 브라우저 인쇄를 사용한다.
- 강사 공간·강의 운영·기존 출결/시험 화면에 출석부 링크를 둔다.

## 수강생 화면
- `/learning/[id]/attendance`: 본인만 조회. 종료된 정상 수업 수, 확인 완료 수, 미입력 수, 인정시간을 표시한다.
- 진행 수업 출석률은 종료된 정상 회차 전체가 기록된 경우에만 인정시간/종료 수업시간으로 표시한다. 미입력이 있으면 확인 중으로 표시하고, 미래 회차와 취소 회차는 이 비율 분모에서 제외한다. 수료 판정은 기존 전체 회차·승인 규정 계산과 별개임을 설명한다.
- 수업별 일정, 보강 연결, 상태, 인정분, 기록 사유 표시. 출석 정정은 담당 강사 문의.
- 나의 학습의 확정 신청 카드·강의실·기존 평가 화면에서 바로 연결한다.

## 성능·검증
- 읽기 1 RPC, 출결 인덱스를 Map으로 한 번 생성해 회차×명단 렌더링 중 반복 전체 검색을 제거한다. 사용자 간 공유 캐시를 두지 않는다.
- 실제 DB 연결/읽기 권한을 운영·Preview에서 확인한다. 기존 데이터가 소수/미등록이면 로그인 업무 속도로 확대 해석하지 않는다.
- 로컬 합성 데이터(여러 과정·1,000행 초과 출결)에서 실제 JWT로 이전 조회와 신규 RPC의 응답시간·전송량·행 수를 교차 측정한다. 첫 요청과 반복 중앙값/p95를 기록한다.
- 입력 검증, 시간·상태별 집계, 접근 거부, 개인정보 범위, 트랜잭션 rollback·revision 경합, 기존 감사/수료 연결을 검사한다. 관련 회귀·빌드·모바일/웹 확인 후 Preview→Production migration, Git main/preview push와 배포 확인.

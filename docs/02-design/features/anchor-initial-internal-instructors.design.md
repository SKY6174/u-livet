# 2026 과정 첫 교내 강사 우선 배정

## 근거와 범위

`docs/operations/2026-course-opening-plans.json`의 16개 원본 계획서 강사현황에서 `staff.teachers` 순서를 유지하고, `classification=교내`인 첫 강사만 선택한다. 교내 강사가 명시된 과정은 10개이며 고유 인물은 9명이다. 나머지 6개에는 교내 강사가 없으므로 원문 강사 명단을 바꾸지 않는다. 사용자 추가 지시에 따라 이 6개 과정의 초기 책임강사는 현용환 센터장으로 둔다. 원본의 이름만으로 기존 로그인 인물과 동일인이라 판단하지 않는다.

## 데이터와 권한

9명의 로그인 미연결 `life_people` 인물과 활성 교내 `instructor_pool` 기록을 만든다. 사용자 요청에 따른 임시 승인 상태로 사업단 `INSTRUCTOR` 역할을 부여하되 `life_auth_links`는 만들지 않는다. 따라서 본인 인증 전에는 강사 페이지나 문서 작성 권한이 열리지 않는다. 등록 출처는 메모에 남긴다.

`life_course_guides.initial_instructor_id`에 10개 과정의 해당 인물을 저장하고 `initial_responsible_id`에는 16개 과정의 초기 책임강사를 기록한다. 센터장은 별도 로그인 미연결 인물로 생성하지만 실제 교과 강사 Pool·강사 역할은 부여하지 않는다. 기존 관리자 전용 예산·과정 조회 RPC가 우선 승인 강사, 초기 책임강사, 실제 계정 연결 상태를 반환한다. 기수가 있는 3개 과정에는 첫 교내 강사를 `life_offering_instructors`에 배정하고, 현재 책임강사가 없으면 초기 책임강사로 지정한다. 기존 제출본은 수정하지 않는다. 향후 인증한 계정과 신원을 확인한 뒤 관리자가 책임강사를 변경할 수 있다. 아직 기수가 없는 13개 과정에는 기수 배정을 만들지 않는다.

## 검증

16개 중 우선 승인 교내 강사 10개/센터장 초기 책임 6개, 9명 Pool 및 역할, 기수 3개 배정, 로그인 연결 0개, 기존 제출본 불변을 Preview와 운영 DB에서 확인한다. 관리자 화면에는 우선 승인과 실제 책임강사를 구별해 표시한다.

# Issue 152 — 사업단 관리 빈 화면 상세설계

작성일: 2026-10-10 · 계획: `docs/01-plan/features/issue-152-admin-workspace.plan.md`

## 기존 설계와 원인

`anchor-role-navigation.design.md`와 `anchor-business-menu.design.md`의 역할별 메뉴 및 서버 권한 경계를 따른다. 서버에서 검증한 `life_identity`의 명부 구분은 업무 홈 진입에, 유효한 업무 역할은 메뉴와 RPC 접근에 사용된다. 신고 계정의 업무 역할 0개는 확인된 원인이다.

## 화면 변경

- `/admin/page.tsx`: `officeSections(me)`를 한 번 계산한다. 빈 배열이면 `Empty`로 “아직 부여된 업무 권한이 없습니다”를 표시한다. 사업단 명부 등록과 업무 역할 부여가 별개임을 설명하고 계정 관리 담당자에게 담당 업무 권한 확인을 요청하도록 안내한다. 새로고침과 내 정보 링크를 제공한다.
- 기존 역할별 업무 카드는 계산한 sections로 렌더링한다. 메뉴 없음과 요청 데이터 없음은 서로 다른 상태다.
- `/admin/not-found.tsx`: 관리 업무 접근 권한 부족 안내와 업무 홈/홈페이지 링크를 제공한다. 서버의 `notFound()` 거부를 유지한다.
- `/admin/loading.tsx`: 인증·권한·업무 현황을 확인 중이라는 status 안내를 제공한다.
- `/admin/error.tsx`: 예상하지 못한 화면 조회 실패를 사용자에게 안내한다. `reset()` 재시도와 업무 홈 링크를 제공한다. 내부 오류·계정 개인정보는 화면에 노출하지 않는다.
- 기존 `LearnerRequestAlerts`의 조회 실패 및 처리할 요청 없음 안내는 유지하고 회귀 검증한다.

## 데이터·권한

기본 수정은 API·DB schema·RLS·역할 부여 규칙을 변경하지 않는다. 모든 하위 화면 및 RPC의 역할/조직 검사를 유지한다.

사용자의 추가 요청에 따라 운영의 지정 사업단(`10000000-0000-4000-8000-000000000001`) 명부에서 `member_group=office`이고 연결된 person이 활성인 현재 구성원 모두에게 `COURSE_MANAGER`를 부여한다. 유효한 동일 역할이 있으면 건너뛰고 기존 다른 역할은 보존한다. 역할 삽입과 `life_audit_events` 기록을 같은 트랜잭션에서 수행하고 변경 후 대상 수·유효 역할 수·중복 수를 재조회한다. 감사에는 이슈 번호와 사용자 요청에 따른 관리 작업임을 남기며 앱 사용자를 허위 actor로 기록하지 않는다. 강사·수강생, 다른 조직 및 미래 신규 구성원은 이 일괄 적용의 대상이 아니다.

## 검증 계획

1. 기존 `verify-role-navigation.mjs`에 실제 문제와 같은 office 명부·책임연구원·roles=[] fixture를 추가하여 안내, 0개 업무 링크, 0회 업무 데이터 조회를 검증한다.
2. 명부 담당자·단일 관리자 역할·복수 역할 메뉴와 하위 서버 gate를 회귀 검증한다.
3. 요청 알림의 실제 컴포넌트에서 null과 빈 requests 안내를 구분한다.
4. 관리 loading/not-found/error 컴포넌트 안내와 재시도 버튼을 검증한다.
5. 타입 검사·lint·production build 및 배포 후 HTTP/배포 커밋/READY 상태를 확인한다.

운영 계정 비밀번호나 로그인 세션을 생성하지 않는다. 운영 DB의 실제 역할 조회와 합성 identity 렌더링은 실제 계정 브라우저 로그인 검증과 구분하여 보고한다.

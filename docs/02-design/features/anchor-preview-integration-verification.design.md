# Preview 통합 검증 설계

- 기능: `anchor-preview-integration-verification`
- 일자: 2026-09-19
- 기존 기능 설계: 과정 편성표, 결과보고서, 관리형 Cloud 인증, DB 성능 개선.

## 검증 경로

1. 고정 Preview의 `/api/version`과 `/api/health` → 기대 커밋·환경·건강 상태.
2. 격리된 시험 조직/사업연도/수강정책과 합성 운영진·강사·학습자 → 기본 DB 권한. 계정 생성은 현재 승인된 가입 정책과 필수 휴대전화 입력 규칙을 따른다.
3. 브라우저 로그인 → native TOTP → 실제 역할별 화면. 비인증·타역할 접근 거부도 확인.
4. `/admin/course-plan` → 14개 원문 과정, 검색과 스마트테크·라이프케어·로컬창업·팝업 필터.
5. 가상 과정 `/admin/offerings/[id]/reports` → 폼 저장 → 재조회 → DB revision/내용 대조.
6. PDF/사진 첨부 → API → DB → 다운로드 원본 대조 → 삭제.
7. 전체·개별 6종 인쇄 화면 → 브라우저 PDF와 화면 확인.

## 시험 데이터와 정리

- 기존 관리자/사용자의 비밀번호·MFA를 변경하지 않는다.
- 무작위 식별자와 `example.invalid` 계정을 사용하고 메일 발송 없는 Auth Admin `generateLink(invite)`로 준비한다. 현재 `life_signup_policy()`의 정책 ID와 합성 휴대전화 값을 사용하며 공개 가입 설정은 변경하지 않는다.
- 생성한 링크의 OTP 검증과 시험 비밀번호 설정 후 세션을 종료하고 웹 로그인부터 확인한다.
- 실제 웹 로그인은 비밀번호/TOTP 입력으로 수행한다. 관리자 키는 시험 데이터 준비와 정리에만 사용한다.
- 최소한의 가상 과정·배정·수강·회차를 만들고 시험 데이터 ID를 Git 제외 경로에 0600으로 기록한다.
- 작업 후 해당 계정 세션을 종료하고 생성한 모든 DB 객체·파일을 식별자 조건으로 정리한다.
- 기존 승인 정책은 보존하고, 그 정책에 연결된 동의 기록 중 시험 인물의 기록만 정리한다.
- 증거에는 토큰·비밀번호·MFA 비밀을 넣지 않는다.

## 결과 판정

- 화면 렌더링만으로 성공을 판정하지 않고 실제 응답과 DB 재조회를 대조한다.
- 실패 경계를 발견하면 원인을 확인·수정하고 해당 경로를 다시 검증한다.
- Production 변경과 DB migration은 이 검증의 범위 밖이다.

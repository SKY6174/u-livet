# 개인 시작화면 설계

## 이동 흐름
- `/`는 `requireIdentity("/")`로 실제 회원과 추가 인증을 확인한다. 비로그인은 `/auth/login?next=%2F`, MFA 미완료는 `/auth/security?next=%2F`로 이동한다.
- 로그인 선택 페이지의 인증 완료 회원은 `/` 또는 명시된 내부 복귀 경로로 보낸다. 인증 화면 자신을 기본 복귀 대상으로 삼지 않는다.
- 이메일·소셜 복귀 경로의 기본값은 `/`이다. audience 기반 자동 업무 경로 변경을 제거하고 검증된 명시적 next는 그대로 유지한다.
- 소셜 신규 가입은 기존 가입 완료 단계를 거친 뒤 `/`로 돌아온다. MFA 필요 계정은 기존 인증 단계를 거친다.
- 로그아웃은 기존 `/`로 돌아간 뒤 로그인 선택 화면으로 연결된다.
- 로그인 시작화면(`/auth/login`, 대상 선택 후 양식 포함)의 상단·모바일 메뉴에서는 ‘나의 공간’과 중복 ‘로그인’ 링크를 숨긴다. 다른 페이지의 계정 메뉴는 유지한다.

## 개인 화면
- 기존 남색 배너, ‘지금의 배움이, 내일의 일로.’, 교육과정 카드와 하단 브랜드를 유지한다.
- 서버 identity의 이름으로 인사한다. 비공개 회원정보를 캐시하거나 클라이언트 audience로 권한을 결정하지 않는다.
- 수강생: 나의 강의실, 신청 현황, 수강이력·수료 현황.
- 강사: 강사 공간, 강사 이력·등록 심사, 나의 공간.
- 사업단: SYSTEM_ADMIN 계정 관리, COURSE_MANAGER 과정 운영, FINANCE 수납·환불, CERTIFIER 증명 발급, PERFORMANCE 성과 관리 중 실제 보유 역할만 표시한다. 복수 역할은 함께 표시한다.
- 바로가기 표시는 편의 기능이며 각 업무의 기존 서버/DB 접근 검증을 유지한다.

## 검증
- 이메일/소셜 기본 로그인, 명시된 업무 링크, 가입 대기와 가입 완료, 필수 MFA 및 검증된 MFA, 로그아웃 경로를 확인한다.
- 인증 전 홈 차단, 역할별 링크, 개인 이름, 인증된 로그인 페이지 이동을 합성 테스트로 확인한다. 브라우저에서 데스크톱/모바일 로그인 선택과 개인 홈을 확인한다.

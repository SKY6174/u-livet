# 수강료 입금·환불 상세설계

2026-09-19 · 기관 규정 미확정, 승인 설정 없으면 유료 모집 차단

## 구조·권한

Next Server Actions → 사용자 세션 RPC → 고정 search_path의 비공개 트랜잭션 함수. 브라우저의 원장 쓰기를 회수하고 원장 조회도 본인 또는 기관 FINANCE+유효 위임에 한정한 RPC로 제공한다. COURSE_MANAGER/CERTIFIER/SYSTEM_ADMIN에는 회계 원문 권한을 자동 부여하지 않는다.

`life_finance_grants`: org/person/permission(RECORD, APPROVE, PAYOUT), 유효기간, 승인자/승인근거. 신뢰된 DB 경로로만 등록. RECORD는 입금확인·배분·환불산출, APPROVE는 산출자와 다른 환불 승인자, PAYOUT은 승인자와 다른 지급 처리자다. 본인 수납 확인/환불 검토·승인·지급은 모두 금지한다.

## 정책·유료 기수

`life_policy_versions`에 REFUND를 추가한다. 승인 규정에 연결된 `life_refund_rules`는 조항명/계산기준(TUITION 또는 PAID)/분자/분모를 저장한다. 0≤분자≤분모, 원단위 내림. 조항 선택은 담당자가 요청시각·수업 진행 근거를 확인해 결정하며 다른 승인자가 검토한다. 자동 법률 판정이 아니다. 규정·조항은 승인 원문 불변, 신규 버전으로 대체한다. 실제 값은 seed하지 않는다.

`life_offering_finance`: 기수 고유키, 승인 환불규정, 납부 예약시간(1–720시간), 납부 안내문(기관이 승인한 계좌 안내 포함), 확인 담당자. COURSE_MANAGER가 DRAFT일 때만 설정. 공개 후 변경 불가. 규정/조항/현재 유효성을 공개·신청 시 재검사. 신청에는 요약 수강료/환불규정 버전 동의가 필요하다.

유료 신청은 심사형이면 SUBMITTED, 선착순이면 남은 좌석에 PENDING_PAYMENT, 초과 시 WAITLISTED다. 심사 선발/대기자 선발은 PENDING_PAYMENT와 청구를 만들며 아직 등록하지 않는다. 기수 잠금으로 현재 ACTIVE 등록+기한 내 PENDING_PAYMENT를 정원에 계산한다. 기한 만료 청구는 EXPIRED, 신청은 CANCELLED로 명시 정리한다. 신청·선발·배분 진입 시에도 만료를 정리하여 수동 만료 버튼 실행 여부에 의존하지 않는다. 기한은 선발시각+예약시간과 교육 시작 자정 중 빠른 시각이며 유료 과정의 개강 후 신규 접수는 차단한다.

## 수납 모델

- `life_invoices`: application 고유키, 기수/사람/기관 복합 FK, 청구 원금, 환불규정 고정, 납부기한, OPEN/SETTLED/CANCELLED/EXPIRED, 생성시각.
- `life_payment_reports`: 본인 신고(청구/금액/입금자/시각), 요청 키 고유. 실제 납부로 합산하지 않는다.
- `life_payments`: 기관/원거래 참조 고유, 확인된 입금 총액/시각/입금자/연결 본인/대사 증빙/확인자. 확인 기록을 삭제·덮어쓰지 않는다.
- `life_payment_allocations`: 원입금/청구/금액. 양수 정수 원화, 같은 기관·사람, 배분총액≤입금액, 청구총배분≤원청구액, 재전송 키 고유. 한 입금의 여러 청구 배분과 분할입금을 지원한다.
- `life_credit_notes`: 청구 조정. 취소 시 미납부분, 환불 지급 시 지급금액을 별도 조정원장으로 기록한다.
- `life_finance_events`: actor, entity, action, details, 시각. 계좌 원문 없는 변경 증거, 본인은 자기 청구에 대한 공개 상태/사유만 조회한다.

잔액=원청구−조정합계−(배분합계−지급환불). 무료 신청에는 가짜 입금을 생성하지 않는다. 실제 입금만 등록돼도 배분 전에는 납부확정하지 않는다. 기한 내 배분총액=청구액일 때 기수/청구 잠금 안에서 수강등록한다. 만료/취소 청구로 들어온 입금은 근거를 남겨 배분하되 자동등록하지 않고 예외 상태로 환불 검토한다. 취소조정이 있던 청구에 늦은 입금을 배분하면 같은 금액의 역조정 이벤트로 미납면제를 환원한다. 미배분/초과입금은 잔액을 숨기지 않고 예외 목록에 남긴다.

## 환불·지급

본인 청구의 환불신청은 수강취소를 함께 확정하며 LMS 접근을 종료하고 미납부분을 조정한다. 이 사실을 신청 전에 표시한다. 신청 시각과 당시 교육기간/진행 회차를 근거 스냅샷으로 남긴다. 환불 반려가 수강을 자동 복원하지 않는다. 일반 취소 API는 납부배분이 있는 유료 건을 환불신청으로 안내해 원장 없는 취소를 막는다.

`life_refunds`: 청구, 본인/사유, REQUESTED → REVIEWED → APPROVED → PROCESSING → PAID; REJECTED/RECONCILING 분기. 진행 중 환불은 청구별 하나, 각 변경에 revision. 규정 조항·산정근거·검토자/승인자·반환계좌 확인 문서 참조를 보존한다. 수강취소 후 재신청 가능하되 이미 반환된 금액을 차감한다.

서버 산식: min(총배분−기지급액, max(0, floor(기준금액×분자/분모)−기지급액)). 기준금액은 승인 조항의 원수강료 또는 총배분액. 검토 시 배분합계·기지급액 snapshot을 저장하고 승인 시 현재값 일치를 검사한다. 산출 0원은 지급승인하지 않고 사유 반려한다. 검토자가 금액을 직접 전달하지 않는다.

`life_refund_allocations`: 원입금 배분별 환불금액. 승인 시 원배분의 기지급+승인/처리중 예약을 차감해 배정한다. 초과환불 불가. 잠금순서는 기수 → 청구 → 환불이며 배분은 추가로 단일 원입금을 잠근다. 모든 변경 RPC는 같은 청구 잠금 규칙을 따른다.

`life_refund_transfers`: 매 지급시도 고유 내부참조, 외부 은행거래 참조, 상태 PROCESSING/RECONCILING/PAID/NOT_PAID. 이 홈페이지는 송금하지 않는다. 실제 은행업무를 시작할 때 처리중으로 예약하고 결과를 기록한다. 불명확한 응답은 RECONCILING, 재시작 금지. 거래 확인 후 PAID 또는 확정 미지급(NOT_PAID+근거)로 판정해야 새 시도가 가능하다. PAID는 실제 거래참조가 기관 내 유일하며 금액 일치 확인 필요. 같은 완료 재전송은 원본을 반환하고 조정원장을 중복 생성하지 않는다.

## 화면

- `/finance`: 권한별 탭 대신 입금대사·청구 배분·환불 요청 카드에 가능한 처리만 표시. 본인 거래 처리 버튼 제외. 미배분 잔액, 기한 만료와 늦은 입금 예외를 표시.
- `/admin/finance`: 회계 화면으로 안내. 실제 `/finance`가 기존 COURSE_MANAGER layout과 분리돼 FINANCE만 가진 직원도 접근 가능.
- `/mypage/payments`: 내 청구, 납부 안내/고정 규정, 신고, 수강취소·환불신청, 산정/승인/실지급 상태와 이력.
- 기존 기수관리: 공개 전 유료 설정, 공개 후 읽기. 신청화면에 비용/환불 원문 확인. 나의 공간에 납부대기 링크. 사업단은 회계 원문 대신 신청·등록 상태만 본다.

## 검증

가상 승인 규정/조항·FINANCE+위임을 로컬에서만 생성한다. 실제 계좌·돈·문자 전송 없음. 역할 격리·직접 테이블/RPC 우회·자기승인·교차 기관/소유자·중복 원거래/배분·정원 경쟁·기한 경계·분할입금/부분환불·예약 한도·지급 불명/중복·부정 입력을 DB와 Auth로 확인한다. 기존 90개 회귀, 프로덕션 빌드, 로컬 DB advisors, 브라우저 학습자와 회계 흐름으로 검증한다.

참고: [Supabase Database Functions](https://supabase.com/docs/guides/database/functions). 실제 운영 규정·보유기간 확정, MFA/재인증, 배포와 은행 API 연결은 별도 운영 준비다.

# 운영결과보고서 원본 PDF·AI 가져오기 설계

2026-09-22 · anchor-operation-result-pdf-ai-import

## 원본 보관과 편집

이미 과정에 보관된 `result` PDF도 권한 검사를 거친 뒤 브라우저에서 다시 읽어, 파일을 재업로드하지 않고 가져올 수 있다.
같은 원본을 다시 선택하면 이미 초안에 반영한 사진은 중복 추가하지 않는다.

기존 `/api/course-reports/[id]/files`의 `result` PDF 보관을 재사용한다. 관리자가 편집 화면에서 PDF를 선택하면 파일 형식·크기·문서 상태를 확인하고 먼저 보관한다. 업로드 성공 시 원본 링크를 보여준다. PDF.js를 브라우저에서 사용해 텍스트와 페이지별 이미지 XObject를 추출한다. 사진은 캔버스에서 작게 압축해 `Content.photos`의 운영사진 칸에 추가한다. 최대 30장, 전체 콘텐츠 3MB 제한을 넘는 사진은 건너뛰고 몇 장을 가져왔는지 알린다. 사진의 날짜와 설명은 PDF 텍스트에서 확정적으로 확인되지 않으면 빈칸으로 둔다. 기존 사진은 유지하고 추가 여부를 사용자가 고른다.

## AI 제안

same-origin API가 세션·관리 권한·문서 상태를 검사하고 Supabase Edge Function에 PDF 추출 텍스트와 기존 과정명만 전달한다. Edge Function도 JWT와 `life_operation_context`의 manager 권한을 검증한다. 서버의 `OPENAI_API_KEY`만 사용해 Responses API `gpt-5.6-terra`로 구조화된 JSON 제안을 만든다. 시스템 지시는 PDF의 지시문을 데이터로 취급하고, 없는 사실·인원·성과를 만들어내지 않으며, 불확실한 숫자는 확인사항에만 남기도록 한다. 입력·출력 길이를 제한하고 학습자 개인정보·예산 필드는 AI 제안에서 제외한다. 원본의 회차별 강의 표가 명시되면 일정·강의주제·강사·시수도 후보로 제시한다. 사용자 화면은 필드별 제안·강의표·확인사항을 보여주고 선택한 제안만 초안에 반영한다. 자동 저장·자동 제출·자동 서명은 없다.

각 제안 필드와 강의표 행은 원본 PDF의 쪽수와 짧은 원문 인용을 함께 요구한다. 서버는 PDF에서 추출해 전달한 해당 쪽 텍스트에 인용이 실제로 있는지 확인하고, 확인된 근거만 화면에 전달한다. 근거가 없거나 일치하지 않는 제안은 자동 선택하지 않고 담당자에게 원본 대조가 필요하다고 표시한다. 강의표도 모든 행의 근거가 확인된 경우에만 기본 선택한다. AI 응답의 모델명을 화면에 명시한다. 키가 없거나 무효인 경우에는 원본 보관·사진 가져오기를 유지하고 키 설정 문제를 구분해 안내한다.

## 권한과 실패

업로드·AI 요청은 과정 관리자만 가능하고 SUBMITTED 문서는 변경하지 않는다. 입력 텍스트는 이 호출에서만 사용하고 별도 서버 로그에 남기지 않는다. AI 오류 시 원본 보관과 로컬 사진 추출은 유지되고 수동 편집은 가능하다. 업로드 뒤 AI 실패를 원본 저장 실패로 표시하지 않는다. 결과 초안의 예산과 서명은 가져오기 대상에서 제외한다.

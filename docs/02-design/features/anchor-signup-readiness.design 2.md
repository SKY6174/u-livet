# 공개 가입 준비 점검 설계

2026-09-19 · [계획](../../01-plan/features/anchor-signup-readiness.plan.md)

## 산출물과 경계

- `ops/signup-readiness.sql`: 고정 앵커 조직의 현재 유효 문안과 관리자 준비 상태를 집계한다. SELECT/CTE만 사용하고 개인정보 원문은 반환하지 않는다. Management API `read_only: true`로 각각 실행한다.
- `docs/operations/signup-opening.md`: 정책 등록, 최초 관리자 설정, 단계별 검증, 개방 순서.
- `docs/operations/privacy-review-template.md`: 구현에 근거한 가입 동의·처리방침 검토 틀. 확정되지 않은 기간·법적 근거·국외이전 조건은 표시한다.
- `ops/evidence/signup-opening/`: 실명 연락처를 반영한 비공개 검토본, 관찰 결과. Git 제외, 폴더 0700·파일 0600.
- `docs/03-analysis/anchor-signup-readiness.analysis.md`: 가입 개방의 미충족 사항과 이번 준비 작업의 완료 여부를 별도 기록한다.

## 읽기 점검

고정 조직은 `10000000-0000-4000-8000-000000000001`이다. 정책은 승인자·승인 시각, 현재 효력 기간, 승인 상태를 확인한다. 유효 ACCOUNT_PRIVACY가 0개이면 미등록, 2개 이상이면 중복 검토 대상이다. 문안의 법적 적정성이나 기관 결재는 SQL로 판정하지 않는다.

관리자 수는 활성 person + 연결된 Auth 계정 + 이메일 인증 완료 + 정지되지 않은 계정 + 현재 유효 역할을 모두 만족한 경우만 센다. SYSTEM_ADMIN과 COURSE_MANAGER는 각각 집계한다. 전자는 후자의 권한을 자동 포함하지 않는다. 검증된 TOTP factor가 있는 계정 수도 역할별로 표시하되, 실제 로그인 AAL2·최근 재인증 성공으로 오인하지 않는다.

가입 트리거와 정책 동결 트리거의 활성 상태도 확인한다. SQL 결과는 `REVIEW_REQUIRED` 또는 `DATABASE_PREREQUISITES_PRESENT`로만 표시한다. 전체 공개 가입 READY를 자동 선언하지 않는다. SMTP, Auth `disable_signup`, UI, 실수신, 문안 승인, 담당자 권한 승인 등은 별도 점검 항목이다.

## 최초 설정 순서

기관 문안 승인과 사용자 본인의 수집·이용 동의는 구분한다. `approved_by`는 Auth 계정이 아닌 `life_people`를 참조하므로 실재 승인자의 업무상 식별 행을 먼저 등록하는 절차를 사용할 수 있다. 이것은 관리자 로그인 계정이나 권한을 자동 생성하지 않는다.

계정 생성 트리거는 Admin API에서도 승인 문안과 본인 동의를 요구한다. 일반 초대 메일을 보내면 해결된다고 가정하지 않는다. 문안 승인 후 지정된 최초 담당자에게 실제 문안을 보여주고 본인 동의를 별도로 받은 뒤, 발송 대상·용도가 확정된 초기 계정 설정을 수행한다. 임의로 `privacy_accepted=true`나 `email_confirm=true`를 넣지 않는다. 메일 인증·비밀번호 본인 설정·MFA 이후 승인된 업무 역할을 부여하고 재로그인 검증한다. 전체 가입 개방은 마지막 단계다.

## 검토 문안

가입 화면의 현재 직접 수집 항목은 이름·이메일·비밀번호다. 동의 기록은 문안 ID·사용자 ID·동의 여부·시각·출처다. 학습·수납·강사·홍보·배지 공개 등 후속 기능의 처리 내용을 가입 동의에 무조건 묶지 않는다. 현재 `/privacy`와 가입 UI는 같은 ACCOUNT_PRIVACY 본문을 읽으므로 수집·이용 동의 절과 전체 처리 안내를 분명히 나누거나 후속 분리 구현을 해야 한다.

Supabase 운영 리전 도쿄와 Resend 도쿄 발송은 관찰 사실이다. 이것만으로 전체 처리 국가·지원 인력 접근·백업·서브프로세서 범위를 단정하지 않는다. 계약상 수탁자 명칭·이전 항목/시점/방법/국가/보유기간·적용 근거는 기관 확인표에 둔다.

## 검증

양 DB에서 SELECT가 동작하고 계정·정책·권한 변경 없이 0건/미충족을 표시해야 한다. 익명 API에서 개인정보 원문을 읽는 방식은 사용하지 않는다. 공개 가입 화면은 안내 및 disabled 버튼을 확인하고, 이전 SMTP/복구 검증을 증빙으로 연결한다. 로컬 문서 링크, 미확정 표시와 Git 제외 여부를 확인한다. 기관 결정이 남아 있으면 가입 완료나 법규 준수 완료로 보고하지 않는다.

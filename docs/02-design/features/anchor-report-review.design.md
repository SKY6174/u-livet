# 결과보고서 관리자 검토 - 설계

2026-09-19 · anchor-report-review

- `/admin/reports/preview`는 기존 관리자 layout과 `requireIdentity`를 사용하고 페이지에서도 COURSE_MANAGER 역할을 검사한다. MFA와 세션 검증을 우회하지 않는다.
- `document=all|result|attendance|completion|scholarships|teaching|fees`만 허용하며 임의 값은 404로 처리한다. 전체·개별 선택을 링크로 제공한다.
- `src/lib/reports/preview.ts`는 타입이 지정된 메모리 내 예시 Offering/ReportBundle을 구성한다. 과정명에 `[검토용 예시]`를 넣어 기존 Sheet가 모든 용지에 표시한다. 수강생·강사·출결·수료·금액은 가상이며 계좌·생년월일은 비워 둔다. 첨부 API나 업무 저장 API를 호출하지 않는다.
- 실제 `ReportDocuments`를 재사용해 검토본과 제출 양식의 구조가 일치하도록 한다. 기존 `PrintToolbar`에 검토용 모드를 추가해 관리 화면 복귀와 PDF 저장을 제공한다. 검토 모드에는 계좌 공개 링크를 제공하지 않는다.
- 관리자 첫 화면과 공통 메뉴에 검토 진입 링크를 넣는다. 검토 화면에서 결과보고서·장학금·강사료는 운영진 입력, 출석은 강사 입력, 수료는 최신 승인 연동, 날인부는 강사 제출·운영진 확인이라는 흐름을 안내한다.
- 기존 운영자 역할은 재사용한다. 본인 계정 설정이 끝나지 않은 후임자의 계정·동의·MFA를 대신 생성하지 않는다. 임시 운영 역할 회수는 후임자 인계 시 수행한다.

검증: 타입·린트·격리 빌드, 로컬 가상 운영자/강사/익명 요청의 접근 경계, 여섯 양식 선택 및 잘못된 쿼리, 브라우저 데스크톱·모바일과 인쇄 표시를 확인한다. 운영 과정 계수 0이 유지되는지 확인한다.

# 16개 과정 연간 일정·PDCA 신호등 설계

> Date: 2026-09-25 | Plan: `docs/01-plan/features/anchor-course-monitoring-pdca.plan.md`

## 데이터

- `life_course_guides`의 `year`, `sort_order`, `name`, `academy`, `period_label`, `offering_id`를 서버에서 읽는다. 2026년 16개가 기준 목록이다.
- `life_course_workspace()`의 과정별 실제 시작·종료일, 모집·수업·출결·수료 지표를 연결한다. `life_operation_list()`의 계획/결과 문서 상태도 연결한다.
- 새 `life_course_monitoring_plans`는 조직·안내 과정 기준 하나의 행을 갖는다. P 목표/완료, D 목표 시작/종료, C 목표/완료, A 목표/완료, 애로 표시/사유, 조치 기록, revision/수정시각을 저장한다.
- 읽기/저장은 권한 검사 RPC로 제한한다. 테이블 RLS를 활성화하고 클라이언트 역할에 직접 권한을 주지 않는다. 저장은 조직의 `COURSE_MANAGER`, 최근 MFA, 공개된 해당 연도 과정과 날짜 순서/문자 수를 확인한다.
- 편집되지 않은 D 기간은 공개 안내의 정확한 날짜 범위에 한해 참고 일정으로 표시한다. 운영 등록 기간은 실제 일정으로 표시하며 계획 기준과 혼동하지 않는다.

## 신호등 판정

1. 명시된 애로가 있으면 `애로`(빨강). 사유와 조치 기록을 필수로 한다.
2. P/D/C/A 목표일 중 필요한 날짜가 없으면 `계획전`(검정). 표시할 근거가 없는 상태를 정상으로 취급하지 않는다.
3. 오늘을 지난 P/C/A 목표일에 완료일이 없거나, 계획한 D 시작일까지 개설되지 않았거나, D 종료일을 넘었는데 수업 종료·결과 보고가 미완료이면 `지연`(노랑).
4. 그 외는 `정상`(초록). `DRAFT` 등 실제 운영 상태는 별도로 병기한다.

날짜 비교는 서울의 오늘 날짜(서버 제공)와 ISO 날짜 문자열을 사용한다. 동률은 기한 내로 본다. 지난 기한에 완료일이 기록되었더라도 목표일보다 늦으면 지연 근거로 표시한다. 직접 애로를 해제하면 재계산한다.

## 화면

- 상단 신호등 카드 4개는 현재 조직·연도 필터의 합계이며, 선택하면 해당 과정만 보여준다.
- 12개월 열의 연간 일정표에 해당 연도의 모든 과정을 행으로 고정하고, 예정 D 기간과 실제 D 기간을 다른 채도/테두리로 표시한다. P/C/A 기한은 월 안에 점으로 표기한다. 구체 일자는 툴팁과 상세에서 확인한다.
- 일정표 아래 과정별 PDCA 목록에서 현재 판정 근거, 단계별 예정·완료일, 운영 문서 상태, 기존 운영 지표를 표시한다.
- 과정 행의 ‘계획·기록 편집’에서 날짜와 애로/조치를 수정해 저장한다. 저장 성공/실패를 명시한다.
- 등록되지 않은 안내 과정은 과정 개설 화면으로, 등록 과정은 운영 화면으로 이동한다.
- 조회 실패는 빈 0건처럼 보이지 않게 오류 안내한다.

## 검증

- 16개와 미등록 과정 포함, 날짜 없는 안내 과정, 월 경계 일정, 상태 우선순위, 완료일 지연, 조직 필터, 저장 검증과 권한을 확인한다.

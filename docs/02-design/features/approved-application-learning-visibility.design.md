# 승인된 수강신청원서의 나의 학습 표시 설계

2026-10-07 · [계획](../../01-plan/features/approved-application-learning-visibility.plan.md)

## 데이터 경계

`getStudentLearning`에서 기존 `life_my_learning`과 별도로 인증 세션의 `life_my_learner_documents`를 병렬 조회한다. 반환형은 `LearnerDocumentRequest[] | null`이며 RPC 실패 시 `null`을 유지한다. 문서 배열은 `kind === 'APPLICATION'`으로 제한한다. 데이터는 서버에서 본인 범위 RPC로만 가져오고 서비스 키를 사용하지 않는다.

## 화면

- 상단 지표에 `승인된 원서` 건수를 추가한다. `APPROVED`와 `COMPLETED`만 센다. `나의 수업`은 실제 학습 RPC에서 도출한 현재 수업 수를 그대로 둔다.
- 기존 `신청 현황` 아래에 `수강신청원서 처리 현황`을 표시한다. 각 원서의 과정명, 상태, 접수일시, 공개된 최신 안내를 보여주고 전체 이력으로 이동할 수 있다.
- 승인된 원서에 대응하는 실제 활성 수강 등록이 없으면 `서류 승인`과 `수강 확정`이 다른 단계임을 안내한다. 과정 연결 ID가 없어도 문서 기록은 표시한다. 연결된 등록이 있으면 기존 강의실을 안내한다.
- 문서 RPC 오류 시 수치 대신 `—`와 조회 실패 안내를 표시한다.
- 관리자 서류 처리 화면에서 연결되지 않은 원서에는 수강 등록과 별도임을 보여준다.

## 검증

기존 학습 UI 검증에 승인 문서만 있는 상태와 실제 등록이 있는 상태를 추가한다. 수치와 설명이 서로 일치하는지 확인하고, 문서 RPC 실패·빈 목록을 구분한다. 운영 DB에는 자동 등록이나 자유 입력 과정명 연결을 수행하지 않는다.

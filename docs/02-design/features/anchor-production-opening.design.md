# 운영 계정 및 교육과정 개방 설계

2026-09-19 · `anchor-production-opening`

## 준비 자료

`docs/operations/production-course-opening.md`에 다음을 기록한다.

- 원본 PDF의 제목·SHA-256 및 기준일.
- 14개 과정의 원문 일정·정원·시수·계획상 시간 상태.
- 미래 일정 3개의 강의 장소·요일·시간과 누락된 모집 조건.
- 달력상 반복 횟수와 원문 시수의 차이. 휴강·휴게시간·추가 차시는 추정하지 않는다.
- 운영 계정의 비식별 상태와 실제 브라우저 검증 여부.
- 담당자·정책·개설·공개 순서의 실행 조건과 현재 보류 사유.

`ops/production-opening-check.sql`은 읽기 전용 집계만 반환한다. 계정 이메일·성명·비밀번호·MFA 비밀값·JWT·세션 식별자는 조회하지 않는다. 활성 역할은 활성 계정·조직과 연결해 계산한다.

## 운영 반영

### 담당자 확정 (2026-09-19)

사용자 지시: “기존 관리자 시범 담당 & 별도 담당자 지정”.

- 기존 운영 DB의 활성 SYSTEM_ADMIN 1명에게 해당 조직의 COURSE_MANAGER만 추가한다. 이메일 인증·정상 계정·자격 정책·검증된 TOTP를 사전 확인한다.
- 후보가 1명이 아니면 자동 선택하지 않는다. 현재 유효한 동일 역할이 있으면 중복 등록하지 않는다.
- 별도 담당자의 성명·로그인 이메일을 사용자에게 받아 지정했다. 해당 이메일의 운영 계정은 아직 없다. 식별 정보는 비공개 운영 자료와 해당 조직의 감사기록에만 보관한다.
- 계정이 없는 지정은 `COURSE_MANAGER_DESIGNATED` 감사기록과 `ACCOUNT_SETUP_PENDING` 상태로 남긴다. 가짜 Auth 계정이나 동의 기록을 만들지 않는다. 공개된 이메일 가입 경로에서 본인이 가입·인증·MFA를 완료한 뒤 확인된 계정에 권한을 연결한다.
- 별도 담당자 지정 후 시범 담당의 인계·역할 종료 여부를 확인한다. 종료일을 사용자 대신 확정하지 않고 감사기록에 시범 목적과 후속 담당자 지정 필요를 남긴다.
- 이 작업은 사용자가 승인한 운영 DB 관리 작업으로 실행하고 사용자 로그인이나 MFA 인증을 가장하지 않는다. 감사 actor는 null로 두고 사용자 지시·작업 경로를 details에 기록한다.
- 운영 역할 및 감사기록을 한 트랜잭션으로 반영한다. 역할 ID를 기준으로 회수할 수 있도록 비밀값 없는 부여 기록을 남긴다.

1. 과정 운영 담당자를 확인한다. 기존 SYSTEM_ADMIN은 COURSE_MANAGER를 포함하지 않으므로 담당자가 확정되면 해당 조직의 과정 운영 권한만 연결한다.
2. 확인된 모집기간·운영방식·정원·교육기간·장소·개요·교육내용으로 기존 `life_create_offering` 경로의 초안을 만든다. 입력에 필수인 모집기간을 채우기 위해 임의 날짜를 만들지 않는다.
3. 수강신청 및 수료 정책을 실제 확정 문안과 승인자에 연결한다. 유료라면 수강료·환불 규정과 납부 안내를 함께 확정한다.
4. 기존 `life_publish`의 권한·정책 검사를 거쳐 공개한다. 정책을 가상 승인하거나 공개 상태를 직접 수정해 검사를 건너뛰지 않는다.
5. 실제 운영 세션에서 MFA·역할·편성표·개설 과정을 확인하고, 공개 페이지에서 일정·정원·모집상태를 확인한다.

## 확인 경계

- 2026-09-19 이후 시작 예정인 과정 3개는 우선 검토 후보이며 자동 공개 대상은 아니다.
- PDF의 강사·보조강사·보조인력은 원문 자료다. 공개 동의나 계정 배정의 근거로 사용하지 않는다.
- PDF의 교내/교외 미기재와 스마트테크 세부 미기재를 보존한다.
- DB의 검증된 TOTP 행은 등록 상태의 근거이며 이번 배포에서 실제 AAL2 로그인을 했다는 증거는 아니다.
- 필요한 운영 조건이 미정이면 자료 준비·점검 결과만 커밋하고 개방 단계는 진행 중으로 유지한다.

## 검증

원본 해시 일치, 14개 중 과거 일정 10·진행 중 일정 1·미래 일정 3, 미래 일정 정원 43명·시수 110시간을 확인한다. SQL이 SELECT 집계뿐인지 검토하고 운영 DB에 실행한다. 변경이 문서와 읽기 전용 SQL뿐이면 앱 테스트·재배포는 반복하지 않는다.

# 주차권 운영 준비 안내 — 설계

> 2026-09-22 · Dynamic · [계획](../../01-plan/features/anchor-parking-readiness.plan.md)

## 화면·데이터 흐름

`/admin/parking`의 서버 컴포넌트가 이미 권한 검사 후 `life_parking_admin_context(year, center)`를 호출한다. 반환된 `offerings`에서 `center_code === null`인 과정을, `stock`에서 잔여 매수를 계산한다. 조회 연도를 기준으로 표시하며 센터 필터는 준비 현황 계산에 영향을 주지 않는다. 별도 API·DB 변경은 없다.

기존 오류·성공 메시지 아래에 운영 준비 영역을 둔다. 미지정 과정은 이름과 수를 표시하고 같은 화면의 `#parking-center-assignment`로 안내한다. 모든 센터의 재고가 0이면 `#parking-stock-receipt`를 가리킨다. 지정 승인자 이름·이메일은 기존 `centers` 응답을 사용한다. 계정 준비 상태는 확인 가능한 API가 없으므로 완료 여부를 추정하지 않고, 실제 로그인 가입·해당 조직의 관리자 역할·추가 인증이 필요하다는 조건만 표시한다. 구성원 관리 목록으로 연결하되, 수동 명부 입력만으로 로그인 계정이 생기지 않음을 명시한다.

## 변경 파일

- `src/app/admin/parking/page.tsx`: 데이터 계산, 준비 영역, 입력 폼 앵커.

## 검증

- 린트와 프로덕션 빌드.
- DB의 현행 미지정 과정과 재고 결과를 화면 계산에 대조.
- 앵커 위치와 운영 안내 문구를 코드에서 확인.

기존 접근 제어와 발급 RPC는 변경하지 않는다. 이메일을 새 경로에 공개하지 않으며, 준비 영역은 관리자 페이지에만 렌더링한다.

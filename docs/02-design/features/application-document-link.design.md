# Application document course link design

Plan: docs/01-plan/features/application-document-link.plan.md. Existing document, course-prefill, approved-learning and issue-124 management designs were read before implementation.

## Database and boundaries
- Add private staff link(r,f,expected_revision): canonical COURSE_MANAGER, recent security verification, same request/offering org, APPLICATION and non-rejected/non-cancelled request. Offering then request lock. Only null offering_id may be bound; same-ID retry is idempotent, a different existing ID is immutable. Keep course_name/PDF/current_note/decision unchanged; increment revision, append same-status public event and audit including offering ID. Allow linking a draft for preparatory administration, but do not admit a draft/archived/ended offering.
- Add private enrollment state(r) returning only related offering name/status/dates, actual application ID/status and active enrollment boolean. It is called only after owner/staff request authorization. Expose this per-document via existing owner/admin RPC response objects, without broad new table access.
- Add manager document offering choices(k org scope) returning ID/name/org/status/dates. Exclude ARCHIVED; retain drafts and explicit dates so staff can select knowingly. Public wrapper SECURITY INVOKER, private checked helper SECURITY DEFINER search_path=''.
- Add staff admit(r,expected_revision): approved/completed APPLICATION, linked offering, manager scope, current request revision. Require an existing life_application for the same person/offering with authoritative policy/consent evidence, and a valid published or recruitment-closed, unsealed, unexpired offering. Invoke existing private.review_application so free/paid capacities, reservations, invoices, audit and actual resulting status stay authoritative. Idempotent already accepted/pending payment. Never create a fake learner consent or force enrollment on a draft/archived/sealed course.
- Wrap existing decide_learner_document as a guarded extended path: require linkage before new APPLICATION approval; if eligible existing actual application is present and actor manages the offering, invoke admission in the same transaction. Other document decisions and optional-note behavior remain unchanged.
- Wrap existing submit_learner_document: when APPLICATION f is null, resolve only a unique same-org published guide exact normalized course title with an offering mapping. Preserve ambiguous/free names as unlinked for explicit staff selection. Resolve before calling the existing guarded implementation, retaining eligibility/PDF/idempotency validation. Existing guide-linked draft submission is validated in the server through a public guide mapping instead of requiring life_catalog publication.
- Migration backfill only unique published guide/title/org matches with a PUBLISHED/CLOSED, unsealed, non-expired offering for unlinked APPLICATION rows. Append same-status link event/audit; retain PDF/title/note/decision. This does not create a life_application/enrollment. The real legacy draft remains pending valid operational setup. Manual linking also rejects ended or archived offerings, while future drafts remain available for preparation.

## UI/actions
- Admin page fetches choices with existing document context. Unlinked APPLICATION rows have their own course-link form with request/revision/filters, explicit offering dates and status. Keep this form independent of note/state forms and usable on legacy approved requests. Once linked, show real offering/app/enrollment state and links to course management/application detail.
- Approved document with a pending eligible actual application shows 수강 등록 확정 button, using manager admit action; missing application shows learner application required, draft shows 모집 준비 중 and course-management link, active registration shows 수강 등록 완료, paid PENDING_PAYMENT shows 납부 대기. Same factual state is available in learner document/learning views, with existing /offerings/:id/apply consent flow when appropriate.
- New actions validate IDs/revision, use cookie-bound RPC, preserve filters and revalidate homepage/admin/documents/mypage/learning/application/learner lists. Never use service keys in application code.

## Validation
Dedicated local uc-life-issues only. Add real RPC/action/browser tests for backfill preserving originals, optional note and prior resolution behavior, linkage before approval, staff admission of actual consent-bearing application, capacity rollback, stale/idempotent behavior, denied cross-org/learner changes, and draft/archived/missing-application blocks. Production runtime verification reads aggregate/state metadata only; no PII or PDF contents in published evidence. Record migration and exact deployment. Actual registration of the user's legacy document depends on the requested confirmed offering/time/policy information.

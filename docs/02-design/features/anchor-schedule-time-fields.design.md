# 강의 일정 입력 구조 조정 설계

2026-09-23 · anchor-schedule-time-fields

## 데이터 구조

일정 행의 공통 열을 다음 순서로 정의한다.

1. `date`: 일자, `YYYY-MM-DD`
2. `startTime`: 시작시간, `HH:mm`
3. `endTime`: 종료시간, `HH:mm`
4. `topic`: 강의주제 및 내용
5. `instructor`: 주강사명
6. `hours`: 주강사 교육시간
7. `assistant`: 보조강사명
8. `assistantHours`: 보조강사 교육시간
9. `location`: 교육장소

운영계획서 일정에는 뒤에 `mode`, `holiday`를 유지한다. `Field.type`에 `time`을 추가하고 클라이언트와 DB 모두 `HH:mm` 형식을 검증한다. 완료 제출에서는 날짜·시작시간·종료시간·주제·주강사·주강사 시간·장소를 필수로 검사하며 종료시간은 시작시간보다 늦어야 한다.

## 기존 데이터 이관

새 Supabase 마이그레이션에서 서버 스키마를 교체하고 수정 가능한 운영문서의 일정 행에 `startTime`, `endTime` 키를 추가한다. 기존 `date` 값에서 `YYYY.MM.DD` 또는 `YYYY-MM-DD`와 괄호 안 `HH:mm~HH:mm`을 추출한다. 파싱이 성공하면 ISO 날짜와 시간으로 분리하고, 실패하면 원문을 `date`에 남긴 채 시간은 빈 값으로 둔다. 이관 전후 행 수와 나머지 열은 유지한다. 불변 보관 원칙이 적용된 최종 제출 스냅샷은 DB 값을 수정하지 않고 조회·출력 시 같은 정규화 함수를 적용한다.

## 화면과 출력

- 편집기는 일자와 시작·종료시간을 날짜·시간 입력기로 표시한다.
- 각 일정 카드의 배치는 일자, 시작시간, 종료시간, 강의주제, 주강사명·시간, 보조강사명·시간, 장소 순서로 정렬한다.
- A4 표는 `일자`, `시간(시작~종료)`, `강의주제 및 내용`, `주강사(강사명/교육시간)`, `보조강사(강사명/교육시간)`, `교육장소`의 9개 실제 열을 사용한다.
- 신규 과정 세션은 서울 시간대의 날짜·시작·종료 시간을 각각 채운다.
- AI 가져오기도 세 필드를 분리하여 반환하며 근거 검증 절차는 유지한다.

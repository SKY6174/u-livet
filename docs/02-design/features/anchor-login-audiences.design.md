# 이용자별 로그인 설계

## 이메일 로그인 선택 버튼 (2026-09-20)
- 교외 강사·수강생 로그인은 카카오 → 네이버 → Google → 이메일(아이디)의 네 가지 선택지를 표시한다.
- 이메일 선택지는 Google 바로 아래 같은 높이의 버튼형 `<summary>`로 표시한다. 기본 접힘 상태의 `<details>`를 열면 기존 이메일·비밀번호·복구·가입 링크와 로그인 버튼이 나타난다. 접었다 열어도 입력값을 유지하고 키보드로 조작할 수 있다.
- 이메일 양식은 소셜 로그인 form 밖에 배치하여 중첩 form을 만들지 않는다. 서버 액션·복귀 주소·대상·보안 검증은 유지한다.
- 사업단·교내 강사, 검토 전용 화면과 이메일 회원가입 양식은 기존 직접 입력 방식을 유지한다.
- 네 가지 대상 화면, 모바일 가로 넘침, 키보드 펼치기/접기, 입력값 유지와 기존 로그인 검증을 확인한다.

## 화면과 서버
- `/auth/login?audience=office|internal|external|learner`: 네 개의 접근성 있는 버튼형 링크와 선택된 로그인 양식. 기본은 대상 선택 화면이다.
- 사업단·교내 강사 화면에서는 이메일/비밀번호만 제공한다. 교내 강사 이메일 도메인은 서버에서 검사한다. 교내 계정 안내에 학교 포털 비밀번호와 별개인 U-LIFE 암호 및 초대·설정 링크를 설명한다.
- 교외 강사·수강생은 공통 소셜 로그인 버튼과 기존 이메일 로그인. 카카오 활성, Google/custom:naver는 서버 설정 전까지 비활성 ‘준비 중’. 허용 제공자 고정 목록과 안전한 복귀 경로, PKCE, 요청 제한을 유지한다.
- 소셜 가입 문구는 제공자 공통으로 변경하되 현행 승인 동의문은 카카오 범위로 유지한다. Google/Naver 개방 전 승인 문안 개정이 필요하다.
- 로그인 후 서버가 실제 계정 분류와 역할을 검사한다. 선택한 버튼은 권한을 부여하지 않는다. 기본 업무 경로는 실제 역할로 결정하고, 사업단·교내 선택이 계정과 다르면 안내한다.

## 분류·권한
- 비공개 `account_classifications`에 사람별 사업단 직책(DIRECTOR/CENTER_HEAD/RESEARCHER), 강사 구분(INTERNAL/EXTERNAL)을 저장한다. 기존 역할 원장은 변경하지 않는다. SYSTEM_ADMIN + 최근 MFA를 통과한 관리 기능에서만 수정한다.
- 현재 강사 역할 계정은 인증 계정의 학교 이메일 여부를 기준으로 최초 분류를 고정한다. 이후 이메일 변경으로 분류를 자동 변경하지 않는다. 새 역할 부여 시에도 초기 분류를 기록한다.
- 사업단 역할을 가진 계정은 소셜 로그인을 허용하지 않는다. 교내 강사도 DB에서 학교 이메일·비밀번호 경로를 강제한다. 교외 강사와 수강생만 소셜 경로를 허용한다.
- 직책은 표시 정보이며 권한 부여에 사용하지 않는다. 송경영(kysong@uc.ac.kr)은 사용자 지정에 따라 단장으로 등록한다. 다른 계정의 직책은 관리자 화면에서 등록하며 이름만으로 추정하지 않는다.
- 본인의 로그인 분류 RPC는 유효한 native 세션에서만 반환하며 MFA 전에도 로그인 안내 용도로만 사용한다. 실제 identity와 업무 RPC의 기존 MFA/RLS는 유지한다.
- 소셜 가입은 기존 이름·휴대폰·동의 완료 후 person과 연결한다. 기존 초대 강사가 소셜 계정을 연결해도 person/역할/이력은 유지한다. 신규 소셜 가입으로 강사 권한이 생기지 않는다.

## 검증·배포
- 합성 SQL 테스트로 교외 OAuth 허용, 사업단/교내 OAuth 차단, 도메인·만료·직책/분류 수정 권한·MFA와 자기 권한 조작을 확인한다.
- 서버 동작 테스트로 네 가지 경로와 비활성 제공자, 허위 audience, 기존 가입·복구 흐름을 확인한다. 모바일/데스크톱 UI, lint/build와 DB advisor 확인 후 운영·스테이징에 동일 구현을 반영한다.
- 근거: Supabase Auth custom OAuth/Google 문서와 2026-09-20 changelog 확인. 네이버 사용자 정보의 중첩 응답은 제공자 설정/매핑 검증이 필요하며 키 없이 실인증을 완료했다고 표시하지 않는다.

## Google 개인정보 최소화와 문안 개정 (2026-09-20)
- 사용자 결정: 프로필 사진을 이용 항목에 포함하지 않는다. Google 요청을 `openid email`로 제한하며 이름은 기존 가입 양식에서 직접 입력받는다.
- Supabase의 `options.scopes`는 기본 `email profile`에 추가된다. 기존 카카오와 같이 고정된 `queryParams.scope`로 대체한다. 실제 Preview 인가 응답에서 `openid email`로 전달되는 것을 확인했다.
- 기존 Google 동의 범위가 새 요청에 합쳐지지 않도록 `include_granted_scopes=false`를 사용한다. PKCE/state 및 고정 callback, 이메일 확인·실제 역할 검사는 유지한다.
- 요청 축소만으로 기존 인증 메타데이터나 과거 토큰이 지워지지는 않는다. 재로그인 후 반환 항목과 잔존 사진 주소를 값 노출 없이 확인한 뒤 정리 범위를 결정한다. 검증 전 ‘사진 미수집 완료’라고 안내하지 않는다.
- ACCOUNT-2026-09-20-v3 초안은 Google 선택 로그인·교외 강사 범위, 휴대폰 미인증, 실제 해외 처리 위치를 반영한다. 사진 제외 문안은 축소 요청과 잔존 정보 정리가 확인된 뒤 적용한다.
- 기관 문안 승인과 이용자 동의는 별개다. 기존 승인 문안/동의 이벤트를 변경하지 않고, 승인 후 새 버전을 등록하고 가입 설정의 정책 참조를 교체한다.

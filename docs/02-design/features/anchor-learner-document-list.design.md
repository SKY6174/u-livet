# 접수 문서 리스트 화면 설계

## 범위
- `src/app/admin/learner-documents/page.tsx`의 접수 목록 표현만 교체한다.
- 기존 Server Component, 자료 조회와 서버 액션을 재사용한다. API·DB·인증 정책 변경 없음.

## 서류 종류 선택
- 기존 GET 조회 폼의 종류 select를 fieldset/legend로 묶은 버튼형 radio 4개로 바꾼다.
- 표시/값: 전체/빈 값, 수강신청/APPLICATION, 장학금신청/SCHOLARSHIP, 환불신청/REFUND.
- 선택된 항목은 청록 배경과 흰 글자로 강조하며 키보드 포커스를 명확히 표시한다.
- 기존과 같이 종류·처리 상태·검색어를 조합한 뒤 조회한다. 선택값은 종류 하나만 제출되며 검색창 Enter도 같은 조건을 유지한다.
- 데스크톱은 필터를 나란히 표시하고 좁은 화면에서는 종류 버튼이 줄바꿈된다. 추가 클라이언트 상태 없이 native radio를 사용한다.

## 9개 열
| 열 | 내용 |
|---|---|
| 순번 | 현재 조회 결과 순서대로 1부터 표시 |
| 과정 | 서류 종류와 과정명, 환불 문서는 기존 자동 산출 반환액 |
| 신청자 | 신청자 성명과 기존 `phone_masked`를 각각 표시 |
| 신청시각 | 기존 `documentDate`의 서울 시간대 표시, semantic time |
| 다음 처리 단계 | 해당 상태에서 허용되는 선택지, 종결 시 ‘처리 종결’ |
| 승인자 | 관리자 조회 RPC의 `reviewer_name`을 표시하고, 담당 처리 기록이 없으면 ‘—’로 표시 |
| 수강생 안내 내용 | 현재 공개 안내와 새 안내 입력란. 새 입력은 비워 두고 1,000자 이내 필수 유지 |
| 첨부문서 | 해당 요청 ID의 인증된 제출 원본 PDF 링크 |
| 비고 | 현재 상태, 행별 상태 저장 버튼, 접을 수 있는 처리 이력 |

## 폼과 접근성
- 유효한 table/thead/tbody/tr/th/td 구조. 열 헤더에 scope, 목록 caption 제공.
- 각 행의 비고 셀에 고유 ID의 form을 둔다. 다음 단계 select와 안내 textarea는 HTML `form` 속성으로 같은 행의 폼에 연결한다.
- 요청 ID, revision과 현재 세 필터는 해당 폼의 hidden input으로 제출한다. 다른 행의 입력은 포함하지 않는다.
- select/textarea에 행별 고유 label을 연결하고, 상태 저장 버튼은 현재 행 form의 submit이다.
- 종결 상태에는 편집 폼 없이 현재 안내·원본·이력만 표시한다.
- 처리 안내의 수강생 공개 및 최근 추가 인증 필요 문구는 목록 위에 공통으로 안내한다.

## 반응형과 검증
- 본문 폭을 최대 1,680px로 넓히고 승인자 열을 포함한 표는 최소 1,480px로 유지한다. 좁은 화면은 키보드 포커스 가능한 목록 영역 안에서 가로 스크롤한다.
- 긴 과정명·안내·처리 이력은 줄바꿈하고, 안내의 줄바꿈도 보존한다.
- 합성 데이터의 여러 행으로 열 순서, 행별 form 연결·필수값·필터·revision, 종결 상태, PDF 링크·이력 및 권한 없는 접근을 검증한다.
- 실제 페이지를 합성 데이터로 서버 렌더링한 로컬 화면에서 native FormData의 행별 격리와 데스크톱/모바일 가로 스크롤을 확인한다. 실제 접수 데이터는 변경하지 않는다.

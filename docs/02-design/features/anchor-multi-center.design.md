# 센터 공통 안내 및 문의 설계

## UI와 단일 데이터 원본
- `LOGIN_AUDIENCES.office.label`은 `사업단`으로 변경한다. 설명 `학교 이메일로 로그인`, audience 값, 인증·권한 판별은 유지한다.
- `src/lib/portal/contact.ts`의 `SUPPORT_CONTACTS` 배열에 센터명, 이름, 전화, 이메일, tel/mailto 링크를 RCC → AID-X → ECC 순서로 저장한다. 직위는 사용자 입력에 맞춰 생략한다.
- `SupportContact`는 `센터별 문의` 제목과 의미 있는 목록으로 세 센터를 표시한다. compact 모드는 하단용 줄바꿈 가능한 간결한 행, 기본 모드는 좁은 패널용 세로 배치이며 링크 터치 영역은 44px 이상이다.
- Footer는 두 열의 최소 폭을 0으로 허용하고 좁은 화면에서 세로 배치한다. 수강안내는 같은 구성요소를 사용해 연락처 중복을 제거한다. 로그인·복구·개인정보·강사 준비 문의는 기존 공통 구성요소를 통해 함께 갱신한다.

## 공통 플랫폼 표현
- 강사 화면의 RCC 연간 점검·배정 주체를 `운영센터`로 바꾼다. 기존 연간 자격 점검과 배정 절차는 보존한다.
- 사업 소개의 RCC 단독 역할 영역을 `함께 운영하는 평생직업교육`으로 교체한다. RCC센터·ECC센터·ICC센터·AID-X지원센터를 동등한 목록으로 표시하고 재직자 교육을 포함한 공동 활용 방향을 설명한다.
- 특정 센터의 역할을 다른 센터에 임의 배분하지 않는다. RCC 단독 역할 사진·설명은 이 공동 영역에서 제외한다. 4대 프로젝트와 사진·색상·사진 위 설명 패널은 유지한다.
- 공동 소개에 각 과정의 모집 안내와 운영 기준을 확인하도록 명시한다. 인증, 승인, 개인정보, 출결 및 수료 기준을 완화하는 코드·DB 변경은 없다.
- 과거 승인 정책 본문은 원문으로 보존한다. 최신 연락처는 페이지의 공통 센터별 문의에서 안내한다.

## 검증
- 로그인 네 대상·학교 이메일 안내, 세 센터의 이름·전화·이메일 및 링크를 로컬/배포 HTML에서 확인한다.
- 데스크톱과 390/320px 모바일에서 공통 하단 및 수강안내 문의가 넘치지 않는지 확인한다.
- 코드와 본 설계를 대조하고 lint·격리 production build 통과 후 main·preview push 및 배포 상태를 확인한다.

# 로그인 인증 코드 자동 확인 설계

2026-09-22 · [계획](../../01-plan/features/anchor-mfa-auto-submit.plan.md)

`MfaPanel`의 `returnToWork && !enrollment`일 때 로그인용 자동 확인을 활성화한다. 기존 인증 앱의 기본 선택과 `MfaCodeInput`의 숫자 정규화·선행 0·한 칸 수정·붙여넣기·one-time-code 지원을 유지한다.

## 입력 및 검증
- `MfaCodeInput`에 선택적 `autoFocus`를 전달한다. 실제 input ref를 사용해 최초 표시 및 pending 해제 시 포커스를 맞춘다. factorId를 key로 사용해 인증 앱 변경 시 입력과 포커스를 새로 시작한다.
- 코드 변경 이벤트가 전달한 최신 문자열이 정확히 숫자 6자리이면 기존 `verifyMfa`를 호출한다. effect로 검증을 반복하거나 DOM의 오래된 코드 값을 사용하지 않는다.
- 모든 MFA 작업은 동기적 ref 잠금과 기존 transition pending으로 중복 실행을 방지한다. 자동 확인 직후 Enter/확인 클릭도 두 번째 요청을 만들지 않는다.
- verify 실패·예외 시 코드를 비우고 기존 오류 메시지를 표시한다. pending 종료 후 입력 포커스를 복구한다. 자동 재시도하지 않는다.
- 성공 시 기존 서버 검증 응답에 따라 `router.replace(next)`를 사용한다. 6자리 형식 자체만으로 성공 처리하지 않는다.
- 수동 확인 버튼과 Enter 제출을 유지하고 최신 코드에 동일한 검증 함수를 사용한다. 새 인증 앱 등록·직접 보안 관리에는 자동 확인을 적용하지 않는다.
- 도움말에 6자리 입력 시 자동 확인됨을 안내한다. 코드/비밀키는 로그·URL·영속 저장소에 저장하지 않는다.

## 검증
실제 컴포넌트 이벤트 회귀로 입력 완성·중복 이벤트·비동기 실패·재입력·등록/관리 경계를 확인한다. 기존 서버 검증/리다이렉트 회귀도 실행한다. 실제 React를 사용하는 로컬 브라우저 fixture에서 자동 포커스, 키보드·붙여넣기, 성공 이동, 실패 재입력을 확인한다. fixture는 합성 코드와 응답만 사용하며 운영 인증 서비스에 요청하지 않는다.

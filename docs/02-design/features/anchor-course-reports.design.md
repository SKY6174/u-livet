# 과정별 운영 결과보고서 설계

## 기존 구조와 연결
Next.js Server Components + 사용자 세션 Supabase. `/admin/offerings/[id]/reports`가 관리 허브, `/admin/offerings/[id]/reports/print?document=…`가 인쇄 뷰다. 관리자 목록·과정 관리에서 접근한다. 기존 강사 출결 입력 및 수료 승인 RPC를 재사용한다.

## 6종
1. 결과보고서: 표지(연도, 영역, 과정, 담당교수, 담당자, 기간, 보고일), 주요 내용, 정원·등록·수료/비율·자격취득·취창업·만족도, 사진, 강사별 교육시간, 예산 신청/집행 합계, 품질개선(방법/내용/홍보/기타), 총평(우수/개선/환류), 장학금 요약.
2. 출석부: 과정·기간, 회차별 일정, 학습자별 인정시간/출석률. 미입력은 결석과 구분. 서명용 빈 시작/종료 칸도 제공. 최대 4회차씩, 인원도 분할한다.
3. 수료자명단: 학습자, 생년월일(운영진 보완), 총시간, 인정시간, 출석률, 수료 여부. ACTIVE + 최신 유효 승인만 수료로 표기한다.
4. 장학금 지급현황: 학습자, 생년월일, 수강료, 수료여부, 유형, 지급률, 금액, 은행/계좌/예금주, 지급일/비고.
5. 강사 강의날인부: 회차, 날짜/시간, 실강의시간, 강사, 본인 확인시각, 수기서명 칸. 로그인 확인을 수기서명 이미지로 대체하지 않는다.
6. 강사료 지급현황: 분야, 과정/기간, 내부/외부/보조, 이름/생년월일, 강의일자, 시수×단가, 은행/계좌/예금주, 지급일, 합계. 동일 강사 단가별 행을 허용한다.

## 데이터와 권한
- `life_course_reports`: offering PK, payload JSON(명시적 필드/배열), revision, updated_by/at. 새 초안은 저장 전임을 표시한다. 전체 문서 저장은 revision 비교 RPC로 처리한다.
- 기존 `life_teaching_logs` 및 submit_teaching/approve_teaching을 재사용한다. 강사가 종료된 수업의 실강의시간과 내용을 제출하고 운영진이 승인한다. 최신 승인 상태와 제출시각을 보고서에서 구분한다.
- `life_report_files`: PDF 6분류 각 1개 및 사진 최대 12개. 파일은 비공개 DB의 제한된 base64 본문(개별 4MB), 메타데이터 RPC와 인증된 HTTP 경로를 분리해 본문이 목록 응답에 섞이지 않도록 한다. 스토리지 서비스가 없는 현재 로컬 환경에서도 검증 가능하며 향후 object storage로 옮길 수 있다.
- 신규 public 테이블은 RLS + 최소 grant. 데이터 변경/읽기는 기존 방식대로 private definer + public invoker RPC, auth.uid/기관 역할/MFA 가드, 고정 search_path, PUBLIC/anon 실행 회수. 파일의 본문은 관리자만 읽는다.
- 보고서·지급내역·파일은 동일 기관 COURSE_MANAGER 전용. 강사에게 지급자료를 전달하지 않는다. 출결 저장은 기존 teaches 검사 유지.
- 원본 주민등록번호는 가져오지 않는다. 생년월일과 계좌를 입력 가능하게 하며 인쇄 기본은 계좌 마스킹, 별도 선택 시 관리자용 원문 인쇄. 금액은 실제 이체와 구분되는 운영 기록이다.
- 모든 금액은 원 정수, 시수/지급률 유한 범위, 날짜 형식 및 행 수 검증. 강사료는 시수×단가 원 미만 내림. 보고서 미작성은 0으로 오인시키지 않고 안내한다.

## 출력·검증
A4 가로 표 / 세로 결과보고서 및 날인부, 반복 표제, 표 행 쪼개짐 방지. 전체 출력은 문서별 페이지 구분. 서버에서 재조회하여 저장된 값만 출력한다. 브라우저 인쇄 PDF로 6개 파일을 각각 저장할 수 있다. 첨부는 자동 실행하지 않는 참고자료로 취급한다.
로컬 권한 테스트(관리자/배정강사/타기관/일반사용자), 저장·재조회·충돌·파일 검증, 빈 과정 및 많은 회차·행의 출력, 기존 회귀 체크와 lint/build를 실행한다.

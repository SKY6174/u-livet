# 관리자 출석부 준비 상태 설계

2026-09-21 · anchor-attendance-readiness

## 데이터와 권한
- 기존 `getManagedCourse`와 `life_course_workspace`의 조직·COURSE_MANAGER·MFA 경계를 유지한다. `instructors`, `enrolled`, `scheduled_sessions`, `ended_sessions`, `missing_attendance`만 사용한다.
- 준비 상태 계산은 순수 함수이며 DB·개인별 명단을 추가 조회하지 않는다. 원본 보고서 `source` 집계를 전산 등록자·회차로 사용하지 않는다.
- ARCHIVED는 준비 작업을 요구하지 않고 원본 첨부/보고서 보관을 안내한다. 실제 전산 자료가 있으면 기존 출결 집계를 계속 표시한다.

## 준비 상태와 다음 작업
- 기존 수업·출결 섹션을 준비 상태 카드로 교체. 활성 과정에는 배정 강사, 수강 확정자, 정상 수업 회차의 현재 건수·등록됨/등록 필요를 표시한다.
- 강사 배정과 수강 확정은 기존 관리자 설정·신청 앵커로 이동한다. 일정 등록은 담당 강사의 업무임을 설명하고 관리자에게는 강사 배정 확인 링크를 제공한다. 강사 권한 화면으로 관리자를 보내지 않는다.
- nextCourseAction 순서: 보관 → 개설 초안 → 신청 심사 → 강사 부족 → 수강 확정자 부족 → 일정 부족 → 종료 수업 미입력 → 전체 수업 종료 및 기간 종료 후 수료 검토 → 강의실적 승인 → 수업 진행 중 → 보고서.
- 다음 할 일은 업무 안내이며 개설 승인·계정 권한·수료 자격을 보장하지 않는다. 일부 자료가 있다는 것을 전체 시간표 검증 완료로 표시하지 않는다.
- 강사 일정 등록 설명에 시작~종료 전체가 교육시간으로 계산되므로 점심·휴게 구간을 제외해 나누어 등록하도록 안내한다. 등록 로직과 공식 출결 계산은 유지한다.

## 검증
- 준비 상태 8개 조합과 보관 과정, 원본 집계만 있는 과정, 신청/미입력/진행/수료/보고서 우선순위를 검사한다.
- 실제 컴포넌트 렌더링에서 0명/0회가 준비 완료로 표시되지 않으며 관리자 링크가 강사 권한 경로를 향하지 않는지 확인한다.
- 데이터 실패 시 기존 오류 화면 유지, 관리 개요의 기존 조회를 재사용하는지 검사한다. 역할 메뉴·출석부 UI·workspace 조회 회귀와 빌드를 실행한다.
- 브라우저 합성 데이터로 웹/모바일 준비 상태·보관 안내를 확인한다. 이후 main/preview push 및 배포/health 검증. 운영 데이터 변경 없음.

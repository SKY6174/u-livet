# 출결·시험·수료판정 상세설계

2026-09-19 · 전체 설계 D03 및 API13–18의 단계별 구현

## 데이터와 권한

- life_class_sessions: 기수·제목·시작/종료·SCHEDULED/CANCELLED·대체 원회차. 실제 시간(분)을 분모로 사용. 취소한 회차는 제외, 보강은 동일 기수의 취소 원회차에 연결한다.
- life_attendance: 회차·수강생·인정분·정정 사유·revision. 강사(담당 기수)만 입력. 종료 전 출결 입력 불가. 갱신 전후값·사유·수정자 감사기록. 수강생 본인 읽기만.
- life_quizzes: 기수·제목·공개기간·제한시간·문제/선택지. 객관식 단일선택 1–20문항, 동등배점, 한 번 응시. 등록 후 불변. 정답은 life_private.quiz_keys에만 저장.
- life_quiz_attempts: 시험·수강생 고유키, 시작·서버 종료시각, 문항 스냅샷, 임시답안, 제출시각·상태. 정답/원점수는 비공개 결과영역. 공개 조회는 응시기간 종료 후 결과만 반환. 마감 초과는 EXPIRED, 제출 재시도는 기존 결과. 임시저장 후 재접속 지원, 자동 채점. 타인의 답안 접근 차단.
- life_completion_rules: 승인된 COMPLETION 정책버전과 1:1 연결. 출석률, 개별 과제 최소점, 개별 시험 최소점은 각각 nullable(명시적 미적용). 적어도 하나의 기준 필요. 작성자와 승인자는 분리하고 승인 뒤 불변. 기관·정책 범위 검증. 정책 문안과 계산 규칙이 일치하는지 승인 화면에서 확인.
- life_offerings: academic_revision, academic_sealed 추가. 새 회차/시험/과제 또는 취소는 운영자료 마감을 해제. 공식 출결·제출·성적·응시·수강상태 변경은 revision 증가. 기수 행 잠금으로 계산·확정과 직렬화. 취소/삭제도 동일하게 추적.
- life_completion_runs: 수강등록·원자료 revision·판정·정책/규칙/출결/성적 스냅샷·산출자·시각. 산출 이력 불변.
- life_completion_approvals: 산출ID 고유키·승인자·시각. CERTIFIER만, 자기 산출/본인 수료 및 담당 강사의 자기 승인 금지. READY이고 현재 revision과 일치해야 확정. 원자료가 나중에 바뀌면 화면에서 재검토 필요로 표시. 발급에는 현재 유효한 승인만 사용할 수 있음.

## 판정 계약

과정 종료일(KST) 이후 + 운영자료 마감 + 승인된 규칙 필요. 모든 취소되지 않은 회차를 분모에 포함한다. 회차가 없거나 출결이 하나라도 없으면 출석률을 대체하지 않는다. 적용되는 과제/시험이 없거나 미제출·미채점·미응시이면 NEEDS_REVIEW. 미완료/미채점 사유를 먼저 판정하고, 모든 근거가 갖추어진 뒤 기준 미달은 INELIGIBLE, 전부 충족은 READY. 만료 시험은 검토 필요. 승인 정책의 현재 효력 및 기관 확인. 평균으로 낮은 필수 점수를 감추지 않고 각 항목별 기준을 적용한다.

원자료 snapshot에 회차ID/일정/인정분, 제출ID/revision/점수, 응시ID/상태/점수 및 계산 규칙을 남긴다. 하나의 학생 자료 변경도 기수 전체의 이전 산출을 무효화하는 보수적 방식이다. 향후 대규모 운영 시 학생별 revision으로 최적화 가능.

## 화면

- /instructor/offerings/[id]/evaluation: 회차·출결·정정, 시험 등록, 응시 현황.
- /learning/[id]/evaluation: 본인 공식 출결, 시험 시작/임시저장/제출, 종료 후 점수.
- /completion 및 /completion/[id]: COURSE_MANAGER 또는 CERTIFIER만 접근. 기준 작성/별도 승인, 운영자료 마감, 후보 산출/별도 확정.
- /mypage/history: 본인 최신 수료판정, 보완 사유, 현재 자료와의 일치 여부. 증명 발급 준비 문구 유지.

서버 액션은 세션검증 후 RPC를 호출한다. DB도 활성 역할·기관·담당기수·본인 여부를 재검증한다. public 테이블은 SELECT RLS, 쓰기는 RPC만. 정답/점수 내부표는 public 스키마에 두지 않는다. private definer + public invoker, search_path 고정, EXECUTE 최소화. 신규 source 파일마다 bkit 검사, SQL 재생·권한/경합 테스트·브라우저 흐름 검증 후 범위별 완료 보고.

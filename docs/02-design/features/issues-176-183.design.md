# Issues 176–183 상세설계

2026-10-17 · 계획: `docs/01-plan/features/issues-176-183.plan.md`

## 운영계획서 (#176–177)

기존 JSON 필드와 표 구조는 유지한다. plan의 program과 qualificationNote는 선택 필드로 남겨 과거 문서를 보존하며 편집·필수검사에서 제외한다. 프로그램은 영역·과정명과 중복되고 plan 출력에서 사용하지 않는다. 결과보고서의 program은 기존대로 유지한다. 발급기관은 기존 issuerInfo 문자열에 기관명·대표자·연락처·이메일·소재지·홈페이지를 이름 있는 줄로 직렬화하고 알 수 없는 이전 본문을 보존한다.

목적은 기존 목적 문자열을 다중 체크로 편집한다. 모집대상은 가로 표 한 곳에 9분류의 정수 인원과 자동 비율을 표시한다. 개별 인원은 모집정원 이하, 합계도 모집정원 이하로 검증하며 빈 초안은 허용한다. 중복 집계가 필요하면 실제 총인원으로 조정하도록 안내한다. 비율은 모집인원을 분모로 소수점 둘째 자리까지 계산하고 서버 모델에서도 같은 범위를 검사한다. 기존 비표준 모집 구분은 손실 없이 보이도록 유지한다.

국가·민간자격 표 다음에 발급기관 양식·환불규정을, 인력 표 다음에 비고를 표시한다. 시간은 HH:mm 24시간 텍스트 입력으로 바꿔 브라우저 오전·오후 부분 입력 문제를 제거한다. 기존 모델·DB의 역전 시간 차단을 재사용하고 즉시 인라인 오류도 표시한다.

예산 parser는 라벨 `강사1)` 등에서 항목 번호를 금액으로 해석하지 않도록 첫 산술 항으로 이어지는 숫자를 찾는다. 기존 BigInt 유리수·범위·전체식 검증을 유지한다. 산출내역 수정 시 매번 계산하고 실패 시 이전 금액 보존과 안내를 유지한다. 사용자의 예시 540000→544000 및 합계 회귀를 검증한다.

## 신청 (#178–179)

신규 원서는 offering 행 잠금 후 PUBLISHED·apply_from<=now<apply_until·교육시작 이전·미마감 여부를 검사한다. 동일 본인/과정의 취소·반려 이외 원서 중복은 거부한다. request_key 재시도는 원래 문서의 idempotency 검증을 그대로 수행한다. 서로 다른 request_key의 동시 제출은 offering 잠금으로 직렬화한다. 기존 일반 신청이 있는 경우 원서 1건 첨부는 허용하지만 원서를 다시 만들 수는 없다. 일반 신청 RPC는 동일 본인·과정의 한 행만 생성하고 재시도 시 기존 행을 재사용한다. 일반 신청의 모집·환불 동의와 PDF 원서는 각자 한 건을 연결하며 통합 조회에서는 하나의 과정 이력으로 표시한다.

서버 액션은 DB 공개 카탈로그의 실제 기간·상태로 동일 검사하고 공개 안내만 있는 DRAFT를 신규 접수로 인정하지 않는다. UI는 신청 가능한 과정만 활성화하고 이미 접수한 원서를 명확히 표시한다. 환불·장학 서류의 기존 자격 판정은 유지한다.

## 조회와 강사 (#180·183)

담당 범위의 일반 신청과 APPLICATION 원서를 통합한 내부 조회 함수를 공유한다. 동일 person/offering의 일반 신청과 원서는 1개 과정 이력으로 표시하며 원서 링크·상태를 함께 제공한다. 원서만 있는 신청도 수강생 목록·상세·신청내역에서 보이게 하고 필터/페이지/기관 권한을 유지한다. 서류 승인 자체를 수강 확정으로 표시하지 않는다. 미연결 과거 원서는 담당 기관 권한으로 포함하고 기존 연결·처리 화면으로 이동시킨다.

강사 대장의 활성 교내·교외 person도 배정 후보로 제공한다. 계정의 전체 INSTRUCTOR 역할을 자동 부여하지 않고, 배정·책임강사 후보 검사에서 해당 기관의 활성 대장 자격을 인정한다. 만료 역할·비활성 대장·타 기관은 제외하고 기존 책임강사 해제 보호를 유지한다. 실제 문서 접근은 기존 본인·기수 배정·MFA 경계를 유지한다.

## 수강료·메뉴 (#181–182)

운영관리의 과정별 관리 링크에 수강료·환불·강사·신청 목적을 명시하고 운영설정 상단 앵커를 제공한다. 수강료는 0원 포함, 미마감·미신청 과정의 DRAFT/PUBLISHED/CLOSED에서만 수정한다. 기존 신청·원서·청구가 있으면 기존 약정 보존을 위해 차단하고 구체적 사유를 보여준다. offering 행 잠금과 academic_revision 낙관잠금을 사용한다.

정책 관리에 REFUND 초안·새 버전·문안 검토·승인 및 명시적인 환불 계산 조항(라벨·기준·분자·분모)을 추가한다. 승인본과 기존 invoice의 정책·조항은 불변이며 변경은 새 버전을 만든다. 승인 시 조항을 함께 원자 저장한다. 수강료 설정에서 승인된 규정만 선택한다.

관리자 메뉴 검색은 권한으로 이미 걸러진 officeSections에서 label/description/분류를 즉시 검색한다. 키보드 방향키·Enter·Escape, 결과 없음, 모바일 너비를 지원하며 링크 선택으로 이동한다. 업무 홈과 상단 사업단 메뉴에서 같은 컴포넌트를 사용한다. 수강료·환불 규정 검색용 목적 링크도 추가한다.

## 검증과 릴리스

로컬 실제 PostgreSQL에서 원서 재시도·중복·기간·권한·조직범위·통합 목록·대장 강사·금액/규정 변경 제한을 검사하고 ROLLBACK한다. 기존 제출본을 수정하지 않는다. UI·PDF·계산과 모델 회귀, lint·type·build, 설계 대비 분석 후 운영 migration과 PR·push·merge·READY·version·health를 확인한다.

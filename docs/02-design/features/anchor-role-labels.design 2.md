# 사용자 역할 표시 상세설계

작성일: 2026-09-19. [계획](../../01-plan/features/anchor-role-labels.plan.md)을 따른다.

## 표시 규칙

`Header.tsx`가 RoleProvider의 검증된 identity.roles를 사용한다. 대표 역할 한 개를 이름 앞에 표시한다.

| 우선순위 | 실제 권한 | 표시 |
|---|---|---|
| 1 | SYSTEM_ADMIN | 관리자 |
| 2 | COURSE_MANAGER, FINANCE, CERTIFIER, PERFORMANCE 중 하나 이상 | 운영자 |
| 3 | INSTRUCTOR | 강사 |
| 4 | 위 권한 없음 | 수강생 |

비로그인 사용자는 기존 로그인 링크를 유지한다. 이름·직함·이메일은 권한 판단에 사용하지 않는다. 운영자는 업무 담당자를 묶는 화면용 이름이며 각각의 업무 권한을 합쳐 부여하지 않는다.

데스크톱 계정 영역과 모바일 메뉴의 로그아웃 앞에 동일한 역할·이름 요소를 배치한다. 역할은 읽을 수 있는 텍스트 배지로 표시하고 이름·기존 ‘님’ 호칭은 유지한다. CSS 색상만으로 역할을 구별하지 않는다.

DB·Auth·메뉴 접근 조건은 바꾸지 않는다. 담당자 계정은 실제로 승인·부여된 권한이 있을 때 표시가 적용된다.
검증: 동일 이름의 관리자·강사·수강생 구분, 네 운영 권한, 복수 권한 우선순위, 비로그인, 모바일 메뉴, lint·프로덕션 빌드. 실제 Header를 합성 신원으로 브라우저에서 렌더링하며 실사용자 세션이나 비밀번호는 사용하지 않는다.

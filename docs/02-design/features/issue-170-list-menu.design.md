# Issue 170: 과정 리스트 관리 메뉴 설계

2026-10-13 · 계획: `docs/01-plan/features/issue-170-list-menu.plan.md`

## 기존 계약

`anchor-course-operations-clarity.design.md`의 `/admin/courses` 카드/리스트 탐색과 `anchor-course-workspace.design.md`의 작업 공간 링크를 사용한다. 조회 데이터, 서버 권한, CourseActions의 조건과 목적지는 유지한다.

## 배치 수정

- `OperationsDashboard` 리스트 표의 마지막 머리글과 각 마지막 셀에 같은 너비 및 `sticky right-0`를 적용한다.
- 작은 화면은 240px, 640px 이상은 320px 너비를 사용한다. 기존 360px 최소 너비를 제거하여 모바일의 320px 안팎 목록 영역에도 관리 열이 들어가게 한다.
- 열의 불투명 배경과 왼쪽 경계선으로 스크롤되는 과정 정보가 버튼 뒤로 비치지 않게 한다. 머리글/셀의 z-index를 구분한다.
- 기존 CourseActions의 auto-fit grid가 좁은 열에서 한 열, 넓은 열에서 두 열로 배치된다. 전체 버튼의 한 줄 문구, 아이콘, 링크와 초점 표시를 보존한다.
- 작은 화면에서는 고정 관리 셀에 과정 이름도 표시한다. 메뉴가 원래 과정명 열을 가리는 폭에서도 어느 과정의 메뉴인지 구분할 수 있다.
- 표의 가로 스크롤·caption·머리글 scope·이름 있는 키보드 초점 영역을 보존한다. 카드형은 같은 CourseActions를 계속 사용한다.

## 검증

실제 컴포넌트를 합성 자료로 렌더링해 수정 전 버튼 클리핑을 측정한다. 수정 후 360/768/1440px의 스크롤 왼쪽/오른쪽에서 머리글·관리 셀·버튼 영역이 화면 및 셀 안에 드는지, 버튼 텍스트가 넘치지 않는지 확인한다. 개설 전/연결 과정의 전체 메뉴 및 관리자/조회 사용자, 카드/리스트 메뉴 링크를 대조한다. lint·타입 검사·빌드 및 운영 revision·health를 확인한다.

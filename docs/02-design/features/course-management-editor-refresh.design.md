# 과정 관리 입력 화면 개선 — Design

2026-10-07 · course-management-editor-refresh

## 데이터 계약

- 기존 `life_offerings.location` 문자열이 단일 출처다. 각 장소 행은 `교내 · 강의실(강의실명) · 비고` 또는 `교외 · 장소명 · 비고` 형식으로 한 줄에 직렬화한다. 비고가 없으면 마지막 부분을 생략한다. 최대 3줄·160자다. 가이드 동기화 트리거와 기존 조회 API를 그대로 쓴다. 기존 쉼표·줄바꿈 문자열은 행으로 파싱하되, 편집하지 않고 다른 필드만 저장하면 원문을 보존한다. 기존 `첫날`, `이후`, 날짜 접두어는 비고로 분리해 편집할 수 있게 한다.
- `life_course_versions.curriculum`은 기존 단일 문자열을 유지한다. `교육내용`, `교육대상`, `준비사항` 섹션 표제를 사용해 세 입력을 직렬화한다. 기존 `계획상 교육대상`도 대상으로 읽고, 모르는 문구는 교육내용에 남겨 정보 손실을 피한다. 편집하지 않으면 원문을 보존한다. 공개 상세에서는 파서 결과를 세 섹션으로 표시한다.
- DB 스키마·기존 RPC 인자·권한·optimistic revision은 변경하지 않는다. 서버의 길이 검증과 장소 유효성 검증은 유지한다.

## UI

- `CourseLocationFields`: 넓은 화면에서 번호·구분(select)·강의실/장소명·비고·삭제를 한 줄에 배치하고 모바일에서 순서대로 쌓는다. 필수 장소명과 선택 비고, 최대 3곳, 총 글자 수를 표시한다.
- `CourseCurriculumFields`: 교육내용·교육대상·준비사항을 각 textarea로 표시한다. 설명과 공개 안내의 구조를 일치시킨다.
- `OfferingEditForm`: 과정명/정원, 모집상태/선발방식/운영방식 한 줄, 접수 시작/마감, 교육 시작/종료 순서. 좁은 화면에서는 세 항목을 세로로 쌓는다. 과정 소개의 목적을 안내한다.
- `ResponsibleInstructorSection`: 기수 표현을 ‘이번 개설 과정’으로 고쳐 강사 배정 대상을 분명히 한다. `ActionForm`에 선택적 오른쪽 정렬을 제공해 관리 화면의 주요 녹색 저장 버튼을 오른쪽에 놓는다.
- 한 교육과정(`life_course_versions.course_id`)에 연결된 개설 과정이 실제로 2개 이상일 때에만 관리 화면에 운영 순서와 총 개설 횟수를 표시한다. 개설 이력 1개 또는 조회 실패 시에는 순서/기수 정보를 표시하지 않는다. 단순히 같은 과정명을 가진 별도 교육과정은 합치지 않는다.

## 검증

기존 장소와 교육본문 파싱·무수정 보존, 장소 행 추가·삭제·비고, 160자 제한, 내용 세 섹션 직렬화·재열기·공개 표시, 반응형, lint/tsc/build, PR Preview, 운영 배포/health 확인.

# 운영계획서에서 등록 양식 연결 설계

> 2026-09-19 · Feature: anchor-course-opening-prefill
> [계획](../../01-plan/features/anchor-course-opening-prefill.plan.md)

## 경로와 권한

각 개설 준비 카드에서 `/admin?plan=P01#offering-draft` 형태로 이동한다. P01~P16 원문 ID만 전달하며 인명·원천 JSON을 URL에 넣지 않는다.
관리자 페이지는 기존 requireIdentity/COURSE_MANAGER 검사 후 기존 server-only 계획서 loader를 호출한다.
plan이 없으면 수동 등록 화면, 존재하지 않는 값·빈 값·배열이면 notFound로 처리한다. 다른 query로 필드값을 주입하지 않는다.
원문 ID는 DB 과정 식별자로 사용하지 않는다. 페이지 조회/링크 클릭은 DB 쓰기를 실행하지 않는다.

## 데이터와 편집 폼

- `src/lib/course-opening/prefill.ts`: 타입만 가져오고 원문 ID 조회와 등록 기본값 변환을 제공한다.
- 기본값은 title/academy/capacity/location/summary/curriculum 6개뿐이다.
- curriculum은 계획서 교육내용과 계획상 대상 문구로 만들며 실제 지원자격 확인 안내를 포함한다.
- 날짜·사업연도·운영방식·선발·금액·강사/담당자 계정은 자동으로 확정하거나 배정하지 않는다.
- `OfferingDraftForm` Server Component로 기존 폼을 옮긴다. 기존 createOffering/action-form 경로를 유지한다.
- 불러온 경우 상세가 열리고, 편집 가능한 defaultValue를 사용한다. sourceId를 React key로 사용해 다른 계획서로 이동하면 이전 값·상태가 남지 않는다.
- 계획서 사용 시 사업연도/mode/selection_method는 빈 필수 선택값으로 시작한다. 수동 등록의 기존 기본 동작은 유지한다.
- 모집 시작·종료와 교육 시작·종료는 항상 빈 필수 입력이다. 저장 성공 시 기존 ActionForm reset 동작으로 이 필수값이 다시 비워진다.
- 기관·사업연도 목록은 기존 관리자 권한 조회 결과만 사용한다.

## 원문 확인 안내

폼 상단에 불러온 과정, 기본값의 성격, 아직 저장되지 않았다는 안내와 전체 계획서로 돌아가는 링크를 둔다.
원문 표제 기간·차시 날짜·시간·운영방식·시수, 최종 금액이 아닌 수강료 산식, 확인 사항을 접어 볼 수 있게 표시한다.
기존 저장 경로가 기수 초안을 무료로 생성한다는 점을 유지하며 계획서 산식과 최종 수강료가 다름을 설명한다.
유료 비용·정책은 기수 상세의 기존 승인 절차로 연결해야 한다. 새 금액 필드나 정책 승인 우회를 추가하지 않는다.
계획서 선택 해제 링크는 `/admin#offering-draft`로 이동한다.

## 검증

1. 16개 원천의 6개 기본값·입력 길이·내용이 일치하고 민감한 인명/원문 예산/잘못된 날짜를 등록 필드로 옮기지 않는다.
2. invalid/배열 ID를 거부하고 원천 객체를 변경하지 않는다.
3. 실제 폼 SSR에서 사업연도·방식·날짜의 빈 필수값, 편집 가능한 기본값, 출처 확인 링크를 검사한다.
4. 16개 카드의 등록 링크와 관리자 페이지의 선택/404/기존 저장 경로 연결을 검사한다.
5. 원문 오류(P05 월, P08 연도, P10 금액, P11 시수)는 안내에 남고 날짜·비용으로 자동 제출되지 않는다.
6. 기존 과정 검사·lint·앱 빌드·모바일 폼 표시·브라우저 필수값 검증을 실행한다. 실제 사용자의 로그인이나 DB 저장을 대신 수행하지 않는다.

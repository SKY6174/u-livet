# 사이트 운영 문구 정리 설계

계획: `docs/01-plan/features/site-operational-copy.plan.md`

1. 수료 상세는 DB `life_completion_board` 결과만 사용한다. `sample` 쿼리와 가상 행 생성·배너·진입 링크를 제거한다. 기존 역할/기관/자기 승인 방지 및 운영자료 마감 규칙은 그대로 적용한다. 등록자가 없으면 ‘수강등록된 학습자가 없습니다’와 수강 확정 후 표시됨을 안내한다. 기존 `anchor-completion-review-sample` 설계의 운영 화면 예시 제공을 이번 요청으로 대체한다.
2. `/admin/reports/preview`는 기존 COURSE_MANAGER 인증을 유지하면서 ‘결과보고서·증빙 안내’로 전환한다. 가상 번들·출석부·PDF 출력을 제거하고 실제 과정별 결과보고서/증빙 목록으로 연결한다. 여섯 문서의 실제 입력/확인 절차와 수료/출결·지급 근거 확인을 설명한다. 목록의 링크 이름도 안내로 바꾼다.
3. 학습자료/일정의 빈 상태는 ‘공개된 학습자료가 없습니다’/‘등록된 수업 일정이 없습니다’로 표현하고 담당 강사에게 문의할 수 있게 한다. 등록/인증/QR 서비스 이용 불가 안내는 구체적인 현재 상태와 다음 행동을 설명한다. 기능을 새로 활성화하거나 인증을 우회하지 않는다.
4. 수강안내의 증명·배지는 수료 상태, 발급 내역, 발급 가능 여부/절차를 안내한다. 발급권이 없는데 실제 발급을 보장하는 문구를 쓰지 않는다. DRAFT 모집 상태, 처리 중 표시, 관리자 필드 도움말은 그대로 유지한다.
5. 매뉴얼 1.3.1을 새로 발행하여 수료 화면의 예시 문구를 현재 실제 기록 확인 절차로 개정한다. 발행본 1.0.0~1.3.0과 해당 원본/해시를 변경하지 않는다.
6. 데이터/스키마 변경 없음. 명시적 합성 과정·신청 기록, 검증 정책 및 test_only 증명 경고는 사실성을 위해 보존한다. 실제 운영 문구로 위장하지 않는다.
7. 공개 HTML 감사에서 Issue124 검증 과정이 공개 목록·상세에 노출됨을 확인했다. 공개용 `getCourseCards`/`getCourseIntroduction` 쿼리는 이름이 `[검증용]`으로 시작하거나 아카데미에 `검증용`이 포함된 과정을 제외한다. 추천 수 제한 전 서버 쿼리에 적용하여 정상 과정이 밀려나지 않도록 한다. 관리자/학습 이력용 조회에는 적용하지 않는다. 공개 상세의 모집 정책도 기존 운영 정책 검사에 통과해야 표시/신청 진입이 가능하게 한다. 승인 규정을 바꾸지 않는다.
8. 새 매뉴얼은 버전 목록뿐 아니라 `src/lib/manuals/data.ts`의 명시적 원문 맵에도 등록한다. 구버전 링크는 보관본으로 계속 제공한다.

검증 기준:
- 공개 HTML 감사와 전체 소스 문구 분류. 과거 매뉴얼/검증 기록/오류 경고는 예외를 기록한다.
- eslint, TypeScript, 매뉴얼 검사/기존 검증을 통과한다. 새 테스트 파일은 단순 문구를 복제하지 않는다.
- 관리자 실제 수료 `?sample=1`에서 가상 행·링크·배너가 없고 실제 0명 상태를 보인다.
- 관리자 보고 안내에 가상 인원·금액·출력 UI가 없고 실제 보고서 목록으로 이동한다.
- 공개 수강안내 개정과 1.3.1 발행을 브라우저로 확인한다. 매뉴얼 PDF 개정 부분을 추출/렌더링해 확인한다.
- Preview/Production READY, 배포 커밋 일치, health 정상, 배포 후 runtime error/fatal 및 drain 상태를 확인한다.
- 운영 DB 12개 주요 테이블 count/hash 전후 동일성을 확인한다.

# 로그인 역할별 메뉴 상세설계

작성일: 2026-09-21. 계획: `docs/01-plan/features/anchor-role-navigation.plan.md`

## 권한과 상단 메뉴
- 서버가 검증한 identity.roles를 공통 메뉴 모델에 전달한다. 직책·이름·선택한 로그인 대상은 권한을 부여하지 않는다.
- SYSTEM_ADMIN/COURSE_MANAGER/FINANCE/CERTIFIER/PERFORMANCE는 관리자 유형이다. 직책이 있으면 관리자 · 단장/센터장/연구원으로 표시한다.
- 공통 안내 3개 다음에 관리자: 사업단 관리 + 내 정보, 강사: 강사 공간 + 내 정보, 수강생: 나의 학습을 표시한다. 실제 관리자+강사 복수 권한은 두 업무 공간을 제공한다.
- 수료·증명·재정·성과 메뉴는 사업단 관리 내부로 이동한다. 모바일과 데스크톱은 같은 메뉴 모델을 사용하며 활성 메뉴를 표시한다.

## 사업단 관리 구조
- `/admin`: 역할별 업무 홈. 과정 운영 / 결과 보고·수료 / 사업단 지원의 세 업무 그룹에서 허용된 항목만 표시한다.
- `/admin/courses`: 기존 과정 목록과 등록 양식. 모집·강사·출결 운영을 설명한다. 과정 현황·개설 준비·강사 심사·개발 심의·안내문자 링크 제공.
- `/admin/reports`: 과정별 결과보고서 현황과 검색·작성 전/보완 필요/내용 저장됨 필터. 개별 결과보고서 작성·검토·6종 출력으로 연결한다. 저장됨을 최종 승인으로 표시하지 않는다.
- `/completion`, `/credentials`: URL·권한을 유지하면서 사업단 하위 탐색 메뉴를 제공한다. `/finance`, `/performance`도 같은 탐색 구조로 연결한다.
- 지원 업무는 SYSTEM_ADMIN 계정 관리, FINANCE 수납·환불, COURSE_MANAGER 또는 PERFORMANCE 연차 평가·성과 관리이다.
- 관리자 공통 layout은 실제 사업단 역할을 요구한다. 기존에 layout의 COURSE_MANAGER 검사에 의존하던 하위 경로에는 과정담당 전용 layout을 유지하여 다른 관리자 역할에 데이터 접근을 넓히지 않는다. 계정 관리는 SYSTEM_ADMIN 전용이다.
- 기존 `/admin?plan=P01` 또는 `?create=1` 링크는 관리자 역할 검사 후 새 과정 운영 경로로 이전한다. 새 경로의 기존 계획 ID 검증·조직별 연도 조회는 유지한다.

## 개인 화면과 첫 화면
- 관리자 `/mypage`: 내 정보·연락처·보안·연결된 인증 앱 관리. 학습 신청 데이터는 조회하지 않는다.
- 강사 `/mypage`: 내 정보·강사 이력·심사·강의실적·연락처·보안. 학습 신청 데이터는 조회하지 않는다.
- 수강생 `/mypage`: 신청·강의실·수강이력·수료·증명·납부·배지·만족도. 강사 등록과 사업단 업무 메뉴는 표시하지 않는다.
- `/`의 안내 문구·주요 버튼·바로가기도 실제 유형에 맞춘다. 공개 교육과정 소개는 유지한다.
- 복수 권한 사용자의 우선 개인 유형은 관리자 > 강사 > 수강생이며 실제 강사 역할의 강의 운영 진입은 유지한다.

## 검증
- 모든 직책과 개별 역할, 복수 역할, 권한 없이 직책만 있는 계정, 비로그인에 대한 메뉴·개인 화면 검사.
- 관리자/강사 개인 화면에서 학습 데이터 미조회, 학습자의 기존 신청·취소·강의실 경로 유지.
- 각 업무 layout의 접근 거부와 기존 MFA/조직/역할 경계, 계획 불러오기 호환성 검사.
- 보고서 필터·링크 및 빈 결과/실패 구분, 활성 메뉴, 모바일/웹 가로 넘침 확인.
- 관련 회귀 테스트와 프로덕션 빌드 후 main/preview 원격 푸시.

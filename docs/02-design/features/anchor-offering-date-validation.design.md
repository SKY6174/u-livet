# 과정 등록 날짜 검증 설계

2026-09-24 · anchor-offering-date-validation

## 원인과 경계
운영 DB `life_offerings_check`는 `apply_until > apply_from`, `life_offerings_check1`은 `ends_on >= starts_on`을 요구한다. 최고관리자 권한은 정상이다. 등록 화면과 서버 액션에서 날짜 순서를 사전 검사하지 않아 DB 오류를 일반 메시지로 바꿔 보여주었다.

## 구현
- 기존 개설 입력 모델에 날짜 순서 검사 함수를 추가한다. 접수 마감이 시작과 같거나 빠르면 `apply_until`, 교육 종료가 시작보다 빠르면 `ends_on`을 오류 항목으로 반환한다.
- 계획서 불러오기 등록 폼은 실제 등록 클릭 시 필수값 확인 후 날짜 순서를 검사하고 해당 입력으로 초점을 옮기며 구체적 오류를 보여준다. 임시저장에서는 순서를 검사하지 않는다.
- 서버 `createOffering`도 RPC 호출 전에 같은 검사를 적용한다. 수동 등록과 우회 요청에도 동일하다. DB 제약 위반이 남아 있으면 해당 제약명을 정확한 메시지로 매핑한다.
- 필드 아래에 순서 규칙을 짧게 안내한다. 날짜를 임의 보정하거나 운영 데이터를 수정하지 않는다.

## 검증
- 동순서·역순서 접수일 및 역순서 교육일이 거부되고 올바른 순서는 통과한다.
- 등록 실패 시 입력이 유지되며 임시저장 흐름은 영향을 받지 않는다.
- 빌드·정적 검사와 preview/main 배포 상태를 확인한다.

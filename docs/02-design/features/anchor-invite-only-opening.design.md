# 초대 우선 계정 개방 설계

2026-09-19 · [계획](../../01-plan/features/anchor-invite-only-opening.plan.md)

`src/lib/auth/signup-config.ts`는 server-only 모듈이며 `AUTH_SIGNUP_ENABLED`가 정확히 `true`인 경우에만 공개 가입을 허용한다. 누락·공백·다른 값은 모두 차단한다. 로컬 환경도 명시적인 설정이 필요하다.

가입 `register` 액션은 입력 검증이나 외부 호출 전에 이 설정을 검사한다. 화면에서 폼을 숨기는 것만으로 보호하지 않는다. `AuthForm` signup 모드도 같은 함수를 사용해 비공개 초대 우선 단계의 안내를 표시한다. 기존 개인정보 정책·동의·이메일 준비·요청 제한·native Auth 검증은 유지한다.

로그인, 비밀번호 복구, 최초 초대 수락은 공개 가입 flag를 참조하지 않는다. 초대 발송 API를 새로 노출하지 않는다. Supabase 자체의 `disable_signup=true`도 유지한다.

`.env.example`과 운영 절차에 기본값 false 및 공개 개방/긴급 중단 순서를 기록한다. 양 Vercel 환경에 false를 명시하며 재배포 후 정책 유무와 무관하게 공개 입력/서버 호출이 차단되는지 확인한다. 향후 native 가입 허용과 앱 flag는 둘 다 개방 승인 후 변경해야 한다.

## 비공개 검토본

사용자가 확인한 보유기간과 해외 처리 기관 검토 상태, SYSTEM_ADMIN 단일 역할, 정확한 이메일·발신자·운영 도메인을 기록한다. 개인정보 계정 문안은 버전·본문 해시와 함께 동결할 수 있게 텍스트로 준비한다. 기관 확인과 본인 동의·메일 발송 요청은 서로 다른 필드로 보관한다. 공개에 필요하지 않은 개인 휴대전화는 문안에 넣지 않는다.

## 검증

정확한 true만 허용하는 설정 검사; 임의 form 값으로 차단 우회 불가; 차단 시 Supabase/정책 조회/요청 제한 호출 없음; 개방 후에도 유효 문안·동의·메일 조건 필요. 실제 사람의 이메일을 시험 데이터로 쓰지 않는다. 변경 파일 lint와 격리 빌드, 양 배포의 동일 버전·가입 화면·기존 로그인/초대 화면을 확인한다.

검토 문안의 승인이나 동의를 자동 생성하지 않는다. 최종 검토본을 제시한 후 실제 초대를 위한 명시적 본인 동의와 발송 요청을 받는다.

# 개설 준비 임시저장 설계

2026-09-21 · anchor-opening-working-copy

## 저장 범위·권한
- `life_opening_working_copies`: id, org_id, person_id, source_id(P01~P16), payload, revision, updated_at. (org_id, person_id, source_id) unique. 실제 offerings와 별도인 작성자 개인 준비 자료.
- RLS 활성, 직접 테이블 접근 권한 없음. 고정 search_path private definer와 public invoker 조회/저장 RPC만 사용한다.
- person_id는 인증 세션에서 결정. 해당 조직 COURSE_MANAGER 검사 및 기존 person_id/MFA 규칙 유지. 최근 MFA 쓰기 트리거를 새 테이블에도 적용.
- payload는 기존 등록 양식 13개 문자열 필드만 허용. 필드 길이·UUID·선택값·정원·실재 날짜/시각을 앱과 DB 양쪽에서 검증하되 빈 값은 허용한다. 임시 날짜 순서는 미완성 가능, 실제 등록 시 기존 제약을 적용한다. 사업연도가 있으면 해당 조직 소속을 검사한다.
- 저장은 작성자 행 잠금 후 expected_revision으로 비교한다. 최초 revision0, 갱신 시 +1. 충돌 시 덮어쓰지 않는다. 감사 이력에는 source/revision만 기록한다.

## UI와 데이터 흐름
- `/admin/courses?plan=Pxx`의 기존 권한 검사 후 해당 작성자 임시저장본을 조회한다. 읽기 오류는 명확히 표시하고 새 저장으로 덮어쓰지 못하도록 폼을 숨긴다. 계획서를 선택하지 않은 수동 등록은 기존 경로 유지.
- 6개 계획서 기본값에 저장된 13개 입력값을 적용한다. 저장본의 빈 값도 편집 결과로 보존하며 원문 기본값으로 다시 채우지 않는다.
- 계획서 양식 전용 클라이언트 wrapper에서 `개설 준비 임시저장`(formNoValidate)과 `실제 기수 초안 등록`(기존 required/서버 검증)을 구분한다. 실제 등록에는 기존 createOffering을 사용한다.
- 수동 dispatch로 실패 시 입력 초기화를 막는다. 저장 성공 시 revision·시각만 갱신하고 편집값 유지. 본인 계정 DB 보관·실제 개설 아님을 설명한다.
- 충돌/연결 실패 시 현재 입력 유지, 명시적 `저장본 다시 불러오기`는 같은 페이지 전체 재탐색으로 서버 저장값을 복원한다. MFA 오류 시 기존 추가 인증 안내 제공.
- 실제 기수 등록 성공 후 중복 클릭을 잠그고 과정 목록 링크를 표시한다. 준비 임시저장본은 별도로 유지된다는 점을 안내한다. 자동 삭제·공유·모집 공개 없음.

## 검증
- 실제 로컬 JWT로 미정 저장/복원, 작성자·조직·역할 격리, 직접 테이블/익명 거부, 잘못된 payload/source/year, stale 및 동시 편집, 감사·실제 offering 개수 불변 확인.
- 서버 액션·로더 경계, 저장본 빈 값 복원, 임시/실제 제출 분기, 입력 유지, 기존 16개 계획서·수동 등록 회귀 확인.
- 합성 UI에서 저장·새로고침·오류·실제 등록 필수값과 모바일 확인. 기존 보관3개·역할 정책 유지. 운영 DB에는 검증용 초안이나 개인정보를 저장하지 않는다.

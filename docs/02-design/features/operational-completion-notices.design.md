# 수료 안내 운영 문안 교정 설계

2026-10-17 · Feature `operational-completion-notices`
Plan: `docs/01-plan/features/operational-completion-notices.plan.md`

## 대상과 보존

산과 필라테스 `912a0200-12dc-4649-bd38-fb7c2ee2b9f5`의 기존 과정 버전
`999d8d43-5f3a-4c81-8825-20f00fc26fd4`와 검증 정책 원문은 보존한다.
동일 과정의 새 버전에 요약·교육내용·승인 상태를 복사하고 COMPLETION 연결만
같은 기관의 기존 승인 정책 `d4a18113-93f3-4f7e-8883-c6f1c22e8fab`로 교체한다.
정책 제목 `수료기준`, 버전 `2026-1`, 본문 ‘전체 과정 80% 이상 출석시 수료가능’의
SHA-256·유효일·승인 여부를 검사한다. 새 승인을 위조하거나 기존 승인을 변경하지 않는다.
운영계획서의 90% 대면 실습 비율을 수료 출석률로 해석하지 않는다.

대상 과정과 기존 연결을 잠그고 기관·이름·과정 ID·원래 버전·정책을 검증한다.
수료 산출 또는 수강 등록·확정 학사 상태가 생겼다면 자동 교정을 중단한다.
개발 제안서가 연결된 과정은 자동 교정하지 않는다. 새 버전은 max(version)+1이며
대상 offering만 새 버전을 참조하도록 변경하고 academic_revision을 1 올린다.
교정 감사 이벤트는 이전/새 과정 버전·정책·본문 해시·revision을 기록한다.
대상이 없는 Preview는 건너뛰고, 재실행은 이미 교정된 연결이면 건너뛴다.

## 재발 방지

수료 정책의 제목·버전·본문에 검증용/Issue숫자/dummy-숫자/fixture가 있거나
COMPLETION 기본 작성 요령 3줄만 있으면 공개 안내와 관리자 선택지에서 제외한다.
동일 검사를 private SECURITY INVOKER 트리거에서 적용한다. offering의 INSERT,
과정 버전 연결·이름·상태 변경과 참조 중인 course_version의 정책 변경을 보호한다.
이름이 `[검증용]`으로 시작하는 명시적 합성 과정은 허용하되 실제 과정명 변경은 검사한다.
offering 연결 검사 때 과정 버전을 FOR SHARE로 잠가 동시 정책 변경과 직렬화한다.
새 과정 버전이 아직 참조되지 않는 단계는 허용하며 실제 과정 연결 시 검사한다.
기존 모집 안내 필터·DB 보호는 유지한다. 수료 기준·규칙 승인·산출·확정 로직은 변경하지 않는다.

## 검증과 릴리스

로컬 합성 DB의 BEGIN/ROLLBACK 안에서 부재 Preview·잘못된 대상/원문/승인/연결,
새 버전 생성·재실행·공유 버전/과거 정책/신청/동의/수료 기록 보존을 검증한다.
제목·버전·본문·CRLF 작성 요령의 TS/SQL 분류 일치, 연결 insert/update/이름 변경,
기존 course_version 정책 update, 실제 publish RPC 성공/실패와 권한 노출 여부를 확인한다.
lint·형 검사·Preview를 통과한 코드를 PR로 병합한다. 운영 DB는 커밋된 SQL과 migration
ledger를 한 트랜잭션으로 적용하고 전후 해시·advisor를 비교한다. 공개 안내 16개와
공개 운영 상세 5개·관리자 수료 화면 및 정책 선택지를 확인하고 운영 배포 SHA·health를 검증한다.

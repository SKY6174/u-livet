# 수강생 마이페이지 학습이력 흐름 개선 설계

2026-09-27 · [계획](../../01-plan/features/anchor-learner-mypage-learning-history.plan.md)

## 화면과 문구

- `/mypage`의 기존 `#learning-record` 영역에 4단계 안내를 넣는다. 1단계는 `/mypage/history`의 본인 수강·수료 이력 확인과 국가 포털 등록 안내, 2단계는 국가 포털 연계동의, 3단계는 국가 포털 학습이력증명서 발급, 4단계는 국가 포털 학습이력철 발급이다.
- 1단계의 UC Life 기록과 국가 포털에 등록된 기록은 자동 동기화되었다고 주장하지 않는다. 3단계에서 UC Life의 사업단 이수증은 별도 링크와 명칭으로 구분한다.
- 외부 링크는 공식 루트 `https://www.all.go.kr/`를 사용하고 새 탭으로 열며, 로그인이 필요한 기능임을 안내한다. 기능별 내부 경로가 공개적으로 검증되지 않았으므로 임의의 딥링크를 만들지 않는다.
- 모바일은 단계 카드 한 열, 넓은 화면은 두 열 또는 네 열로 배치한다. 각 링크는 키보드 포커스와 44px 이상 터치 영역을 확보한다.

## 데이터와 권한

- 기존 `life_completion_history`를 그대로 사용한다. `/mypage/history`는 인증된 본인 RPC 결과로 전체·수료 확정·확인 중 수를 계산한다.
- 수료 확정은 `approved_at && !stale` 조건이다. stale, outcome, 미확정의 표시를 구분한다. 조회 오류 시 숫자와 목록을 감추고 재시도 링크를 제공한다.
- 외부 포털에는 데이터를 전송하지 않는다. 동의 상태나 발급 가능 여부를 UC Life가 추정하지 않는다.

## 검증

- 링크 및 문구의 내·외부 역할 구분, 이력 빈 상태·오류 상태·확정/재검토 상태를 확인한다.
- lint, TypeScript, production build. 가능하면 브라우저에서 데스크톱·모바일 배치를 확인한다.

# 이수증·강사 경력증명 구현 보고

2026-09-19 · anchor-certificates 완료 · 전체 플랫폼은 구현 단계 진행 중

수료가 확정된 수강생과 실제 강의실적이 승인된 강사가 증명을 신청하고, 위임받은 사업단 담당자가 승인하면 한글 PDF 원본을 생성하도록 연결했다. 원본 다운로드, QR 공개 검증, 파일 해시 대조, 취소와 정정 발급을 포함한다. 전용 로컬 환경에서 검증했으며 원격 DB 적용이나 배포는 하지 않았다.

## 이용 흐름

| 사용자 | 위치 | 할 수 있는 일 |
|---|---|---|
| 수강생·강사 | `/mypage/certificates` | 본인 증명 신청·상태·이력 조회 |
| 강사 | `/instructor/records` | 종료 회차 실제 강의시간/내용 제출·정정 |
| 과정담당 | `/credentials` | 강의실적 확인·승인 |
| 발급 위임자 | `/credentials` | 승인된 명의/서식으로 발급 승인·실패 재시도·취소 |
| 본인·인가 발급 위임자 | `/certificate/[id]` | PDF 원본 다운로드·해시 확인, 본인의 정정 신청 |
| 증명서 확인자 | `/verify` | 최소정보 진위 상태 조회·보관 원본과 파일 대조 |

강의경력은 예정 시간 대신 별도 승인된 실제 강의분을 합산한다. CERTIFIER 역할만으로 발급할 수 없으며 기관·문서종류·기간이 맞는 발급 위임이 필요하다. 자신의 강의실적과 자신의 증명 발급을 승인할 수 없다.

PDF 파일이 저장되기 전에는 발급 완료가 되지 않는다. 중복 승인과 재시도는 같은 건에 연결되고, 발급된 원본은 재다운로드해도 동일하다. 출결·성적·강의일지 등 근거가 변경되면 이전 증명은 재검토 상태가 되며 다운로드가 차단된다. 정정 발급은 새 번호를 부여하고 이전 원본에 대체 상태를 남긴다.

## 검증 결과

- DB/Auth/RPC 자동 검사 **90개 통과**: 기존 66개 회귀 + 증명 24개.
- 실제 HTTP 경계 검사 **4개 통과**: 과대/잘못된 본문, 정상 검증/보안 헤더, 비로그인 다운로드.
- 전체 14개 마이그레이션 로컬 재생, 린트·타입·프로덕션 빌드 성공.
- 로컬 DB 보안 점검 문제 0, 운영 의존성 audit 취약점 0.
- 브라우저에서 승인 후 PDF를 생성·다운로드하고 익명 상태 조회와 로컬 파일 해시 비교 성공.
- 두 종류 PDF 한글 렌더·텍스트·QR 확인, 390px 모바일 표시와 브라우저 오류 검사 통과.

## 운영 설정과 범위

실제 발급 전 D05 결정이 필요하다. 사업단장 직함/성명·발급기관·유효기간·승인 근거·직인 또는 승인된 생략 근거·담당자 위임·서식을 신뢰된 DB 관리 경로로 등록한다. 실제 설정을 기본값으로 넣지 않았다. 로컬 가상 발급권은 PDF와 화면에 검증용으로 명시되며 실제 사업단 증명으로 사용할 수 없다.

서버 전용 서비스 키와 고정 HTTPS 검증 주소가 필요하다. 비공개 DB 원본 저장은 최대 2MB이며 추후 대량 운영 시 파일 저장소로 이관할 수 있다. 한글 글꼴은 Nanum Gothic 전체 임베드이며 OFL을 함께 보관한다. 생성기는 [pdf-lib](https://pdf-lib.js.org/)를 사용한다.

QR 토큰은 fragment로 전달한 후 POST로 조회하고 주소에서 제거한다. 공개 조회는 마스킹 정보만 반환한다. 파일 대조는 이용자의 브라우저에서 수행하고 파일을 서버에 전송하지 않는다. 토큰별/전체 DB 제한과 앱 공유 제한을 사용하며 신뢰된 프록시를 명시한 배포에서만 앱 IP별 제한을 사용한다. QR·해시는 전자서명 인증이 아니다.

아직 남은 운영 준비는 공식 서식/직인 확정, 관리자 MFA·재인증, 보유/파기 작업, 백업/복구·부하 검증과 배포다. 디지털 배지, 자유 서식 편집, 직인 업로드 관리 UI는 이번 범위 밖이다.

다음 권장 구현 단위는 **수강료 입금 확인·환불 신청/승인·수납 이력**이다. 승인된 환불 규정과 수납 담당자 권한을 기준으로 설계한 뒤 연결한다.

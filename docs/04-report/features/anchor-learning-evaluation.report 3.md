# 출결·시험·수료판정 구현 보고

2026-09-19 · 홈페이지 내 기본 LMS의 두 번째 구현 범위 · 로컬 검증 완료

강사의 공식 출결·객관식 시험, 수강생 응시·결과 확인, 사업단의 수료 기준 승인·후보 산출·확정을 실제 DB 흐름으로 연결했다.

## 화면과 기능

| 사용자 | 경로 | 제공 기능 |
|---|---|---|
| 수강생 | `/learning/[id]/evaluation` | 공식 출결, 시험 시작·임시저장·재접속·최종제출, 시험 마감 후 점수 |
| 수강생 | `/mypage/history` | 본인 최신 수료 상태·보완 사유·확정일, 정정 후 재검토 표시 |
| 강사 | `/instructor/offerings/[id]/evaluation` | 수업·휴강·보강, 인정 출석분·정정 사유, 객관식 시험 등록·응시현황 |
| 과정담당 | `/completion/[id]` | 정책에 맞는 기준안, 전체 운영자료 마감, 근거별 수료 후보 산출 |
| 별도 승인자 | `/completion/[id]` | 기준 승인, 출결·과제·시험 근거 검토, 수료 확정 |

문항은 동일 배점의 단일선택, 1회 응시다. 문제와 종료시각은 시작할 때 고정한다. 자료 열람 표시는 공식 출석으로 계산하지 않는다. 출석 기준은 실제 회차 시간 대비 인정분, 과제·시험은 각 항목의 최소점이며 기본값을 넣지 않았다. 빈칸은 미적용이고, 최소 한 가지 기준과 별도 승인이 필요하다.

과정 종료 전, 필수 자료 없음, 출결 누락, 미제출·미채점·시험 미완료는 자동 수료되지 않는다. 산출 근거를 보존하고 이후 자료가 바뀌면 이전 결과를 확정할 수 없다. 이미 승인한 기록도 현재 자료와 달라지면 재검토 상태로 표시한다. 동일 자료를 다시 계산하는 것만으로 기존 승인이 사라지지 않는다.

## 보안과 데이터

추가 마이그레이션: `20260918153332_anchor_learning_evaluation.sql`. 출결·시험·응시·수료 규칙·산출·승인 테이블과 private 정답/결과 영역을 추가했다. 브라우저 직접 쓰기는 허용하지 않고 역할·기관·기수·본인 여부를 검증하는 RPC를 사용한다. 시험 원점수는 종료 전 학습자에게 보내지 않는다.

담당강사 자기 출결/과제 채점, 기준 작성자 자기승인, 산출자 자기 확정, 본인 수료 확정을 차단한다. 출결·성적 정정은 이전/변경 값과 actor를 남긴다. 수료 승인 권한은 CERTIFIER로 제한하며 이 권한만으로 증명서 직인·발급권이 생기지는 않는다.

## 실행과 다음 범위

`npm run dev:local`로 http://127.0.0.1:3100 에서 확인한다. 검증은 `npm run test:core` 다음 `node scripts/verify-learning.mjs`. 테스트 계정과 실행 방법은 저장소 README에 정리했다.

검증은 `uc-life-core` 전용 로컬 프로젝트에서만 진행했다. 원격 DB에는 적용하지 않았다. 화면의 [테스트] 과정·기준·확정은 검증자료이며 실제 사업단 수료나 증명 발급이 아니다.

기관의 실제 수료기준(D03), 발급권·전결·직인(D05)은 아직 확정되지 않았다. 영상/QR 출결, 재응시·서술형·가중배점, 문항 정정/대체, 증명서·디지털배지·강사경력 증명은 후속 범위다. 현재 문항 등록 후 수정 기능은 제공하지 않으며 운영 오류 정정 절차는 운영 공개 전에 확장해야 한다. 전체 플랫폼은 Do 진행 중이고 이번 범위만 완료했다.

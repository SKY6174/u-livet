# 인증 반복 요청·봇 방어 구현 보고

2026-09-19 · `anchor-auth-abuse` · 로컬 구현 및 검증

로그인·회원가입·비밀번호 복구 요청에 서버 요청 제한을 적용했다. 여러 서버에서 공유하는 DB 기록으로 제한하며, 브라우저 버튼을 조작하거나 전달 IP 헤더를 바꿔도 우회되지 않는다. 거절 시 대기 시간을 알려 주고 입력값을 유지한다.

## 이용자에게 달라지는 점

- 동일 이메일·접속망의 로그인은 5분당 8회까지 허용하며 계정 전체·접속망 전체 상한도 적용한다. 영구 계정 잠금은 아니다.
- 복구 메일은 같은 이메일에 60초 간격, 15분당 3회 제한. native Auth 직접 재발송도 60초 간격이다.
- 가입·복구 완료에도 별도 상한이 있다. 상한·기간은 [설계](../../02-design/features/anchor-auth-abuse.design.md)에 기록했다.
- 대기 초가 표시되고 시간이 지나면 버튼을 다시 누를 수 있다. 가입 여부·메일 제한 여부를 드러내지 않도록 복구 요청은 같은 안내를 반환한다.
- 보안 설정 또는 제한 저장소를 확인하지 못하면 인증을 진행하지 않고 쉬운 연결 안내를 제공한다.
- 기존 이메일 아이디, 12자 이상+영문·숫자·특수문자/대소문자 혼용 의무 없음, 비밀번호 보이기 및 조건 안내, 관리자 MFA를 유지한다.

## 봇 확인 연계

Turnstile 위젯과 Supabase native CAPTCHA 검증을 연결했다. 한국어 상태, 제출 전 확인, 실패·만료 시 재시도, 서버 응답 뒤 새 토큰을 제공한다. 앱은 비밀키로 토큰을 이중 소비하지 않으며 native Auth에서 검증한다.

공식 공개 테스트 키로 native API의 토큰 누락·실패 거부와 성공, 실제 브라우저 로그인→나의 공간 이동을 확인했다. 스크립트 네트워크 차단 시 안내·재시도 버튼이 나타나고, 차단 해제 후에는 입력값을 유지한 채 확인이 복구됨을 확인했다. **테스트 키는 실제 봇을 판별하지 않는다.** 기본 로컬 미리보기는 테스트 후 외부 CAPTCHA 미사용 설정으로 복원한다. 운영 키·허용 도메인·native CAPTCHA 활성화·개인정보 처리 문안은 운영 전 확정이 필요하다. 운영 환경의 설정 누락/테스트 키 사용 시 홈페이지 인증은 차단한다.

## 개인정보·운영 경계

제한 테이블에는 서버 HMAC 식별값과 요청 수·만료시각만 기록한다. 이메일/IP/비밀번호/복구 증명 원문은 저장하지 않는다. 익명·회원은 카운터 및 정리 RPC 권한이 없다. 승인된 프록시가 단일 IP를 덮어쓰는 경우에만 해당 헤더를 사용하며 기본은 공유 버킷이다.

실제 공용망 트래픽에 맞춘 임계값 조정, 원점 직접 접속 제한, WAF, 정리 스케줄/실패 감시는 운영 항목이다. 정리 RPC는 제공하지만 스케줄러를 설치하지 않았다. 미실행 시 만료 기록이 남는다. 키 교체 시 기존 제한 연속성이 끊기므로 사전 절차가 필요하다. 홈페이지 제한은 direct Auth 전체를 대신 보호하지 않으므로 native CAPTCHA와 native rate limit도 함께 검증해야 한다.

## 검증 결과

| 검증 | 이번 실행 |
|---|---:|
| 신규 DB·정책·동시성·권한 | 29개 통과 |
| 실제 홈페이지 HTTP 액션 | 11개 통과 |
| 장애 시 차단·native CAPTCHA | 9개 통과 |
| 기존 접근성 인증 | 21개 통과 |
| 기존 비밀번호 복구 | 18개 통과 |
| 기존 관리자 MFA | 32개 통과 |
| 합계 | **120개 통과** |

추가로 lint, TypeScript 포함 production build, DB 보안 점검, 22개 migration 이력과 shadow 재생 후 스키마 일치를 확인했다. 기존 341개 전체 업무 검사를 이번에 모두 다시 실행한 것은 아니다. 320px 모바일에서 가로 넘침 없이 입력 보존·제한 안내를 확인했다. 증거는 `evidence/abuse-*.txt`, `abuse-limited-mobile.png`, `abuse-captcha-mobile.png`에 있다.

## 실행 및 다음 단계

로컬 빌드: `node scripts/dev-local.mjs --build`

로컬 미리보기: `node scripts/dev-local.mjs --production`

검사: `verify-auth-abuse.mjs` → 미리보기 실행 상태에서 `verify-auth-abuse-http.mjs` → `verify-auth-abuse-guards.mjs`. 마지막 검사는 public CAPTCHA test key를 일시 적용하고 기본값을 복원한다. 실제 운영 데이터·원격 DB·배포 설정은 변경하지 않았다.

다음 단계는 운영 보안 설정 점검표와 배포 준비다. 운영 도메인/인증 배치, CAPTCHA 키, 승인된 SMTP, 프록시/정리 스케줄 및 MFA 분실 복구 절차를 준비한 뒤 승인된 환경에 적용한다.

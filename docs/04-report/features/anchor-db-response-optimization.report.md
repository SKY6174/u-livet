# DB 연동 및 응답 최적화 완료

2026-09-22 · anchor-db-response-optimization

## 변경 결과

강사·학습자 강의실이 현재 과정의 제출물·성적·읽음 기록만 DB에서 가져오도록 했다. 기존 로그인·배정·수강 검사와 RLS를 유지하며 5개 조회의 병렬 실행도 보존했다. 과정 관리의 예산·책임강사 목록은 현황 조회와 함께 시작하고 응답 후 조직 범위에 맞춰 합친다.

운영 DB는 정상 연결된다. 과정 4개·신청 2개·등록 2개를 확인했고, 공개 catalog 읽기는 200, 비로그인 제출물·성적 읽기는 401로 차단됐다. 운영 데이터와 계정 설정, 스키마·RLS는 수정하지 않았다.

## 성능 검증

로컬 합성 데이터에서 authenticated 역할과 실제 RLS를 적용한 동등 SQL 비교다. 5쌍 교차 실행 중 첫 쌍을 제외한 4회의 EXPLAIN ANALYZE 중앙값이며 운영 HTTP 개선율은 아니다.

| 조회 | 기존 → 개선 | 감소 |
| --- | ---: | ---: |
| 제출물 | 532.14 → 215.12ms | 59.6% |
| 성적 | 534.33 → 354.68ms | 33.6% |

필요 없는 2개 과정의 자료를 제외하여 결과는 30→10건으로 줄었다. SQL JSONB 텍스트 크기는 제출물 151,110→51,140B, 성적 28,980→10,650B였다. 미배정 과정 접근 차단과 전체 시험 자료 롤백도 확인했다. 실제 PostgREST 관계 필터 문법 및 권한 없는 빈 응답은 별도로 확인했다.

공개 경로는 변경 대상이 아니지만 배포 후 점검했다. 최초 측정과 배포 직후에 공통 지연이 달라져 이전·새 고정 배포를 같은 시간대에 경로당 각각 9회 번갈아 요청했다. 첫 요청 제외 중앙값/p95(ms):

| 경로 | 이전 배포 | 새 배포 |
| --- | ---: | ---: |
| DB health | 523.5 / 528 | 523.5 / 529 |
| 과정 목록 | 524 / 527 | 486 / 526 |
| 로그인 | 252 / 384 | 272.5 / 390 |

54회 모두 HTTP 200, health healthy였다. 공개 응답 개선은 입증하지 않았으며, 운영 계정의 로그인 후 전체 페이지 및 동시 부하는 측정하지 않았다. 과정 관리 병렬화는 실제 페이지 실행의 동시 시작 barrier 검사로 확인했다.

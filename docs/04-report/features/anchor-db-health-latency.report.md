# DB 연결·응답 점검 및 상태 확인 최적화

2026-09-27 · anchor-db-health-latency

운영·스테이징 Supabase의 읽기 연결이 정상이고 잠금 대기는 0건이었다. 운영 공개 경로의 기본 응답은 모두 정상이며, 가장 최근 운영 DB 목록·신원 조회 최적화는 양쪽 DB에 반영되어 있다.

상태 확인 API는 공개 테이블 `life_course_guides`에서 `id` 1건을 조회하도록 변경했다. 기존 `life_catalog` 복합 뷰보다 운영 누적 SQL 평균이 34.1ms → 0.5ms로 가볍다. 동일 클라이언트의 공개 REST 6쌍 비교 중앙값은 224.8ms → 135.0ms였으며, 이것은 API 쿼리 후보의 비교이지 배포 후 `/api/health` 전체 응답 개선율은 아니다.

응답 규격·RLS·데이터·스키마는 유지했다. lint, TypeScript, Next 프로덕션 빌드와 로컬 health 7/7 HTTP 200을 확인했다. [설계 비교와 측정 조건](../../03-analysis/anchor-db-health-latency.analysis.md)에 자세히 기록했다.

성능 advisor의 RLS 정책 관련 경고는 별도 보안 검증이 필요한 넓은 변경이다. 현 운영 DB는 표 규모가 작고 해당 경고가 이번 공개 상태 확인 지연을 일으킨다는 근거가 없어 일괄 변경하지 않았다. 인증된 관리자·강사·수강생 화면 전체 응답과 동시 부하는 계정 세션을 이용한 별도 측정이 필요하다.

# 성인학습자 친화적 인증 개선 결과

2026-09-19 · 로컬 구현. 사용자 결정: **12자 이상 + 영문·숫자·특수문자, 대소문자 구분 조건 없음**.

## 반영한 화면과 동작

- 로그인·회원가입 비밀번호에 눈 아이콘과 **보이기/숨기기** 버튼을 제공한다. 기본은 숨김이며 키보드로도 조작할 수 있다.
- 가입 시 **12자 이상 / 영문 / 숫자 / 특수문자**를 입력 아래에 표시한다. 충족하면 초록 체크로 바뀌며 조건 개수와 충족 문구를 함께 안내한다.
- 소문자만 또는 대문자만 사용해도 영문 조건을 만족한다. 공백을 특수문자로 세지 않는다. 붙여넣기와 자동완성을 막지 않는다.
-16px 안내,44px 높이 버튼, 넓은 가입/로그인 버튼과 이메일 아이디 안내를 적용했다. 강사·관리자는 기존 승인된 이메일 계정과 권한을 사용한다.
- 포털 가입·로그인 서버에서 같은 비밀번호 정책을 검사한다. 강사·관리자 권한은 가입 시 자동 부여하지 않는다.

## 적용 범위를 구분해야 하는 부분

로컬 인증 서비스의 최소 길이를6자에서12자로 높였으며 영문·숫자도 필수다. **인증 서비스 기본 설정에는 대소문자 혼합 없이 특수문자를 필수로 하는 조합이 없어, 직접 Auth API의 특수문자 강제는 남아 있다.** 포털 화면/서버 검사만으로 전체 경로가 완전히 통제되었다고 볼 수 없다. 운영 전 이 경로를 보완해야 한다.

기존 계정은 비밀번호 해시로 저장되어 길이를 일괄 읽을 수 없고 새 정책이 기존 비밀번호를 자동 무효화하지 않는다. 기존 강사·관리자의 비밀번호 재설정·세션 회수는 운영 이관 절차에서 완료해야 한다. 포털은 기준 미달 비밀번호 로그인을 차단하고 재설정을 안내한다. 현재 사용자용 복구 화면과 실제 SMTP는 아직 없다.

## 카카오·네이버·PASS 도입안

카카오·네이버는 학습자의 간편 로그인 수단, PASS는 필요한 단계의 본인확인·복구 수단으로 분리해 설계했다. 기존 학습 이력과 provider subject를 연결하며 성명/전화번호만으로 자동 병합하지 않는다. 앱/도메인·callback 등록, 업체 계약·심사·키와 동의 문안을 준비한 후 연동한다. 아직 실제 로그인 버튼이나 본인확인 호출을 제공하지 않는다.

상세 흐름과 DB 제안, 확인한 공식 자료는 [설계 문서](../../02-design/features/anchor-accessible-auth.design.md)에 있다.

## 검증과 확인 링크

신규 정책·로컬 Auth **21개**, 기존 핵심 흐름 **33개** 통과. 브라우저에서 가입·서버 거부·폼 초기화·실제 담당자 로그인·키보드·320/390px 화면을 확인했다. lint와 production build 통과, 결과는 증거 파일에 보존한다. dev 첫 방문의 일시적 조건 표시 오류는 분석 문서에 기록했다. 빌드된 앱에서 조건 표시·기준 미달 로그인 거부·실제 관리자 로그인을 별도로 검증했으며 오류가 없었다. 현재3100포트는 로컬 production build 미리보기다. 원격 Auth/DB 설정은 변경하지 않았고 배포하지 않았다.

# 관리자 추가 인증·최근 인증 구현 결과

2026-09-19 · `anchor-admin-mfa` · 로컬 구현

사업단 계정은 이메일·비밀번호 다음에 인증 앱의6자리 코드를 확인해야 업무 자료를 이용할 수 있다. 저장·승인 시 마지막 추가 인증으로부터15분이 지났다면 입력한 내용을 유지하고 새 창에서 다시 확인하도록 안내한다.

## 이용 방법

1. 관리자 계정으로 로그인하면 **인증 앱으로 한 번 더 확인해요** 화면으로 이동한다.
2. 첫 이용은 **인증 앱 연결하기**→앱에 QR 또는 설정 키 등록→6자리 코드 확인.
3. 이후에는 앱의 현재 코드를 입력한 뒤 **작업 화면으로 이동**한다.
4. 저장 중 인증 시간이 지났다면 **추가 인증하기 (새 창)**에서 확인하고 원래 화면의 저장 버튼을 다시 누른다.

[계정 보안 화면](http://127.0.0.1:3100/auth/security)은 나의 공간에서도 열 수 있다. 일반 수강생과 강사 단독 계정은 선택 사항이다. 사업단 과정·수납·증명·시스템·성과 역할은 필수다.

## 보안과 복구

현재 DB의 역할·활성 계정·유효 세션·검증된 인증 앱을 함께 확인한다. JWT의 AAL2 표시만으로 허용하지 않으며, 토큰 갱신만으로 최근 인증 시간을 연장하지 않는다. MFA를 통과해도 기존 기관 범위·업무 위임·자기승인 금지는 그대로 적용된다.

이메일로 비밀번호를 복구할 때도 MFA를 설정한 계정은6자리 코드가 필요하다. 새 비밀번호로 바꿔도 MFA 연결을 유지한다. 코드가 없거나 틀려 복구 링크를 사용했다면 새 메일을 요청하도록 안내한다.

관리자는 화면에서 마지막 인증 앱을 해제할 수 없다. 다른 기기에 앱을 추가한 후 교체한다. 앱 분실은 기관이 승인한 본인 확인·별도 승인·세션 회수·사건 기록 후 신뢰된 관리 경로로 처리하는 운영 절차다. 이메일만으로 자동 해제하지 않는다. 운영 담당자와 확인 기준은 기관의 확정이 필요하다.

## 적용 범위

전용 로컬 Supabase와 홈페이지에만 적용했다. 원격 운영 환경이나 실제 사용자 계정을 변경하지 않았다. 공급자 MFA 설정과 현재 비밀번호 정책을 먼저 확인한 뒤 migration을 배포해야 한다. 인증 앱 QR/키·코드는 업무 DB/브라우저 저장소에 복제하지 않고 native Auth가 관리한다.

native factor API에도 DB guard를 적용했다. 앱 추가/해제에는 사용자·세션·작업에 묶인1분 유효·일회용 변경 허가가 필요하며, 기존 MFA 계정은 최근 인증 없이는 이를 받을 수 없다. 관리자 마지막 factor 삭제도 DB에서 거부한다. 새 업무 테이블은 동일 guard 부착이 필요하며 Auth 버전 변경 때 session/factor/AMR 구조를 재검증한다.

다음 권장 단계는 **로그인·가입·복구 요청의 속도제한과 봇 방어 보완**이다. 운영 메일·모니터링·백업/복구·보유기간별 파기 및 사회관계망 로그인/본인확인 연계도 남아 있다.

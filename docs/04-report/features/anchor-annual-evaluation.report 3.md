# 연차 평가·성과 관리 구현 결과

2026-09-19 · 전용 로컬 환경 `uc-life-core`에서 구현·검증 완료. 원격 DB와 운영 사이트에는 적용하지 않았다.

## 사용 흐름

1. 사업단 관리 → **연차 평가·성과 관리**(`/performance`)에서 사업연도와 아카데미를 선택한다. 실인원·수강건수·수료건수와 원자료 재검토 항목을 구분한다.
2. 과정별 평가(`/quality/[id]`)에서 종강 후 승인된 조사정책을 선택해 개설한다. 수강생은 나의 공간 → 만족도 조사에서 선택 참여한다. 설문 미참여는 수료·증명 조건에 영향을 주지 않는다. 마감 후 사업단이 결과를 확정하고 승인 최소 응답수 이상일 때만 점수를 공개한다.
3. 강사는 배정된 과정의 개선 의견을 저장한다. 사업단은 당시 만족도·의견을 근거로 과정 검토 버전을 남긴다. 담당자에게 개선 과제를 부여하고 다음 기수의 반영 증빙을 다른 과정담당자가 확인한다.
4. PERFORMANCE 역할과 PREPARE 위임을 받은 담당자는 지표 정의·외부 실적·보고 초안을 등록한다. APPROVE 위임을 받은 별도 담당자가 정의와 보고를 승인한다. 작성·외부자료 입력자의 자기 승인은 금지한다.
5. 확정본은 당시 지표·산정 근거를 보존한다. 원자료가 바뀌면 재검토 표시를 하고 새 버전으로 정정한다. 인증된 담당자는 확정본 JSON을 내려받는다. 이는 등록 지표의 내부 확정본이며 전체 RISE 제출 완료를 뜻하지 않는다.

## 사업계획·기관 기준

C1 사업계획 인쇄 168~169쪽의 2차년도 목표는 참고표로 제공한다. 지원지수 목표와 제시 산식의 계산값이 달라 공식 복합지수 자동 계산은 제공하지 않는다. 지표 원자료가 없으면 미확인으로 표시하며 목표값을 실적으로 만들지 않는다.

기관의 공식 성과지표 산식·분모·중복 기준에 대한 추가 답변은 받지 못했다. 따라서 실제 기준 승인으로 처리하지 않았으며 등록·별도 승인 전 공식 확정을 제한한다. 조사 안내문, 개인정보 보유기간, 공개 최소응답수, 성과 담당자 위임도 실제 기관 승인이 필요하다. 코드에 있는 가상 검증 정책은 운영용이 아니다.

| lint / production build / diff whitespace | 통과 |
| 로컬 DB security advisor | warn 이상 없음 |

실제 Auth와 RPC를 사용해 교차기관 접근, 원답변 접근, 배정·위임 만료, 자기 승인, 잘못된 값, 동시 중복 보고, 변경된 원자료와 불변 확정본을 검사했다. 마감 결과 확정은 응답 처리와 같은 잠금을 사용하며 확정 후 점수와 건수가 달라지지 않는다. 미확인·재검토가 겹치는 등록 건은 공식 검토 건수에서 중복하지 않는다.

브라우저: 사업단 개설 → 수강생 응답 → 강사 의견 → 사업단 과정 검토 → 성과 초안 → 별도 승인 → JSON 다운로드를 확인했다. 다운로드는 정상 200/초안 409/수강생 404/익명 401, `private, no-store`. 모바일(390px) 설문·대시보드 가로 넘침 없음. 최종 확인한 역할별 브라우저 콘솔 오류 없음. 첫 dev 컴파일의 CSS 미적용은 새 탐색 후 정상 확인했다.

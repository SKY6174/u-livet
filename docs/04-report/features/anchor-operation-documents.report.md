# 운영계획서·운영결과보고서 완료 보고

2026-09-22 · feature: `anchor-operation-documents`

## 사용 순서

1. 관리자/담당자가 Office의 **운영계획서·결과보고서** 또는 과정 관리 탭으로 이동한다.
2. 해당 과정에 배정된 강사 중 책임강사를 지정한다. 필요한 강사는 기존 과정 관리에서 먼저 배정한다.
3. 책임강사는 My Room → 강의 운영 → **운영계획서·결과보고서**에서 본인의 과정 내용을 작성하고 임시저장한다.
4. 내용을 확인하고 **담당자 검토 요청**을 한다. 검토 중 강사 수정은 잠긴다.
5. 담당자가 모든 항목을 검토하고 예산계획 또는 예산집행·장학금을 완성하여 **최종 제출**한다.
6. 저장본 또는 이전 제출본을 A4 인쇄/PDF 다운로드한다. 보완이 필요하면 담당자가 사유를 적어 수정 재개 후 새 버전을 제출한다.

## 구현

- 첨부 공식 양식의 항목·표·사진·서명 영역을 웹 입력과 A4 출력으로 재현했다. 작성안내를 뺀 계획서는 기본 7쪽, 결과보고서는 기본 5쪽이다.
- 원본 PDF도 `/forms/operation-plan.pdf`, `/forms/operation-result.pdf`에서 열 수 있다.
- 계획서와 결과보고서는 과정 ID로 연결하며 기존 결과 집계, 보관 PDF, 출결·수료·지급 증빙 흐름을 유지한다.
- 계획 내용과 예산을 결과보고서 초기에 이어받는다. 강사의 첫 저장에서도 예산은 DB가 직접 복사하므로 강사에게 예산 수정 권한을 주지 않는다.
- Supabase 책임 지정·초안·최종 스냅샷 테이블과 기관/역할/MFA 기반 RPC를 적용했다. 제출본은 수정·삭제할 수 없고 재개 후 새 버전으로 남긴다.

## 검증

실제 로컬 Auth/PostgREST 권한·상태 전이 검증, 메뉴 19개, PDF 6개 검사 통과. 관리자 최종 제출 및 강사 모바일 저장·재접속·예산 읽기 제한 확인. 실제 A4 PDF 다운로드를 렌더링하여 구성 확인. Next 프로덕션 빌드·린트·타입 검사 통과.

운영 및 검증 Supabase에 `20260922074253_anchor_operation_documents`, `20260922081743_anchor_operation_budget_prefill` 적용. 운영 DB 보안 검사 WARN/ERROR 없음.

상세 증거와 기능 대조는 `docs/03-analysis/anchor-operation-documents.analysis.md`에 기록했다. 다음 운영 단계는 담당자의 실제 과정별 책임강사 지정 및 첫 제출본 검토다.

# 강사 출석부·개인 출석 확인 구현 보고

2026-09-21 · anchor-attendance-book

## 사용 흐름

- 강사: **강사 공간 → 담당 과정 → 출석부**. 수업/보강 일정을 추가하면 수강 확정 명단과 출석부가 구성된다. 종료된 수업을 선택하고 대상자·인정시간·확인 근거를 입력해 저장한다. 전원 선택은 미입력자 초안만 채우며 직접 저장해야 반영된다.
- 강사: **출석부 → 인쇄용 출석부**. 20명·6회차 단위로 분할해 출력한다. 브라우저 인쇄에서 A4 가로·배율 100%로 인쇄 또는 PDF 저장한다.
- 수강생: **나의 학습 → 나의 출석 확인** 또는 강의실의 출석 링크. 본인 수업별 내역·인정시간·미입력을 확인한다. 모든 종료 수업의 출결이 기록되기 전에는 출석률을 확정하지 않는다.

공식 출결은 기존 DB에 저장하고 기존 수료 검토·감사 이력과 연결한다. 타인의 개인 내역 조회, 본인 출결 기록, 미래/휴강 수업 기록을 허용하지 않는다. 관리자의 메뉴·인증과 기존 공개 과정 소개 카드 정책은 유지한다.

## 연동·성능

Preview/Production에 신규 조회 및 일괄 저장 함수를 적용하고 실행 권한·익명 차단·기존 데이터 보존을 확인했다. 두 환경 모두 현재 과정 3개이며 수업과 ACTIVE 등록자는 아직 없다.

1,402건 로컬 합성 출결 시험에서 조회 API를 6회에서 1회로 줄였다. 전체 자료를 가져오는 반복 응답 중앙값은 3,591.5ms에서 22.5ms, 전송량은 약 37.1% 감소했다. 이는 로컬 시험 결과이며 운영 응답속도 보장은 아니다. 1,000행 기본 제한으로 출석 기록이 누락되던 경로도 제거했다.

총 137개 자동 검증, 빌드, 모바일 UI와 저장 실패 재시도, 인쇄 배치 확인을 완료했다. 실제 과정에 수업 일정과 수강 확정자가 등록되면 해당 데이터로 출석부를 바로 사용할 수 있다.

상세 검증 및 측정 조건: [검증 보고](../../03-analysis/anchor-attendance-book.analysis.md).

## 실제 운영 등록 후속 점검

2026-09-21 사용자 후속 진행 요청으로 두 DB를 다시 대조했다. 기존 3개는 모두 결과보고서 보관 과정이며 유효 강사 배정·수업·ACTIVE 수강생은 각각 0건이다. 계획서 16개 전체의 최종 시간표와 휴게 구간, 계정·명단 연결 요건을 [출석부 운영 등록 준비표](../../operations/2026-attendance-rollout-readiness.md)에 정리했다. 최종 자료의 파일·폴더 경로를 요청했으며 실제 데이터 등록은 자료 확인 후 진행한다.

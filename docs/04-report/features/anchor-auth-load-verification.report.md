# 로그인·역할별 부하 검증 및 최적화 보고

2026-09-19 · anchor-auth-load-verification

로그인 후 세 역할의 실제 DB 화면을 측정하고, 전체 과정 읽기를 사용자별 관련 과정 조회로 줄였다. 학습자의 권한 없는 업무 경로에서 페이지 내용이 응답에 함께 생성되는 문제도 보완했다.

## 변경

- 학습자: 신청한 과정 ID만 조회.
- 강사: 유효하게 배정된 과정 ID만 조회.
- 운영자: 담당 사업단 org_id만 조회.
- 세 화면은 필요한 7개 필드만 받고, 빈 과정 범위는 DB 요청을 생략한다.
- 신청/배정/과정 읽기 실패를 정상적인 빈 화면으로 표시하지 않는다.
- 관리자·강사 진입 페이지가 조회 전에 역할을 검사한다.
- `npm run test:auth-load`를 추가했다. 기존 로컬 합성 계정과 임시 프로덕션 빌드에서 로그인/MFA, 권한 차단, 동시 요청, 세션 격리를 재검증한다.

## 응답시간

로컬 동일 데이터, 각 조합 24회, 전체 본문 수신까지 측정한 중앙값이다.

| 화면 | 단일 요청 기존 → 개선 | 동시 요청 8개 기존 → 개선 |
|---|---:|---:|
| 학습자 | 4,129 → 365ms | 7,375 → 566ms |
| 강사 | 5,320 → 1,609ms | 8,185 → 2,443ms |
| 운영자 | 781 → 244ms | 1,210 → 379ms |

단일 요청 중앙값은 각각 91.2%, 69.8%, 68.8% 감소했다. 동시성 4, p95, 측정 방법은 [분석 문서](../../03-analysis/anchor-auth-load-verification.analysis.md)에 기록했다.

## 완료한 검증

- 3개 역할의 비밀번호 로그인/MFA와 실제 로그인 Server Action 성공.
- 역할별 페이지 216회 + 사용자 교차 페이지 24회: 오류 0건.
- 학습자의 관리자·강사 페이지: 404와 업무 내용 미포함 확인.
- 조회 범위·오류 처리 회귀검사 13개 통과.
- lint, TypeScript 검사, 프로덕션 빌드 통과.
- 이번 실행의 로그인 세션·서버·임시 빌드 정리 성공.

운영 DB는 점검 당시 업무 데이터가 없으므로 위 수치는 로컬 합성 데이터 결과다. 운영 체감 속도와 동시 사용자 수용량을 뜻하지 않는다. 운영 DB 데이터·RLS·스키마·인증 설정 변경 없이 앱 조회를 최적화했다. 강사 화면의 잔여 지연은 실제 데이터 준비 후 실행계획과 함께 재측정한다.

PDCA: plan → design → do → check → act → report. 설계 점검 16/16 충족. 다음 단계는 실제 과정·신청이 준비된 환경에서 역할별 재측정이다.

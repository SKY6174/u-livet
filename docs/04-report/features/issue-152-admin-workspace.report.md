# Issue 152 — 사업단 관리 빈 화면 수정 결과

작성일: 2026-10-10

## 원인

신고 계정은 활성·이메일 인증·사업단 명부 등록·책임연구원 분류가 있었지만 유효한 업무 역할이 없었다. 명부 등록은 업무 홈 진입을 허용하지만 역할별 업무 메뉴를 부여하지 않는다. 업무 홈이 메뉴가 없는 상태를 설명하지 않아 빈 화면으로 보였다. 운영 DB에서 다른 사업단 계정에도 같은 권한 공백이 있음을 확인했다.

## 수정

- 업무 역할 없는 사업단 구성원에게 권한 미부여 이유·담당자 문의·새로고침 안내를 표시한다.
- 관리 화면의 로딩·접근 거부·조회 실패 및 재시도 안내를 추가한다.
- 기존 역할별 메뉴, 서버/RPC/조직 접근 경계, 요청 데이터 없음과 조회 실패의 구분을 유지한다.

## 운영 계정 처리

사용자는 신고 계정에 COURSE_MANAGER 역할을 선택한 뒤 다른 사업단 구성원에게도 같은 권한을 요청했다. 이에 운영의 해당 사업단 명부에 등록된 현재 활성 구성원 10명(신고 계정 포함)에게 COURSE_MANAGER를 부여했다. 기존 다른 역할은 보존했다.

역할 부여와 `ROLE_GRANTED` 감사 이벤트를 같은 DB 문장에서 적용했다. 재조회에서 대상 10명 모두 유효 역할 정확히 1개, 감사 이벤트 10개, 누락 0·중복 0을 확인했다. 다른 조직·강사·수강생과 미래 신규 구성원에게 자동 역할을 부여하는 규칙은 추가하지 않았다. 이메일·회원 ID·실제 인증 정보는 이 문서에 포함하지 않는다.

## 검증

역할 탐색·화면·접근 제어 회귀 27개, lint, TypeScript 검사, 매뉴얼 검사와 production build를 통과했다. 실제 운영 역할 조회와 합성 identity 기반 화면 검증을 수행했으며 실제 사용자 계정 브라우저 로그인 검증은 수행하지 않았다.

계획·설계·분석은 각각 `docs/01-plan/features/issue-152-admin-workspace.plan.md`, `docs/02-design/features/issue-152-admin-workspace.design.md`, `docs/03-analysis/issue-152-admin-workspace.analysis.md`에 기록했다. 배포 식별자·최종 커밋·운영 HTTP 확인 결과는 연결된 PR과 작업 응답에 기록한다.

# 안내문자 예약·동의 관리 구현 결과

2026-09-19 · anchor-messaging · 로컬 구현·검증 완료

## 사용 흐름

사업단 관리 → **안내문자 · 예약·처리 이력**에서 기수·승인 문안·예약시각을 선택한다. 문안, 종류, 대상 조건, 제외 사유, 마스킹 표본을 확인한 뒤 예약한다. 문안은 고정되고 대상 상태는 예약/처리 직전에 다시 확인한다.

나의 공간 → **연락처·홍보 수신 설정**에서 인증 연락처 상태와 SMS 홍보 원문을 확인한다. 선택동의는 수강/LMS 이용에 영향을 주지 않는다. 철회하면 대기 중 홍보 대상에서 즉시 제외하고 버전·시각을 남긴다. 연락처 연결 해제도 본인이 할 수 있다.

![관리자에서 홍보 철회 반영](assets/messaging-withdrawal.png)

## 구현 경계

- 실제 SMS 발송 업체·등록 발신번호·요금·위탁 조건이 확정되지 않아 **실제 문자 전송은 비활성**이다. 비용을 0원으로 추정하지 않는다.
- 연락처 입력/휴대전화 본인확인 연계는 아직 제공하지 않는다. 비공개 인증 참조/마스킹/유효기간을 사용하고 로컬 검증에만 가상 연락처를 등록했다.
- 기본 예약은 연결 대기다. 업체 연결 후 자동 전송되는 구조가 아니다. 설정은 DISABLED/TEST뿐이며 LIVE 값은 거부된다.
- 수동 로컬 처리기는 테스트 결과만 저장한다. 실제 공급자 발송·전달 증빙, 서명 callback, 자동 예약 실행, 결과 대사·재시도 UI는 후속 연계 범위다.
- 원격 DB와 실제 업체에는 변경하거나 발송하지 않았다. 기존 승인 기관 규정·실제 개인정보를 임의로 만들지 않았다.

## 데이터·보안

승인 문안, SMS 정책 지정, 기관별 홍보 설정과 동의 이벤트, 작업, 대상 스냅샷, 처리 이벤트를 분리했다. 인증 연락처는 비공개 스키마에 opaque 참조로 보관한다. 일반 브라우저의 직접 테이블 읽기/쓰기를 회수하고 고정 search_path 함수의 본인/기관 권한 검사만 허용한다. 화면과 로그에 실제 전화번호·공급자 참조를 반환하지 않는다.

중복 요청 키, 기관별 트랜잭션 잠금, 처리 lease/token을 적용했다. 만료된 처리 상태는 결과 확인 필요로 남아 자동으로 다시 처리하지 않는다. 개인정보 선택동의 철회, 계정 중지/인증 연결 삭제, 연락처 변경/만료, 등록취소, 담당자 권한 회수, 문안 중지를 처리 시점에 확인한다.

## 검증

| 검증 | 결과 |
|---|---|
| 기존 기본 신청·학습 | 33개 통과 |
| 출결·시험·수료 | 33개 통과 |
| 증명 | 24개 통과 |
| 수납·환불 | 37개 통과 |
| 문자 예약·동의 | 39개 통과 |
| 합계 | **166개 통과** |
| 로컬 수동 처리 CLI | 1건 가상 처리, 실제 문자 0건 |
| SQL 재생 | 전용 로컬 DB 16개 migration 적용 확인 |
| lint·프로덕션 빌드 | 통과 |
| Supabase 보안 advisors | 경고 이상 없음 |
| 브라우저 | 예약·철회 반영·취소·재동의, 모바일 390px 가로 넘침 없음 |

최종 함수 수정은 로컬 DB에 직접 반영하고 문자 검사 39개를 재실행했다. 최초 서버 전환 시 한 번 기록된 브라우저 오류는 새 세션에서 재현되지 않았고 최종 관리자/학습자 세션 오류 목록은 비어 있었다. 상세는 [설계 대비 분석](../../03-analysis/anchor-messaging.analysis.md)에 기록했다.

검증 로그는 `evidence/messaging-*.txt`, 화면은 `assets/messaging-withdrawal.png`, `assets/messaging-mobile.png`다. 테스트 정책·연락처·발신 내용은 운영에 이관하지 않는다.

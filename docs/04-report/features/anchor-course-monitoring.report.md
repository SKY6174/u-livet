# 과정 모니터링 구현 보고

> Date: 2026-09-24 | Feature: `anchor-course-monitoring`

## 결과

- `접수·운영` 첫 메뉴에 `과정 모니터링`을 추가했다.
- 담당 기관과 과정별 신청 대기·수강 확정·정원, 수업 회차, 출결 입력률·미입력, 강의일지 미확정, 수료 승인·검토를 한 화면에 표시한다.
- 조직·연도·상태·검색 필터, 주의 항목 우선 정렬, 업무 바로가기, 30초 갱신을 제공한다.
- 기존 관리자 집계 RPC와 MFA·조직 권한을 유지하고 화면에 필요한 숫자만 전달한다.
- 보관 과정의 원본 보고서 인원과 전산 인원, 출결 미입력과 결석을 명확히 구분한다.

## 검증

- `npm run lint`: 통과.
- `node scripts/verify-role-navigation.mjs`: 23개 통과. 운영문서 목록의 오래된 모의 데이터도 현재 조회 구조에 맞게 갱신했다.
- `node scripts/verify-course-monitoring.mjs`: 5개 통과.
- `npm run build`: 통과, `/admin/monitoring` 경로 생성 확인.
- `tsc --noEmit`, `git diff --check`: 통과.
- 운영·스테이징 Supabase 읽기 쿼리로 현재 등록 과정 수를 확인했다. 데이터 변경 없음.

## 운영 참고

운영 DB는 초안 13개와 보관 3개, 스테이징 DB는 보관 3개가 등록돼 있다. 따라서 화면의 과정 수는 환경별로 다르다. 화면의 `신청 대기·대기자`는 전체 신청 누적이 아니라 제출·대기 상태의 건수다.

# DB 연결 및 응답 개선 계획

2026-10-07 · db-connectivity-response-oct07

## 목적과 근거

운영 연결 상태를 검증하고 원서 처리 현황 조회의 반복 계산을 줄인다. 공개 경로 7회 측정에서 warm 중앙값은 health 189.5ms, 홈 208ms, 과정 목록 262ms, 로그인 146.5ms였다. 운영 누적 통계는 identity 1,699회/평균 83.50ms, operation list 227회/평균 448.01ms지만 과거 실행을 포함하므로 현재 성능 개선의 근거로 단독 사용하지 않는다.

실제 production RSC 실행에서는 같은 요청의 Auth HTTP 읽기가 이미 합쳐져 1회로 확인됐다. 최근 추가된 원서 현황 확장 함수는 문서마다 동일 기수의 권한과 같은 수강생/기수의 등록 상태를 반복 계산한다.

## 범위

- 현재 Auth 조회·검증과 middleware 갱신 절차를 유지한다.
- 원서 처리 현황은 기존 권한 검사로 승인된 문서 ID를 일괄 조회하고, 중복된 수강생/기수와 기수 권한 계산을 줄인다.
- 로컬 비교로 이득이 입증된 DB 변경만 migration에 포함한다.
- 운영 FK/과정·원서·신청·등록 연결, 함수/권한, migration 이력 및 서비스 응답을 읽기 전용으로 검사한다.
- 기존 데이터, 동의, 접수·승인·등록 규칙, 조직 접근 범위를 유지한다.

## 완료 기준

동일 native Auth 세션의 이전/개선 DB 응답 동등성, 비로그인/비담당자/기관 격리, 원서→PDF→접수 회귀, lint/build를 통과한다. PR push·merge와 운영 migration 및 정확한 main SHA의 Vercel production 배포를 완료한다. HTTP 측정과 SQL 내부 측정을 구분한다.

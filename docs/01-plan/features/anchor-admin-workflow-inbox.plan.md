# 관리자 업무 흐름·실시간 요청함 개선 계획

> Version: 1.0.0 | Date: 2026-09-23 | Status: Approved by user request
> Level: Dynamic

## 1. 목적

관리자 메뉴를 과정의 개설부터 접수, 운영, 마감, 정산까지 실제 업무 순서로 재구성한다. 업무 홈에서는 수강신청원서·장학금 지급신청서·수강료환불신청서의 미종결 요청을 한눈에 확인하고, 수료 검토 화면에서는 2026년 운영 대상 과정 전체를 확인할 수 있게 한다.

## 2. 범위

- 권한별 메뉴 링크와 URL은 유지하면서 업무 단계별 섹션과 표시 순서를 변경한다.
- 업무 홈에 조직 권한 범위의 미종결 수강생 요청 건수, 유형별 건수, 최근 요청을 표시한다.
- 접수 알림은 기존 보안 RPC와 MFA·조직 권한을 그대로 사용하며 주기적으로 새 데이터를 다시 불러온다.
- 수료 검토 목록은 DB 등록 과정과 2026년 원문 이관 대상 16개 과정을 병합한다.
- DB에 등록된 과정은 기존 수료 검토로 연결하고, 미등록 과정은 과정 등록 상태와 다음 동작을 명확히 표시한다.

## 3. 제외 범위

- 요청 제출이나 승인 상태 모델 변경
- 실시간 메시지 서버, 외부 알림 발송, 브라우저 푸시 알림
- 미등록 2026 과정의 자동 DB 생성
- 역할, RLS, MFA 및 기존 서버 권한 완화

## 4. 성공 기준

- 관리자 메뉴가 `기획·개설 → 접수·운영 → 마감·수료 → 정산·성과 → 계정·권한` 순으로 표시된다.
- 권한이 있는 관리자는 업무 홈에서 수강신청·장학금·환불 미종결 건수와 최근 요청을 확인하고 상세 문서함으로 이동할 수 있다.
- 알림 영역은 30초 간격으로 서버 데이터를 갱신하며 오류 시 다른 업무 카드는 계속 사용할 수 있다.
- 수료 검토 화면에 2026년 운영 대상 16개 과정과 추가 DB 과정이 누락 없이 표시된다.
- 미등록 과정은 검토 링크를 열지 않으며 담당 관리자에게 등록 경로를 제공한다.
- 기존 역할별 내비게이션, 서류 처리, 수료 검토 권한 검사가 유지된다.
- 린트, 역할 내비게이션 검사, 관련 데이터 검사, 프로덕션 빌드가 통과한다.

## 5. 위험과 대응

| 위험 | 대응 |
|---|---|
| 대시보드 새로고침으로 불필요한 DB 부하 발생 | 화면이 보일 때만 30초 간격으로 갱신하고 기존 최대 500건·인덱스 적용 RPC를 재사용한다. |
| 미등록 과정을 실제 수료 검토 가능 과정으로 오인 | `등록 필요` 상태와 비활성 검토 안내를 표시하고 과정 등록 링크를 분리한다. |
| 메뉴 재정렬로 권한 없는 링크 노출 | 기존 `hasRole` 조건을 유지하고 순서와 섹션만 변경한다. |
| 정적 원문 목록과 DB 과정 중복 | 기존 과정명 정규화 매칭 함수를 재사용하고 DB ID 기준으로 중복을 제거한다. |

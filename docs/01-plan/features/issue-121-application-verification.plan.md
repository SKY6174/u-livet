# Issue #121 수강신청 연결 검증 계획

2026-10-07 · https://github.com/SKY6174/u-livet/issues/121

목표는 수강생 화면의 실제 신청 제출 → `life_apply` → `life_applications` → 담당자의 `life_roster` → 관리자 신청 심사 화면이 같은 신청 건을 표시하는지 확인하는 것이다. 화면 전체 디자인은 #122에서 별도로 다룬다.

최신 main의 신청 서버 액션, 적용 가능한 전체 마이그레이션과 관리자 `/admin/offerings/[id]/manage`를 기준으로 한다. 기존 사용자 작업을 보존하기 위해 독립 worktree에서 작업한다.

- 기존 로컬 프로젝트와 운영 DB를 변경하지 않고 전용 로컬 Supabase를 사용한다.
- 가상 계정과 테스트 정책·과정만 생성한다. 운영 모집이나 정책 승인을 가장하지 않는다.
- 신청 전 0건, 제출 후 저장 ID·과정·수강생·시각·상태, 동의 기록, 담당자 RPC와 화면, 새 브라우저 세션 조회를 검증한다.
- 비담당자·수강생의 명단 조회 차단과 잘못된 정책·마감된 모집·중복 제출을 확인한다.
- 실패가 확인되면 해당 경로만 수정하고 재검증한다. 문제 없으면 근거와 재현 방법을 제출한다.
- 검증 기록과 개인정보 없는 관리자 화면 캡처를 커밋하고 PR로 제출한다.

완료 조건: DB와 UI의 동일 신청 건 확인, 새 조회의 유지 확인, 음성 경로 통과, 검증 명령과 환경·한계의 기록.

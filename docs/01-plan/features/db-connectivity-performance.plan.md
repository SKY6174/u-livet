# DB 연결·응답 최적화 계획

2026-10-08 · Dynamic · db-connectivity-performance

## 목적과 근거

- 운영 DB 연결, 공개 페이지와 권한 경계를 점검한다.
- `pg_stat_statements`에서 `life_operation_list()`는 256회 평균 400.55ms다. `/admin/courses`는 이 전체 목록에서 책임강사 이름만 사용하며, 같은 화면에서 이미 기관·연도 범위의 `life_course_budget_overview()`를 호출한다.
- 운영 `/api/health`, `/`, `/courses`, `/auth/login`은 5회 표본 모두 정상 응답했다. 첫 요청 제외 중앙값은 각각 375/356.5/413.5/248.5ms다.

## 범위와 성공 기준

1. 예산 개요 RPC가 같은 기관·연도의 개설 과정에 한해 현재 책임강사 이름을 반환한다. 기존 `course_budget_allowed` 권한 검사를 유지한다.
2. 관리자 과정 화면의 전체 운영문서 목록 RPC를 제거하고, 기존 예산 결과에서 이름을 읽는다. 현재 이름이 없을 때의 초기 지정 안내를 유지한다.
3. 서로 다른 기관의 이름을 노출하지 않는 회귀 검증과 DB 연결·기능·빌드 검사를 통과한다.
4. 변경 전후 응답을 가능한 동일 조건에서 측정하고, 표본 한계를 명시한다.

## 범위 밖

- 운영문서 목록 자체의 계약·권한 변경, 인증 사용자 간 캐시, 광범위한 인덱스 추가.

## 위험과 대응

- 개설 과정 연결이 없는 안내 행: `null`을 반환하고 기존 초기 지정 표시를 유지한다.
- 변경 배포 순서: 새 DB 필드를 먼저 배포하고 호환되는 앱을 배포한다. 기존 응답 필드는 유지한다.

# 관리자 MFA·최근 인증 계획

2026-09-19 · `anchor-admin-mfa`

이메일·비밀번호 이후 인증 앱의6자리 코드로 사업단 업무를 보호한다. Supabase native TOTP를 사용하며 직접 REST/RPC에서도 같은 접근 통제를 적용한다. 기존 비밀번호 정책과 학습 기록은 유지한다.

## 범위

- COURSE_MANAGER·FINANCE·CERTIFIER·SYSTEM_ADMIN·PERFORMANCE 활성 역할은 MFA 필수. INSTRUCTOR 단독·일반 수강생은 선택. MFA를 등록한 일반 사용자도 추가 인증 후 자료에 접근한다.
- `/auth/security`에서 첫 등록(QR/수동 키),6자리 코드 확인·재인증, 추가 인증 앱 등록·삭제. 관리자는 마지막 인증 앱을 화면에서 삭제하지 않는다.
- 관리자 읽기는 유효 AAL2, 관리자 계정이 수행하는 `life_` 업무 데이터 저장/승인은 최근15분 내 TOTP 확인 요구. 타임아웃 오류는 입력을 보존하고 새 창 추가 인증 후 다시 저장하도록 안내한다.
- 토큰 갱신 시각 대신 실제 TOTP 인증 시각을 검사한다. factor 해제·계정 차단·세션 회수·구정책 비밀번호도 기존 통제와 함께 검사한다.
- 인증 앱 분실은 승인된 신원 확인·별도 운영자 확인·세션 회수 뒤 신뢰된 관리 경로로만 처리하도록 절차를 문서화한다. 이메일 비밀번호 복구로 MFA를 자동 해제하지 않는다.
- 전용 로컬 Auth/DB55321/55322만 변경하고 가상 계정으로 검증한다. 원격 배포와 실제 문자·메일 발송은 하지 않는다.

## 완료 기준

MFA 미등록/비밀번호만 로그인한 관리자의 직접 자료 접근 거부, native 등록·오류 코드·코드 검증 후 접근 성공. 일반 학습자 미등록 접근 유지. 최근 인증 만료 후 저장 거부·재확인 후 성공·refresh 우회 거부. factor 해제·다른 계정/metadata 우회·비밀번호 복구에 의한 MFA 해제 방지. 기존 기능 회귀, DB 권한, lint/build 및 실제 브라우저·모바일 확인.

기본15분은 이번 구현의 보수적인 운영 설정이며 기관의 법정·승인 규정으로 표시하지 않는다. 운영 도입 때 인증 앱 사용 교육·지원 인력·분실 복구 승인자를 확정해야 한다.

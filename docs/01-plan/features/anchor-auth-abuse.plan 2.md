# 인증 반복 요청·봇 방어 계획

- 기능: `anchor-auth-abuse` / 2026-09-19 / Dynamic
- 선행: accessible-auth, auth-recovery, admin-mfa 완료.
- 목적: 로그인 추측, 무분별한 가입, 재설정 메일 폭주를 제한하면서 성인학습자가 입력 내용을 유지하고 다시 시도할 수 있게 한다.

## 범위와 완료 기준

1. 서버 인스턴스 간 공유되는 DB 제한. 익명 브라우저가 임의로 카운터를 변경하거나 우회하지 못한다.
2. 이메일·접속 주소·복구 토큰 원문을 제한 기록에 보관하지 않는다. 서버 HMAC 식별자, 요청 수, 만료 시각만 보관한다.
3. 로그인·가입·메일 요청·복구 완료의 서버 액션에 적용. 클라이언트 버튼 잠금만으로 보호하지 않는다.
4. 제한 시 대기 시간과 재시도 안내, 기존 입력 보존. 복구 메일 응답은 계정 존재 여부에 무관하다.
5. Supabase native CAPTCHA용 Turnstile 위젯·토큰 전달·실패/만료/재시도 처리. 운영 키가 없으므로 로컬 기본은 위젯 미사용, 운영 설정 누락은 인증 요청을 차단한다.
6. DB 권한, 동시 요청, 기간 만료, 위조 전달 헤더, 장애 시 차단, 인증 기존 흐름과 모바일 화면 검증.

## 경계

운영 배포·키 발급·외부 유료 계약·실제 메일 발송은 포함하지 않는다. native Auth 직접 호출에는 native rate limit/CAPTCHA가 필요하며 홈페이지 제한만으로 전체 경로를 보호했다고 표시하지 않는다. 원격 인증 설정을 검증하는 배포 점검 절차를 문서화한다.

## 위험 대응

- 학교 공용망: 계정별 제한과 네트워크 제한을 분리하고, 운영 트래픽을 확인한 뒤 임계값 조정.
- IP 위조: 임의 X-Forwarded-For를 신뢰하지 않음. 관리자가 지정한 프록시가 덮어쓰는 단일 IP 헤더만 허용. 미지정 환경은 보수적으로 공유 버킷.
- 계정 잠금 악용: 영구 잠금 없이 짧은 기간 제한. 거절된 시도로 만료시간 연장하지 않음.
- 장애·누락: 제한 저장소/필수 운영 설정을 확인하지 못하면 Auth 호출 전 중단.

## 검증

설계 대비 갭 분석, 전용 DB/API 회귀 검사, 기존 인증/MFA 회귀 검사, lint/build, 실제 브라우저에서 로그인·메일 요청·제한·입력 보존·모바일 검증. 변경 범위 밖 전체 업무 검사는 이전 341개 결과와 구분한다.

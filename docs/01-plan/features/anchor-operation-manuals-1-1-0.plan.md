## 1. Overview

### 1.1 Purpose

Update the eight audience-specific U-LIFE manuals from v1.0.0 to v1.1.0 so the web manual, Markdown downloads, and PDF distribution files describe the current product behavior.

### 1.2 Background

The v1.0.0 manual release is immutable and remains available at its fixed URLs. Since tag `manuals-v1.0.0`, the product added or changed learner document tabs, responsible instructor assignment, operation document menus, signed teaching and attendance evidence, budget approval order, PDF-assisted result drafting, schedule date/time fields, scholarship and attachment records, and 16:9 operation photo handling.

## 2. Goals

### 2.1 Primary Goals

- [x] Preserve every v1.0.0 source and distribution artifact without modification.
- [x] Publish v1.1.0 as the current release for all eight audiences.
- [x] Describe the new workflows in the audiences that perform or review them.
- [x] Produce and visually verify eight PDFs, eight Markdown files, one combined PDF, and a SHA-256 manifest.
- [x] Keep current-version redirects, version history, search, and old fixed URLs working.

### 2.2 Non-Goals

- Remote production deployment or notifying users.
- Claiming institutional approval or live-site validation.
- Changing the underlying operational workflows while documenting them.

## 3. Scope

### 3.1 In Scope

- New canonical source `src/content/manuals/1.1.0.json` and release-catalog registration.
- Current release loader registration and manual management documentation update.
- Procedure, checklist, FAQ, source reference, and change-log updates based on commits after `manuals-v1.0.0`.
- Versioned web pages and downloadable PDF/Markdown artifacts generated by the existing release pipeline.
- Integrity, text, build, route, PDF text, and rendered-page validation.

### 3.2 Out of Scope

- Screenshots containing live accounts or personal data.
- Changes to v1.0.0 files or its Git tag.
- Database migrations, API changes, and UI changes outside the manual release.

## 4. Success Criteria

- [x] `releases.json` and `MANUAL_RELEASES` contain 1.0.0 and 1.1.0, with 1.1.0 current.
- [x] Every changed workflow has a clear actor, entry point, ordered steps, completion check, and operational caution.
- [x] `npm run manuals:release`, `npm run manuals:check`, and `npm run test:manuals` pass.
- [x] Lint and production build pass without changing unrelated user files.
- [x] All generated PDFs render with readable Korean text, no clipping, and correct page numbering.
- [x] v1.0.0 hashes remain valid and v1.1.0 hashes match the new source and artifacts.

## 6. Risks & Mitigations

| Risk | Impact | Probability | Mitigation |
|---|---|---|---|
| A workflow is documented for the wrong role | High | Medium | Cross-check route guards, navigation, UI labels, design documents, and verification scripts. |
| Generated v1.1.0 artifacts omit source text | High | Low | Compare canonical JSON, generated Markdown, and extracted PDF text. |
| Old release is mutated | High | Low | Run immutable-release hash checks before and after generation. |
| PDF layout regresses as content grows | Medium | Medium | Render every page and inspect contact sheets plus page-level exceptions. |
| Source commit changes during authoring | Medium | Low | Record the verified HEAD used for the release and rerun the change audit before publication. |

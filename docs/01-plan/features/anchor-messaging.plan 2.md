# 안내문자 관리 계획

2026-09-19 · anchor-messaging · Dynamic

## 목적과 범위

전체 설계 A10, API22, T23을 바탕으로 사업단의 운영 안내/홍보 문자를 미리보기 → 예약 → 취소 → 처리 이력으로 연결한다. 홈페이지 내 기본 LMS 및 수납·환불 원장을 대상으로 사용한다.

이번 단위는 업체 독립적인 예약 관리와 동의 보호까지다. 실제 발송 업체·발신번호·요금·개인정보 위탁 조건은 미확정이다. 실제 SMS 네트워크 호출이나 자동 예약 실행은 제공하지 않는다. 미설정 상태에서 예약은 연결 대기로 보존하며 실제 전송으로 표시하지 않는다. 로컬 합성 데이터에서만 테스트 처리기를 수동 실행한다.

## 목표

- 기관 COURSE_MANAGER의 담당 기수 범위, 승인된 고정 문안과 대상 조건만 허용.
- 운영과 홍보를 구분하고 홍보 선택동의 원문/버전/철회 이력 제공.
- 연락처 원문을 화면·이력에 노출하지 않고 검증된 연락처 참조만 사용.
- 미리보기 대상 스냅샷, 제외 사유 집계, 예약시각·취소 및 중복 예약 방지.
- 예약 직전과 처리 직전의 동의·계정·연락처·문안·권한 재검사.
- 장애/확인 중 상태는 재전송 차단. 테스트 결과와 실제 전달 결과 구분.

## 유보 및 성공 기준

휴대전화 본인확인/업체 API/서명 검증 callback/실제 발신번호 등록/실제 요금/보유기간 정책/운영 worker 배포는 업체 확정 후 별도 연결한다. 이를 기능 완료로 주장하지 않는다. 개인정보를 임시 평문 입력으로 받지 않는다.

동의 철회 경쟁, 교차기관/타인 접근, 미인증 연락처, 재시도 중복, 예약 취소, 변경된 대상 스냅샷, 오래된 권한, 미설정 발송 차단을 로컬 Auth+DB에서 검증한다. 기존 127개 회귀와 빌드, 브라우저 사업단·학습자 화면을 확인한다.

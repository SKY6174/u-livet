# 과정별 출석 수료기준·수료율·중도 환불 표시 계획

> Feature: anchor-completion-attendance-refunds | 2026-09-25 | Dynamic

## 목표

- 운영계획서에서 책임교수가 과정별 최소 출석률을 입력하고 사업단이 검토·최종 제출한다. 초기값은 80%이며 80~100% 범위로 제한한다.
- 최종 제출된 계획서의 기준을 수료 판정에 적용한다. 기존 승인 정책의 과제·시험 기준도 유지하며, 출석 기준을 충족하지 못한 사람은 수료 확정할 수 없다.
- 실시간 출석부에서 학습자별 출석률과 자동 산정 수료 후보/수료율을 표시한다. 미종료 회차·출석 누락·미마감 자료는 확정 수료로 세지 않는다.
- 과정 중 환불 신청 또는 실제 환불 진행 이력을 학습자별로 별도 표시한다. 신청·승인·지급을 혼동하지 않고, 철회자는 수료 후보에서 제외한다.

## 범위 및 판단 기준

- 등록 학습자 전체를 수료율 분모로 하며 중도 환불/철회자를 별도 집계한다. 자동 산정 수료율은 최신 판정에서 수료 가능인 인원/등록 인원, 확정 수료율은 승인 인원/등록 인원으로 구분한다.
- 기존 계획서에 기준이 없는 경우 승인된 정책의 출석 기준을 사용하고, 그것도 없으면 기본 80%를 적용한다. 새 계획서는 기준 입력을 필수로 한다.
- 최종 제출된 운영계획서의 새 버전은 기존 판정을 무효화해 재산출하게 한다.
- 환불은 실제 금융 환불과 수강생 신청 문서를 구분해 출처·상태를 노출한다. 금액이나 계좌 정보는 수료 화면에 노출하지 않는다.

## 성공 조건

- 80% 미만인 학생은 과제·시험 성적이 좋아도 READY가 되지 않는다. 과정별 90% 기준을 승인·제출하면 85% 학생도 READY가 되지 않는다.
- 출결 수정 또는 계획서 재제출 이후 기존 판정은 stale이며 확정할 수 없다.
- 수료율의 분자·분모가 화면에 보이고 0명일 때 나눗셈 오류가 없다.
- 중도 환불 신청과 지급 완료를 다른 상태로 표시하며, 환불 전 신청만으로 지급 완료라 표기하지 않는다.
- lint, TypeScript, DB migration 검증을 통과한다.

## 위험 및 대응

- 기존 수료 정책과 새 계획서 기준이 충돌할 수 있으므로 더 높은 출석률을 적용하고 기준 출처를 화면에 명시한다.
- 기존 최종 제출 계획서에 새 필드가 없을 수 있으므로 호환용 80% 기본값을 유지한다.
- 환불 신청과 실제 환불은 별개 흐름이므로 상태 및 출처를 함께 제공한다.

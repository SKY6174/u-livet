# 수강료 입금·환불 관리 계획

2026-09-19 · anchor-finance · Dynamic

사용자가 선택한 다음 구현 단위. 환불·감면 규정은 **미확정이며 규정 등록 후 사용**한다는 답변을 반영한다. 전체 설계 D02/D04/D07, API06–08, T08–10을 기준으로 별도 설계 후 구현한다.

범위는 계좌이체를 사람이 대사하는 수납 업무다. 유료 기수 설정, 선발 후 납부대기/기한/좌석 예약, 본인 청구·입금신고, 회계 거래 확인·청구 배분, 본인 수강취소·환불신청, 계산 검토·별도 승인·수동 송금 결과 대사와 이력을 연결한다. 입금 신고를 납부 완료로 보지 않고 실제 은행 거래 근거가 있어야 확인한다.

기관 승인 규정과 제한된 회계 권한 없이 운영할 수 없다. 규정의 조항별 비율을 등록하고 회계담당자가 적용 조항과 진행 근거를 확인하며 금액은 서버에서 계산한다. 기본 환불률·감면률은 넣지 않는다. 수납 확인, 환불 승인, 지급 처리를 별도 위임하고 자기 거래 승인과 검토자 자기 승인을 차단한다.

PG·은행 API를 통한 실제 결제/송금, 감면·장학금, 강사료, 세무 증빙, 원계좌 정보 수집/업로드, 자동 계좌 매칭은 후속이다. 이번에는 은행의 원입금자 반환 확인 절차를 거친 외부 증빙 참조만 기록하고 전체 계좌번호는 저장하지 않는다. 미배분 잔액/초과입금은 예외함에서 드러내며 청구 배분 전 반환 업무는 후속이다. 확정 원장의 소급 수정은 제공하지 않는다.

성공 기준: 유료 신청에서 실제 대사된 전액 납부 전 LMS 접근 금지, 만료 후 입금 자동등록 금지, 분할 입금·여러 청구 배분의 합계/기관/소유자 검증, 동일 원거래 중복 방지, 환불 승인 예약으로 초과환불 방지, 지급 불명 상태에서 재송금 시도 차단, 환불 후 잔액의 허위 미납 방지, 이력/권한 검증과 실제 브라우저 흐름 확인. 기존 무료 과정·학사·증명 검사도 회귀한다.

# 최초 계정 비밀번호 설정 계획

2026-09-19 · anchor-initial-account · Dynamic

## 목적과 범위

공개 가입이 중단된 상태에서도 승인된 담당자 초대 후 이메일 소유자가 직접 비밀번호를 설정할 수 있는 수락 화면을 준비한다. 이전 가입 준비 점검에서 전용 초기 설정 화면이 없음을 확인했다.

- `/auth/accept-invitation`과 한국어 초대 템플릿을 추가한다.
- native `invite` 증명을 서버에서 검증하고 기존 비밀번호 조건·계정 상태·MFA·세션 종료 절차를 재사용한다.
- GET/메일 스캐너가 토큰을 소비하지 않게 하고, 실제 비밀번호 제출 때만 검증한다.
- 초대 링크 검증과 관리자 역할 부여를 분리한다.
- Preview 합성 계정으로 초대·복구 타입 구분, 재사용·만료·권한 검증을 수행한다. 기본 시험은 generateLink로 메일을 보내지 않는다.

기관 문안 승인·실제 담당자 동의·계정 초대 발송·역할 부여·공개 가입 개방은 별도 운영 실행 단계다. 본 작업에서 승인 없는 정책/동의를 생성하거나 실제 관리자 후보에게 메일을 보내지 않는다.

## 완료 기준

1. 초대 링크가 없거나 유효하지 않으면 비밀번호가 변경되지 않는다.
2. 초대 증명과 복구 증명의 타입을 서버 코드가 고정하며 사용자 입력으로 바꾸지 않는다.
3. 비밀번호 조건에 맞지 않으면 일회용 토큰을 소비하지 않는다.
4. 비밀번호 설정 후 재로그인하며 실제 MFA와 역할 승인 순서를 안내한다.
5. Preview에서 이메일 확인·비밀번호 설정·학습자 기본 접근·역할 자동 부여 없음·토큰 재사용 거부를 검증한다.
6. 기존 복구 기능의 보안 검증이 유지된다.

# Vercel + Supabase 운영 준비 계획

2026-09-19 · `anchor-release-readiness` · Dynamic

사용자 선택은 **Vercel + Supabase 예정**이다. 앞선 인증 요청 제한 구현 다음 단계로, 설정 실수와 미확인 운영 조건을 발견하는 사전 검사 및 운영 인수 자료를 준비한다.

## 결과물

1. 모든 현재 필수 환경변수를 설명하는 비밀값 없는 예시.
2. Vercel Preview/Production 설정 사전 검사 및 Vercel build command 연결.
3. 버전·소스·migration 지문에 묶인 운영 점검 기록 양식과 검사.
4. 담당자별 배포·검증·장애·복구 순서, 공급자 설정 및 운영 차단 사유.
5. 설정 누락·키 혼동·환경 혼용·미확인 증거·낡은 기록에 대한 회귀 검사.

## 경계

운영 도메인/프로젝트/키/담당자/기관 규정은 미확정이다. 실제 값을 추정하지 않고 빈칸으로 둔다. `.env.local`과 원격 데이터·프로젝트 설정은 변경하지 않는다. 이번 단계는 실제 배포·키 발급·정책 승인·메일 발송을 수행하지 않는다. 사전 검사는 자동 배포 도구가 아니다.

현재 확정 비밀번호(12자+영문/숫자/특수문자, 대소문자 혼용 불필요)를 완화하지 않는다. hosted Supabase에서 동등한 native 통제와 auth schema 사용자 지정의 유지 가능성을 증거로 확인하기 전에는 운영 준비 완료로 판정하지 않는다.

## 완료 기준

기본 예시 파일은 정상적으로 ‘미준비’를 반환해야 한다. 설정 검사 통과와 운영 인수 증거 확인을 구분한다. 실제 비밀값이 CLI 출력에 나타나지 않아야 한다. Preview/Production DB·도메인 혼용 및 브라우저 공개 비밀을 차단한다. 검사와 Vercel build gate의 성공·실패 시나리오를 검증하고 보고서를 남긴다.

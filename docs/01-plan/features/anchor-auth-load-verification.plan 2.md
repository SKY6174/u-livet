# 로그인·역할별 부하 검증 계획

2026-09-19 · anchor-auth-load-verification

DB 최적화 이후 후속 검증을 진행한다. 운영 DB는 과정·신청·수강 모두 0건이므로 실사용 데이터 성능은 아직 측정할 수 없다. 현재 로컬 시험 DB의 합성 과정과 시험 계정으로 인증된 실제 DB·앱 경로를 검증한다.

## 범위

- 고정된 로컬 Supabase(127.0.0.1:55321)만 사용한다.
- 학습자·강사·과정 운영자 시험 계정의 비밀번호 로그인과 필요한 MFA를 검증한다.
- 실제 Next.js 프로덕션 빌드의 로그인 Server Action과 로그인 후 화면을 호출한다.
- 동시 요청 1·4·8개에서 역할별 화면 응답시간, p50·p95·오류율을 측정한다.
- 사용자 간 세션 격리와 권한 없는 화면 접근 차단을 확인한다.
- 재실행 가능한 제한된 로컬 벤치마크, 결과 보고서를 추가하고 기존 요청대로 Git에 반영한다.

## 완료 기준

1. 대상 환경과 계정은 고정된 로컬 합성 데이터임을 코드에서 확인한다.
2. 앱 원본 환경파일·현재 빌드·실행 중 서버를 건드리지 않도록 임시 빌드 디렉터리와 전용 포트를 사용한다.
3. 앱 오류 페이지나 로그인 리다이렉트를 성공적인 업무 응답으로 집계하지 않는다.
4. 비밀번호·JWT·MFA secret·쿠키·개인정보는 출력 또는 보고서에 포함하지 않는다.
5. 측정 세션·서버·임시 빌드는 종료 시 정리한다.
6. 로컬 결과를 운영 동시 사용자 수용량이나 실제 사용자 성능으로 표현하지 않는다.

운영 부하, 실제 계정으로 로그인, 운영 데이터 생성, 메일 전송은 이번 검증에 필요하지 않다. 확인된 병목은 해당 경로와 측정 근거를 바탕으로 후속 범위를 정한다.

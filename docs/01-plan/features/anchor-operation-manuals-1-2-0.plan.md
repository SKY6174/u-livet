## 1. Overview

### 1.1 Purpose

Update the eight audience-specific U-LIFE manuals from v1.1.0 to v1.2.0 so the web manual and distribution documents describe the current learner-document, administrator-inbox, completion-list, and operation-document behavior.

### 1.2 Background

The v1.1.0 manual release is immutable and remains available at its fixed URLs. Since tag `manuals-v1.1.0`, the product added a tuition-refund form, server-side document submission and history, approval-based access to follow-up forms, an administrator learner-document inbox and live dashboard summary, full 16-course completion and operation-document lists with migration-state labels, staff roster account linking, and print-layout refinements for schedules and result covers.

## 2. Goals

### 2.1 Primary Goals

- [x] Preserve every v1.0.0 and v1.1.0 source and distribution artifact without modification.
- [x] Publish v1.2.0 as the current release for all eight audiences.
- [x] Explain the new learner submission, eligibility, status, review, and handoff boundaries in the manuals for the actors who use them.
- [x] Produce and visually verify eight PDFs, eight Markdown files, one combined PDF, and a SHA-256 manifest.
- [x] Keep current-version redirects, version history, search, and old fixed URLs working.

### 2.2 Non-Goals

- Remote production deployment or notifying users.
- Claiming institutional approval or live-site validation.
- Changing the workflows, authorization rules, or institutional policies while documenting them.

## 3. Scope

### 3.1 In Scope

- New canonical source `src/content/manuals/1.2.0.json` and release-catalog registration.
- Current release loader registration and manual-management documentation update.
- Learner instructions for the three document tabs, eligibility locks, PDF download, server submission, timeline, original-PDF access, and receipt cancellation.
- Staff instructions for the learner-document inbox, dashboard request summary, status transitions, notes, MFA, finance handoff, and completion-course registration gaps.
- Operation-document notes for card/list filters, `DB 이관 대기`, and refined printed schedules and result covers.
- Versioned web pages and downloadable PDF/Markdown artifacts generated by the existing release pipeline.
- Integrity, text, build, route, PDF text, and rendered-page validation.

### 3.2 Out of Scope

- Screenshots containing live accounts, signatures, resident registration numbers, or bank details.
- Changes to v1.0.0 or v1.1.0 files and Git tags.
- Database migrations, API changes, UI changes, or policy approval outside the manual release.

## 6. Risks & Mitigations

| Risk | Impact | Probability | Mitigation |
|---|---|---|---|
| Document approval is confused with a financial or academic decision | High | Medium | State the handoff boundary in learner, finance, certification, and administrator manuals. |
| A workflow is documented for the wrong role | High | Medium | Cross-check route guards, navigation, UI labels, design documents, and database functions. |
| Generated v1.2.0 artifacts omit source text | High | Low | Compare canonical JSON, generated Markdown, and extracted PDF text. |
| An old release is mutated | High | Low | Run immutable-release hash checks before and after generation. |
| PDF layout regresses as content grows | Medium | Medium | Render every page and inspect contact sheets plus dense pages at full resolution. |
| Source commit changes during authoring | Medium | Low | Record the verified HEAD and rerun the commit and working-tree audit before publication. |

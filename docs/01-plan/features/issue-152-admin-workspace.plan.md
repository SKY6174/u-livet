# Issue 152 — 사업단 관리 빈 화면 수정 계획

작성일: 2026-10-10

## 문제와 근거

- 사업단 명부의 `member_group=office`는 업무 홈 진입을 허용하지만 실제 업무 메뉴는 유효한 `life_role_assignments`에 따라 표시한다.
- 신고 계정은 활성·이메일 인증·책임연구원 분류·사업단 명부 연결이 확인됐으며 업무 역할은 0개다.
- `/admin`은 허용된 메뉴가 0개인 상태를 설명하지 않아 제목 아래가 비어 보인다.
- 직책·명부 분류를 업무 권한으로 사용하는 것은 기존 역할별 접근 설계와 충돌한다.

## 목표와 범위

1. 메뉴 없는 사업단 구성원에게 업무 권한 미부여 이유와 담당자에게 확인할 방법을 표시한다.
2. 기존 역할별 메뉴, 명부 등록 담당자의 구성원 관리 메뉴, 서버 접근 제한을 유지한다.
3. 권한 부족, 데이터 없음, 조회 실패, 로딩을 각각 안내한다.
4. 다른 관리자 역할 및 무권한 계정의 회귀 검증을 남긴다.
5. PR 생성·병합·push와 운영 배포 및 배포 상태 확인을 수행한다.

## 계정 처리

사용자가 신고 계정에 `COURSE_MANAGER` 부여를 선택했으며, 이어서 같은 사업단의 다른 구성원에게도 동일한 역할 부여를 요청했다. 해당 사업단 명부의 현재 활성 구성원 모두에게 조직 범위의 `COURSE_MANAGER`를 멱등적으로 부여하고 재조회·감사 기록을 남긴다. 기존 다른 역할과 인증·동의·MFA 경계를 유지한다. 미래 신규 구성원에게 역할을 자동 부여하는 규칙은 추가하지 않는다.

## 완료 기준

역할 없는 사업단 구성원의 페이지가 명시적인 안내를 제공하고, 유효한 업무 역할은 해당 메뉴를 제공하며, 강사·수강생·직책만 있는 계정은 관리 기능에 접근하지 못한다. 기존 요청 알림의 데이터 없음과 조회 실패 상태를 검증하고 타입 검사·lint·production build를 통과한다.

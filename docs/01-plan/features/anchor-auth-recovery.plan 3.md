# 인증 정책 강제·이메일 비밀번호 복구 계획

2026-09-19 · `anchor-auth-recovery`

이전 접근성 인증 작업의 후속이다. 사용자 선택인12자 이상+영문·숫자·특수문자, 대소문자 혼합 불필요를 유지한다. 로컬 Supabase Auth 엔진의 공식 환경설정으로 직접 가입/변경 API에도 조건을 적용하고 이메일 복구를 구현한다.

## 구현 범위

- 전용 로컬 Auth 컨테이너에 사용자 지정 문자 집합을 적용하는 재현 가능한 도구. 기존 프로젝트·환경변수·볼륨은 보존하고 지정된 Auth 컨테이너만 교체한다. 설정 검증 실패 시 원래 컨테이너로 복구한다.
- 이메일 요청 → 메일의 재설정 페이지 → 새 비밀번호 입력 → 메일 토큰 검증·비밀번호 변경 → 전체 로그아웃 → 새 비밀번호 로그인.
- 새 창/기기에서 열리는 메일을 지원한다. 메일 링크의 GET만으로 토큰을 소비하지 않으며 단일 사용·만료는 Auth가 관리한다.
- 기존 계정은 새 정책으로 비밀번호가 생성/변경된 기록이 없으면 데이터 접근을 차단하고 재설정을 안내한다. 기존 학습/강의/증명 기록은 그대로 둔다.
- 비밀번호 변경 이전 세션과 로그아웃으로 회수한 세션의 남은 JWT가 DB/RPC 권한을 계속 행사하지 못하게 한다.

## 범위와 운영 결정

사용자 요청은 원격 배포가 아니다. 실제 이메일은 발송하지 않고 로컬 메일함으로 검증한다. 원격 Supabase 호스팅의 기본 프리셋 제약은 계속 존재하므로 실제 운영에는 사용자 지정 Auth 설정을 지원하는 배치 방식 또는 동등한 통제가 필요하다. 로컬 도구를 운영 호스팅에 적용한 것으로 보고하지 않는다. 관리자 MFA·소셜/본인확인은 후속이다.

모든 테스트는 `uc-life-core`55321/55322에서 가상 계정으로 수행한다. 기존 구정책 로컬 테스트 계정은 명시적으로 새 정책 비밀번호로 갱신한 뒤 회귀 검증한다. 실제 사용자 비밀번호를 일괄 변경하는 도구는 만들지 않는다.

## 완료 기준

직접 Auth API의 특수문자 누락 거부·소문자만 허용, 메일 실제 도착·토큰의 GET 미소비/일회성·잘못된/만료된 토큰·일반 로그인으로 복구 우회 불가·새 비밀번호만 로그인·기존 JWT와 갱신 토큰 회수·구정책 계정 차단/복구 후 기록 유지. DB 권한·전체 회귀·빌드·모바일/키보드 검증과 설계 대비 보고를 남긴다.

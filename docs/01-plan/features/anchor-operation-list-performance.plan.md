# 운영 문서 목록 DB 지연 개선 계획

2026-09-25 · anchor-operation-list-performance · Dynamic

## 근거와 목표

운영 Supabase는 ACTIVE_HEALTHY이지만 누적 `pg_stat_statements`에서 `life_operation_list()` 212회 평균 477.2ms, 누적 101.2초로 확인됐다. 로컬 DB에서 MFA가 확인된 기존 시험 관리자 세션으로 129개 과정 조회에 1.83초가 걸렸다. 과정마다 반복되는 사용자·MFA·역할 조회를 한 요청에서 재사용하여 이 병목을 낮춘다.

## 범위와 성공 기준

- 기존 public RPC 이름·응답 필드·순서·권한 범위를 유지한다.
- private 함수 내부에서 MFA·사용자 식별과 유효한 기관별 역할을 한번 계산한다. 관리자 또는 책임강사 배정+활성 강사 역할+유효한 강의 배정 조건을 그대로 적용한다.
- 로컬에서 기존/새 함수를 같은 세션·자료로 비교한다. 관리자·책임강사·권한 없는 사용자·비로그인 경로를 확인한다.
- 로컬 성능 비교, 기존 운영문서 회귀, lint·빌드, 운영 배포 후 읽기 전용 확인을 완료하고 `main`에 push한다.

## 주의

권한을 넓히거나 auth/RLS 스키마를 변경하지 않는다. 성능 비교는 로컬 데이터 분포에 한정한다. 운영 DB에는 검증한 migration만 적용한다. 기존 체크아웃의 미추적 파일과 다른 작업의 커밋은 유지한다.

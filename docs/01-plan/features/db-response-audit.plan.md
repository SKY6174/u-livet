# DB 연결·관리 목록 응답 최적화 계획

2026-10-17 · Dynamic · db-response-audit

## 근거와 범위

운영 DB 직접 연결과 공개 HTTP 4경로를 확인했다. 연결 18/60, 잠금 대기·장기 트랜잭션·무효 인덱스 0. 공개 경로 각 5회 정상. 운영 관리자 화면을 읽은 구간의 pg_stat_statements 차분에서 신청 목록 333.37ms, 수강생 목록 562.96ms가 관측됐다(각 1회, 전후 비교 지표가 아님). 두 목록의 공통 읽기 함수는 과정·원서마다 manages → has_role → person_id를 반복한다.

이번 변경은 management_application_rows와 management_courses의 권한 범위를 한 번 계산하고 해당 기관·과정과 조인한다. 동일 결과와 기관 경계를 로컬 DB에서 대조하고 교차 순서로 성능을 측정한다. 기존 검증용 분류, 미연결 원서, 상태·검색·페이지 처리, 과거 이력은 보존한다.

## 성공 기준

- 관리자·복수 기관·타 기관·일반 사용자·만료/미래 역할·MFA 미충족의 이전/새 결과가 일치한다.
- 원서 중복 선택과 미연결 신청, hidden 과정 제외, 실제 신청·수강생 수와 정렬·페이지를 유지한다.
- 실제 DB 실행 비용 감소를 확인한 변경만 반영한다. 운영 웹 응답·보안 Advisor·원본 해시를 배포 전후 확인한다.
- 별도 Preview DB, 기능 회귀, lint·빌드, PR 검사 후 병합 및 운영 배포를 검증한다.

권한 헬퍼·RLS·인증·쓰기·재무 계산·증빙은 변경하지 않는다. 사용자 간 캐시나 임의 인덱스 추가도 범위에 넣지 않는다.

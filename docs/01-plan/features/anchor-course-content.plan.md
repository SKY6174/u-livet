# U-LIFE 교육과정·강의 콘텐츠 구성안

작성일: 2026-09-19 · 버전: 1.0 · 기능: `anchor-course-content` · 단계: Plan

사용자 요청 범위는 **교육과정·강의 콘텐츠 구성**이다. 기존 사업 기획의 4개 아카데미를 기준으로 과정 분류, 과정 소개, 차시별 자료와 평가의 공통 틀을 정리한다. 아래 과정명·시간·활동은 검토용 제안이며 실제 모집 과정이나 승인된 운영정책이 아니다.

## 1. 목적과 범위

수강생이 ‘무엇을 배우고, 무엇을 만들어 내며, 다음에 무엇을 배울지’를 이해하도록 구성한다. 강사는 같은 틀로 과정 소개·강의계획·학습자료·과제를 작성하고, 사업단은 교육목표와 평가의 연결을 검토한다.

- 산출물: 4개 아카데미의 과정 후보, 공통 과정 소개 양식, 차시 콘텐츠 양식, 12시간 예시 과정, 1회차 자료·과제 예시, 제작·검토 순서.
- 운영 일정·정원·수강료·강사·수료기준은 실제 과정 개설 시 확정한다.
- 콘텐츠 기획 문서다. 운영 데이터 등록, 모집 공개, 화면·DB 구현은 별도 적용 단계다.

## 2. 전체 구조

**아카데미 → 과정 → 과정 버전 → 기수 → 차시 → 학습자료·실습·평가**

| 단위 | 담는 내용 | 예시 |
|---|---|---|
| 아카데미 | 교육 분야 | 스마트테크 |
| 과정 | 지속해서 운영할 교육의 주제·목표 | 생성형 AI 사무업무 활용 |
| 과정 버전 | 목표·차시·교재·평가의 확정된 묶음 | 최초 개발안 v1 |
| 기수 | 실제 강사·일정·장소·수강생 | 운영 일정 확정 후 개설 |
| 차시 | 한 번의 학습목표와 활동 | 업무 요청문 작성 실습 |
| 콘텐츠 | 읽을 자료, 수행할 활동, 제출·확인할 결과 | 설명 본문, 예제, 과제, 점검 문항 |

입문·실무·심화는 학습 경로를 설명하는 기획 분류로 사용한다. 현재 별도 트랙·선수과정 관리 기능이 있다는 뜻은 아니다. 같은 과정의 재개설은 새 기수로, 목표나 평가를 바꾸는 개편은 새 과정 버전으로 관리한다.

## 3. 아카데미별 과정 후보

아카데미 명칭은 기존 사업 기획을 따른다. 아래 교육 주제와 결과물은 신규 제안이다.

| 아카데미 | 입문 과정 후보 | 실무·심화 과정 후보 | 학습 결과물 예시 |
|---|---|---|---|
| 스마트테크 | 디지털 업무 기초, 생성형 AI 사무업무 활용 | 데이터 정리와 시각화, 반복 업무 개선 | 업무문서, 데이터 요약표, 업무 절차서 |
| 라이프케어 | 생활돌봄 소통 기초, 생활지원 서비스 이해 | 돌봄 상황별 의사소통, 생활지원 프로그램 기획 | 상황별 대화안, 지원활동 계획서 |
| 로컬창업 | 지역 자원과 고객 이해, 작은 사업 기획 | 지역 상품 소개 콘텐츠, 판매 실험 설계 | 고객 가설, 상품 소개문, 실험 계획서 |
| 팝업 | 관심 분야 체험, 현장 전문가 특강 | 기업·지역 수요 기반 단기 실습 | 체험 결과물, 현장 적용 메모 |

팝업은 정규 과정 진입과 단기 수요 대응의 입구로 구성한다. 다른 아카데미와 주제가 겹치면 주관 아카데미를 하나 정하고 과정 소개에 관련 분야를 표시한다. 자격·취업·학점 연계 문구는 실제 연계 내용이 확인된 과정에만 기재한다.

## 4. 과정 소개 콘텐츠 양식

공개 소개는 아래 순서로 작성한다. 먼저 학습자가 얻는 결과를 보여주고, 신청 판단에 필요한 운영 정보를 이어 붙인다.

| 순서 | 항목 | 작성 기준 |
|---|---|---|
| 1 | 과정명·한 줄 소개 | 배우는 주제와 적용 장면을 구체적으로 표현 |
| 2 | 이런 분께 권합니다 | 대상과 현재 할 수 있어야 하는 일, 선수조건 |
| 3 | 수강 후 할 수 있는 일 | 관찰 가능한 행동으로 3개 안팎 작성 |
| 4 | 배우는 내용 | 차시명·주요 활동·시간·결과물을 표로 안내 |
| 5 | 수업 방식 | 대면·온라인·혼합, 이론·실습 구성, 학습 지원 |
| 6 | 강사 소개 | 공개가 허용된 전문분야·관련 경력 |
| 7 | 일정·장소·모집 | 모집기간, 교육일시, 정원·최소개강인원, 선발·대기 방식 |
| 8 | 비용·준비물 | 수강료와 별도 재료·소프트웨어 비용, 지참 장비 |
| 9 | 평가·이수 | 승인된 출결·과제·시험 기준, 증명·배지 발급조건 |
| 10 | 신청·문의 | 신청 방법, 취소·환불 안내, 담당 연락처 |

학습목표는 ‘AI를 이해한다’보다 ‘업무 목적·대상·조건을 포함한 요청문을 작성한다’처럼 확인할 수 있게 쓴다. 모집 일정과 비용이 미정인 초안은 내부 검토 문서로 유지한다.

## 5. 차시별 강의 콘텐츠 양식

| 구성 | 작성할 내용 | 결과 확인 |
|---|---|---|
| 시작 안내 | 차시 제목, 목표, 시간, 준비물 | 오늘 완성할 결과물을 알 수 있음 |
| 핵심 설명 | 개념 2~3개, 쉬운 용어 풀이 | 학습자가 자기 말로 설명 |
| 따라 하기 | 완성 예시, 단계별 절차, 흔한 실수 | 동일한 예제 수행 |
| 직접 해보기 | 새로운 상황·문제, 수행 조건 | 자기 결과물 작성 |
| 확인하기 | 자가점검 문항 또는 공식 평가 연결 | 목표 달성 여부 확인 |
| 정리·다음 학습 | 핵심 요약, 다음 차시 준비 | 후속 학습으로 연결 |

강의자료는 모바일에서도 읽을 수 있는 본문을 기본으로 작성한다. 슬라이드·영상 등을 제작할 때도 핵심 설명과 실습 조건을 본문에 남긴다. 자료에 사용한 외부 이미지·예제의 출처와 사용 가능 범위는 제작 기록에 기재한다.

학습자용 설명과 강사용 운영 메모·평가 정답은 별도 문서로 관리한다. 본 문서는 강사용 예시를 포함한 내부 제작용 문서다.

## 6. 상세 예시: 생성형 AI 사무업무 활용

### 6.1 과정 소개 초안

**한 줄 소개:** 반복되는 문서 업무를 주제로 AI에 요청하고, 결과를 확인하고, 업무에 맞게 수정하는 방법을 실습합니다.

- 아카데미·수준: 스마트테크 · 입문.
- 대상: 이메일·안내문·회의록 등 사무문서를 작성하는 성인학습자.
- 선수조건: 키보드 입력, 복사·붙여넣기, 인터넷 접속 가능. 추가 도움이 필요한 학습자를 위한 사전 안내 제공.
- 교육 구성 제안: 6회 × 120분 = 총 720분(12시간). 매회 이론 30분·실습 90분. 휴게시간은 수업시간에 포함하지 않음.
- 준비물: 인터넷 사용이 가능한 컴퓨터, 문서 작성 도구, 사업단이 선정한 AI 도구. 유료 계정 필요 여부·지원 방식은 개설 전에 확정.
- 실습 자료: 기관과 개인을 식별할 수 없는 가상 업무자료.

**학습성과**

1. 목적·대상·입력자료·제약·출력형식을 포함한 업무 요청문을 작성한다.
2. 제공 자료와 AI 결과를 대조해 수치·일정·누락·근거 없는 내용을 찾아 수정한다.
3. 한 가지 업무의 입력→초안→검토→최종본 절차를 문서로 정리한다.

### 6.2 회차별 구성

| 회차 | 주제 | 이론 30분 | 실습 90분 | 결과물 |
|---|---|---|---|---|
| 1 | 업무 요청문 작성 | 요청문의 구성과 결과 확인 | 모호한 요청문을 구체화하고 가상 교육 안내문 작성 | 요청문 전·후와 수정 이유 |
| 2 | 이메일·안내문 | 대상·목적에 맞춘 문장 구성 | 같은 내용을 수강생용·내부 담당자용으로 변환 | 대상별 안내문 2종 |
| 3 | 회의록·보고서 | 사실·결정·할 일 구분 | 가상 회의 메모에서 요약·담당·기한 정리 | 회의록과 근거 대조표 |
| 4 | 표·데이터 설명 | 항목·단위·수치 확인 | 가상 교육 운영표를 읽고 요약문의 수치를 검산 | 요약문과 검산 기록 |
| 5 | 업무 절차 설계 | 반복 업무의 입력과 검토 단계 | 자기 업무 하나를 골라 절차·요청문·확인 기준 작성 | 업무 절차서 초안 |
| 6 | 종합 실습·개선 | 결과물 점검 기준 | 가상 업무자료로 문서 완성, 피드백 반영 | 최종 문서와 업무 절차서 |

현재 과정 개발 양식에서는 한 차시에 이론 또는 실습을 선택한다. 따라서 위 6회차를 입력할 때는 각 회차를 ‘이론 30분’과 ‘실습 90분’ 두 항목으로 나누어 **12개 차시 항목**으로 작성한다. 이론 총 180분, 실습 총 540분이며 합계는 720분이다. 개발안의 차시와 실제 운영 출결 회차는 구분하여 일정을 등록한다.

### 6.3 1회차 학습자료 본문 예시

**오늘의 목표**

업무 요청에 필요한 정보를 빠짐없이 넣고, 완성된 안내문이 제공 자료와 일치하는지 확인합니다.

**핵심 설명**

요청문에는 ① 무엇을 만들지 ② 누가 읽는지 ③ 어떤 자료를 사용할지 ④ 지켜야 할 조건 ⑤ 원하는 형식을 적습니다. 처음부터 모든 문장을 완벽하게 만들기보다, 결과를 확인하고 부족한 조건을 보완합니다.

**가상 실습자료**

- 행사명: 문서 작성 기초 체험수업
- 일시: 10월 15일 14:00~16:00 — 연도는 제공하지 않음
- 장소: 배움관 201호 — 실습용 가상 장소
- 준비물: 노트북
- 대상: 신청을 완료한 수강생
- 문의처·담당자·신청 링크: 제공하지 않음

**따라 하기**

1. 첫 요청문을 ‘체험수업 안내문을 작성해 줘’로 작성하고, 결과에 부족하거나 임의로 추가된 내용을 표시합니다.
2. 요청문을 다음과 같이 바꿉니다. ‘위 가상 실습자료만 사용해 신청 완료 수강생에게 보낼 안내문을 작성해 주세요. 제목과 본문을 나누고, 일시·장소·준비물을 포함하세요. 본문은 다섯 문장 이내로 작성하고, 자료에 없는 연도·담당자·연락처·링크는 만들지 마세요.’
3. 생성된 문장의 일시·장소·준비물을 원자료와 한 항목씩 대조합니다.
4. 틀린 내용과 누락을 수정하고, 추가 확인이 필요한 사항은 안내문 밖의 검토 메모에 남깁니다.

**직접 해보기**

같은 자료로 내부 운영 담당자에게 전달할 준비사항 메모를 작성합니다. 수강생 안내문과 달라진 표현 두 곳과 그 이유를 적습니다. 실제 메일 발송은 실습에 포함하지 않습니다.

**자가점검**

- 대상·목적·자료·조건·출력형식을 모두 제시했나요?
- 원자료의 일시·장소·준비물과 최종 문서가 일치하나요?
- 제공되지 않은 사실을 임의로 추가하지 않았나요?

**다음 시간 준비:** 수강생용과 내부 담당자용 문서의 차이를 한 문장으로 정리합니다.

### 6.4 과제·평가 구성

| 항목 | 확인할 성과 | 제출 내용 | 피드백 기준 |
|---|---|---|---|
| 1회차 연습 | 요청문 작성·수정 | 최초 요청문, 수정 요청문, 결과, 수정 이유 | 다섯 구성요소와 원자료 일치 여부 |
| 공식 과제 후보 A | 문서 작성·검토 | 최종 문서, 사용 요청문, 오류·누락 수정 기록 | 정확성 40점·대상 적합성 30점·검토 근거 30점 |
| 공식 과제 후보 B | 업무 절차 설계 | 업무 목적, 입력자료, 단계, 검토 기준, 적용 예시 | 절차 명확성 40점·검토 기준 40점·예시 완결성 20점 |
| 공식 시험 후보 | 개념·검토 판단 | 단일선택 객관식 5문항 | 요청 구성, 원자료 대조, 누락·오류 판단 |

점수 배분은 강사의 평가안 예시다. 위 A·B 점수를 임의로 가중평균해 수료 여부를 결정하지 않는다. 공식 평가로 채택할 항목, 각 항목의 통과 기준, 출결 기준은 사업단이 별도 승인한다. 연습용 자가점검을 공식 시험에 자동 등록하지 않는다.

**1회차 연습과제 안내문 예시**

‘최초 요청문 → 수정 요청문 → 최종 안내문 → 원자료 대조 결과 → 수정 이유 두 가지’ 순서로 작성하세요. 제공되지 않은 내용은 추가하지 말고 별도 확인 항목으로 표시하세요. 강사는 요청문에 필요한 조건이 포함되었는지와 최종 문서가 실습자료와 일치하는지를 확인합니다. 제출기한은 실제 수업 일정에 맞춰 안내합니다.

**강사용 문항 예시 — 학습자료 본문에 정답 포함 금지**

질문: 가상 실습자료에 없는 문의 전화번호가 생성 결과에 포함되어 있습니다. 가장 적절한 다음 행동은 무엇인가요?

A. 자연스러운 번호이므로 그대로 사용한다. / B. 임의 번호를 다른 번호로 바꾼다. / C. 번호를 삭제하고 실제 문의처 확인이 필요하다고 검토 메모에 남긴다. / D. 같은 결과가 나올 때까지 반복 생성한다.

정답: C. 해설: 제공 자료에서 확인되지 않은 정보는 사실로 확정하지 않고 확인 대상으로 남긴다.

## 7. 현재 시스템에 적용하는 방법

로컬 소스와 기존 설계 문서를 확인한 범위의 대응표다. 운영 환경에서의 콘텐츠 등록·재생 검증을 의미하지 않는다.

| 콘텐츠 | 현재 확인한 입력·표시 방식 | 제작 시 적용 |
|---|---|---|
| 과정 개발안 | 과정명·분야·소개·수요·대상·성과·선수조건·평가안·준비물·예산 | 공개 소개와 내부 개발 근거를 구분해 작성 |
| 차시 계획 | 차시명·이론/실습·분·학습내용·장비·평가 | 총시간과 차시시간의 합계 일치 |
| 강의자료 | 순서·제목·본문, 읽음 표시 | 본문만으로 핵심 학습 수행 가능하게 작성 |
| 과제 | 안내문·마감·텍스트 제출·점수·피드백 | 텍스트로 결과와 검토 근거를 제출할 수 있게 구성 |
| 시험 | 단일선택 객관식, 기존 설계상 1~20문항·동등배점·1회 응시 | 공식 시험과 연습용 자가점검 구분 |
| 출결·수료 | 자료 읽음과 별도 관리 | 읽음 표시를 출석·수료라고 안내하지 않음 |

영상 진도, 파일 과제 업로드, 학습 경로 자동 추천은 이번에 확인한 학습 화면의 전제 기능으로 사용하지 않는다. 해당 형식이 필요한 과정은 지원 방식과 화면을 별도로 확인한 뒤 제작한다.

## 8. 제작·검토 순서와 완료 기준

1. **과정 선정:** 대상 학습자와 현장 수요를 확인하고 우선 제작할 과정을 정한다.
2. **강의계획 작성:** 목표·총시간·차시·결과물·평가안을 연결한다.
3. **대표 차시 제작:** 자료 본문, 예제, 활동, 과제, 강사용 피드백 기준을 한 묶음으로 만든다.
4. **전체 차시 확장:** 대표 차시의 형식과 난이도를 기준으로 나머지를 작성한다.
5. **검토·수정:** 내용 전문성은 담당 강사, 운영정보·수료정책은 사업단, 가독성은 학습자 관점에서 검토한다.
6. **기수 적용:** 승인된 과정 버전과 실제 일정에 맞춰 자료·과제·시험을 등록한다.

현재 완료 기준:

- [x] 기존 4개 아카데미와 연결된 과정 후보 구성.
- [x] 과정 소개와 차시 콘텐츠에 반복 사용할 양식 제공.
- [x] 예시 과정의 학습성과·활동·결과물·평가 연결.
- [x] 예시 총시간 720분 = 이론 180분 + 실습 540분 확인.
- [x] 현재 입력 양식과 학습 화면에 맞춘 적용 방법 구분.
- [x] 제안 수치·과정 후보와 실제 운영 확정사항 구분.

이후 일정은 우선 과정 선정 → 전체 강의자료 작성 → 강사·사업단 검토 → 기수 등록 순서로 정한다. 실제 제작일과 개강일은 아직 지정하지 않았다.

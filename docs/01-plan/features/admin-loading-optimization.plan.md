# 관리자 화면 로딩·DB 최적화 계획

2026-10-17 · Dynamic · admin-loading-optimization

관리 업무 홈·모니터링·과정·구성원·강사·주차권·수강생 서류·증명·성과·수료 화면 10곳을 기존 로그인 세션에서 각 4회 읽었다. 이동/새로고침 시작부터 데이터 조회 뒤 표시되는 제목까지 측정하며 자동화 통신 시간이 포함됨을 명시한다. 별도로 pg_stat_statements 누적값 차분에서 주차권 RPC 4회 평균 474.63ms, 증명 화면의 좁은 과정 목록 SQL 4회 평균 397.37ms를 확인했다.

## 변경 범위

- parking_admin_context의 활성 관리자 기관과 센터 심사 권한을 조회당 한 번 계산한다. 입력·기관·MFA·재고·요청 이력·can_decide 의미를 유지한다.
- 과정 메타데이터 목록 전용 security_invoker view를 만들어 life_offerings 및 사업연도만 읽는다. 기존 life_catalog의 사용하지 않는 과정·버전 조인 때문에 반복되던 부모 RLS 평가를 제거한다. 기본 과정 RLS와 검증용 제외 정책은 계속 적용하며 상세 조회는 유지한다.
- getWorkspaceOfferings만 새 view로 전환하여 증명·수료·강사 작업 목록에 같은 좁은 반환 계약을 제공한다.

## 성공 기준

이전/새 주차권 JSON과 과정 목록 결과가 기관·역할·MFA·분류·기수/상태·센터/연도별로 동등해야 한다. 로컬 교차 DB 측정과 운영 실화면/DB 전후 측정을 기록한다. 재고/요청/원본·권한/RLS·쓰기/발급/감사 함수는 보존한다. Preview 전체 마이그레이션·기능 회귀·lint/build와 최종 PR 검사 후 DB→앱 순으로 배포한다. 캐시·권한 확대·임의 인덱스/계정 변경은 추가하지 않는다.

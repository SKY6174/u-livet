# Issue 172: 운영계획서 반복 입력 및 제출 보완

2026-10-13 · 이슈: https://github.com/SKY6174/u-livet/issues/172

## 목적과 범위

운영계획서의 반복 강의정보 입력, 주요대상 직접 입력, 선택 서명, 수동 예산 계산 및 한 줄 산출내역을 개선한다. 기존 `anchor-operation-documents.design.md`의 문서 형식·임시저장·제출 권한·원본 보관 규칙을 유지한다.

- 강의 기본정보를 입력하거나 기존 회차에서 불러오고 새 회차에 재사용한다. 일자와 공휴일/보강 날짜는 개별 입력한다.
- 성인학습자/지역주민을 독립적으로 선택한다. 기존 문자열 저장 형식을 유지한다.
- 담당교수 서명을 검토 요청 및 최종 제출의 필수 항목으로 검사한다. 임시저장 및 기존 제출본 읽기는 유지한다.
- 표지 서명을 미리보기와 PDF에서 읽을 수 있는 크기로 표시한다.
- 원 단위 산출식과 여러 줄 재료비 내역에서 확정 가능한 금액만 자동 계산한다. 불명확한 내역은 안내하고 금액을 직접 입력할 수 있다.

## 완료 기준

회차의 기본정보 재사용·독립 편집·빈 일자, 두 대상 중복 선택·저장 복원, 서명 없는 검토/제출 서버 거부, 서명 있는 정상 제출을 확인한다. `15,000원*10시간`은 150,000원, 두 줄 10만원/20만원 재료비는 300,000원이어야 한다. 임의 코드·잘못된 수식·초과 금액은 계산하지 않는다. 실제 UI와 생성 PDF를 확인하고 lint·typecheck·build 및 관련 회귀를 통과한다.

DB 함수/트리거 변경은 로컬 트랜잭션에서 검증한 뒤 운영에 적용한다. Push → PR 검사 → 병합 → 운영 READY·revision·health 확인까지 진행한다.

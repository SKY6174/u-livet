# 신원 조회 중복 권한 계산 제거 계획

2026-09-27

## 배경과 목표

운영 DB의 누적 쿼리 통계에서 `life_identity()`가 빈번하고 시간이 많이 소요된다. 현재 `life_private.identity()`는 `member_entry_orgs()`를 목록 생성과 최고 관리자 판정에 각각 한 번씩 호출한다. 동일한 권한 목록을 한 번만 계산하여 DB 실행 시간을 줄인다.

## 범위와 성공 기준

- 기존 JSON 계약, 인증 결과, 함수 권한을 유지한다.
- 로컬 DB의 관리자·강사·학습자·거절 세션에서 이전/새 결과가 동일해야 한다.
- 교차 순서 반복 측정에서 새 함수의 중앙값이 개선되어야 한다.
- 프로덕션과 Preview 연결 및 운영 API 상태를 확인한다.
- 마이그레이션과 검증 결과를 커밋하고 원격 브랜치로 푸시한다.

## 위험

권한 집계 순서 또는 `null` 처리가 바뀌면 로그인 화면에 영향이 있다. 롤백 트랜잭션에서 결과 동등성을 먼저 확인하고, 실측 개선이 없으면 배포하지 않는다. 운영 통계는 누적값이므로 전후 비교에는 새로 측정한 표본만 사용한다.

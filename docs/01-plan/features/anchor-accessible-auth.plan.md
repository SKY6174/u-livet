# 성인학습자 친화적 인증 개선 계획

2026-09-19 · `anchor-accessible-auth`

## 요청과 범위

비밀번호 보이기/숨기기, 가입 시 실시간 조건 확인, 강사·관리자의 이메일 ID와 12자 이상 비밀번호를 구현한다. 기존 공통 계정을 유지하므로 신규 이메일 가입에는 같은 기준을 적용한다. 카카오·네이버 로그인과 PASS 본인확인은 도입 설계와 운영 준비 조건을 정리한다.

현재 가입 Server Action은 길이만12자를 검사하고 로컬 Auth 서비스는6자여서 직접 API 가입에 차이가 있다. 사용자는 **12자 이상 + 영문·숫자·특수문자, 대소문자 구분 조건 없음**을 선택했다. 화면·Server Action은 이 조건을 동일하게 적용한다. Supabase CLI/호스팅 기본 설정은 대소문자 혼합 없이 특수문자만 추가하는 조합을 제공하지 않으므로 Auth는12자+영문·숫자를 강제한다. 직접 Auth API의 특수문자 강제는 아직 제공되지 않는다는 경계를 보고하며 대소문자 혼합을 임의로 강제하지 않는다.

## 접근성과 보안

- 비밀번호는 기본 숨김, 눈 아이콘과 보이기/숨기기 글자,44px 이상 버튼, 키보드 조작·포커스·접근 가능한 이름 제공.
- 가입 입력 아래 조건 목록: 각 조건 충족 여부를 체크와 문구로 표현. 초록색만으로 의미를 전달하지 않는다. 만족한 조건 수만 정중한 라이브 영역으로 알린다.
- 붙여넣기·자동완성·비밀번호 관리자 허용. 비밀번호를 localStorage·로그·분석 도구에 저장하지 않는다. 성공/폼 초기화 시 값·조건·공개 상태를 초기화한다.
- 입력 오류를 고칠 수 있게 값을 보존하되 오류 발생/화면 이탈 시 비밀번호 표시 상태를 숨긴다.
- 강사·관리자 역할은 가입 입력으로 부여하지 않는다. 공통 이메일 계정에 기존 승인 절차로 역할을 부여한다.

## 검증과 운영 경계

단순 스타일 테스트 대신 실제 가입 API에서 약한 비밀번호 거부와 유효 가입·로그인·비밀번호 변경 기준을 검증한다. 브라우저에서 조건 전환·토글·키보드·폼 초기화·모바일 화면을 확인하고 lint/build 및 기존 핵심 인증 검사를 실행한다.

기존 계정의 비밀번호는 해시로 저장되어 일괄 길이 조회가 불가능하다. Auth의 정책 변경은 기존 비밀번호를 소급 무효화하지 않으므로 운영 전 기존 강사·관리자 비밀번호 재설정과 세션 회수를 별도로 완료해야 한다. 이번 작업은 로컬 구현이다. 소셜/본인확인 실연동, 운영 SMTP·복구·MFA는 별도이며 작동하지 않는 로그인 버튼을 노출하지 않는다.

# 출결·성적·수료 운영 조회 정리 계획

요청: 검증용 출결·성적·수료 판정을 운영 화면과 통계에서 제외하며 기존 이력은 보존한다. PR/push/병합/운영 배포를 수행한다.

운영 감사: 출결 10건, 수료 판정 10건, 승인 4건 모두 기존 검증 과정 2개의 자료다. 과제 제출·성적·시험 응시·QR 기록·구형 LMS 출결/성적은 0건. 기존 과정·계정 ID 분류를 재사용하며 새로운 이름/점수/사유 정규식으로 실제 자료를 추측 분류하지 않는다.

공통 운영 읽기 모델을 출석부/QR/과제 성적/시험/수료 보드·개인 이력/강사 요약/사업단 모니터링/연간 집계에 적용한다. 브라우저가 직접 조회하는 등록·출결·제출·판정에도 기존 RLS에 restrictive SELECT 정책만 더해 우회 조회를 막는다. 읽기 역할/기관·배정·본인 경계는 유지한다.

기록의 점수·출석시간·revision·사유·판정 근거·승인 및 원본 파일·감사/송금/확정 보고서는 수정하지 않는다. 판정/승인/출결 정정/채점/시험 응시/QR 기록/증명·배지 근거 함수도 변경하지 않는다. 정상 중도 철회/오래된 판정/미입력 자료는 계속 표시하고 계산한다.

검증: 정상과 검증 과정/계정을 섞은 로컬 단일 transaction/ROLLBACK, 명단·시간·점수·확정/미확정·오래됨·연간 분모/분자·RLS직접조회·다른 기관/익명 경계, 원본과 쓰기/증빙 함수 hash 보존. 별도 Preview 전체 migration 및 실제 운영 페이지·health·배포 SHA 확인.

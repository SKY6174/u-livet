# 필수 검사 기반 자동 병합·배포 계획

2026-11-22 · `u-livet-auto-merge-release`

## 목적과 범위

사용자는 필수 검사를 통과한 PR을 검토 승인 없이 자동 병합하고 기존 Git 연동으로 운영 배포하도록 요청했다. 대상은 `SKY6174/u-livet`의 `main`이며, 프로젝트 규칙에도 같은 방침을 기록한다.

- 저장소의 `allow_auto_merge`를 활성화한다.
- 승인 요구 0건, `PR quality gate` 필수 검사, 최신 base 검사와 관리자 보호를 유지한다.
- 품질 검사 완료 후 PR의 현재 상태와 SHA를 확인해 자동 병합을 실행하거나 예약한다.
- `main` → Vercel Production 및 기존 Supabase 운영 연동을 재사용한다.
- 문서 전용 변경은 기존 허용 목록에 따라 앱 빌드를 생략한다.

## 제외 범위

스테이징 재개, 새 DB·계정·비밀 생성, 관리자 우회 병합, 실패한 검사 무시, 충돌 강제 해결 및 검증되지 않은 운영 DB 쓰기는 포함하지 않는다.

## 완료 기준

1. 자동 병합 허용 설정과 기존 보호 규칙을 API로 확인한다.
2. 성공한 품질 검사의 SHA와 일치하는 열린 비초안 `main` PR만 처리한다.
3. 권한 있는 자동화는 PR 소스·산출물을 내려받거나 실행하지 않는다.
4. 현재 변경을 한 PR에 모아 필수 검사와 자동 병합을 확인한다.
5. 로컬 `main` 동기화 및 Vercel의 정상 배포 또는 근거가 있는 빌드 생략, 운영 상태를 확인한다.

## 검증과 일정

계획 → 설계 → 구현 → SHA·상태 경계 검사 → 실제 GitHub 자동 병합·배포 확인 순서로 진행한다. 처음 추가하는 워크플로는 기본 브랜치에 반영된 뒤부터 이벤트를 받으므로 설치 PR의 자동 병합 예약은 인증된 CLI로 수행한다.

# DB 연결 및 응답시간 최적화 계획

2026-09-19 · anchor-db-performance

사용자 요청: DB 연동성·반응속도 확인, 최적화, git push.

## 측정 근거

- 운영·Preview DB 실제 조회 성공. 운영 DB는 ap-northeast-1(도쿄).
- 운영 배포의 Functions 리전은 iad1(미국 동부).
- 한국 개발 환경에서 각 URL을 순차 9회 요청, 첫 요청을 제외한 8회의 응답 본문 수신 완료시간 중앙값: DB REST 92ms, health 817ms, 홈 729ms, 과정 목록 918ms, 로그인 307ms.
- 빈 카탈로그의 관리 연결 EXPLAIN ANALYZE 실행시간 0.268ms. 권한상 anon 역할 전환은 불가했으므로 이 수치를 RLS 비용 측정으로 해석하지 않는다.

## 범위

1. Vercel 서버와 DB 리전을 맞춘다.
2. 홈에서는 공개 과정 3건과 카드 필드만 조회한다.
3. 과정 목록 검색·페이지 나누기를 DB에서 처리해 전체 본문 전송을 줄인다.
4. 과정 상세의 독립 조회를 병렬 실행하고, 요청 안에서 Supabase 클라이언트를 재사용한다.
5. 반복 가능한 읽기 전용 응답시간 측정 도구와 검증 결과를 남긴다.

## 완료 기준

- 인증·RLS·개인정보 캐시 격리를 유지하고 조회 실패 안내가 동작한다.
- 검색어 특수문자, 페이지 경계, 홈 공개 조건, 조회량 제한을 검증한다.
- lint, 타입·프로덕션 빌드 및 관련 회귀 검증을 통과한다.
- 현재 preview 브랜치에 커밋·push하고 해당 배포에서 연결·응답시간을 재측정한다.
- 운영 배포 반영 여부와 빈 DB에서 측정했다는 한계를 보고한다.

성능 Advisor의 WARN은 기존 life_ 이전 테이블 정책에 있다. 현재 화면의 지연 원인과 무관한 권한 재설계·인덱스 추가는 이번 변경에 포함하지 않는다.
